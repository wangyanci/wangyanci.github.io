系统设计题攻略

一、系统设计题概述

Agent 工程师的系统设计题通常要求设计一个完整的 AI Agent 系统或子系统，考察候选人的架构能力、技术深度和工程经验。

常见题型

二、答题框架（4S 法则）

步骤 内容 时间分配
Scenario 澄清需求、明确约束 2-3 分钟
Service 确定功能模块 3-5 分钟
Storage 数据模型和存储设计 3-5 分钟
Scale 扩展性、容错、监控 5-10 分钟

三、Agent 系统设计题详解

题目：设计一个智能客服 Agent 系统

Step 1: 明确场景

## 需求澄清（先问面试官）

1. **业务范围**：什么行业的客服？（电商/金融/技术支持）
2. **规模**：日均对话量？并发用户数？
3. **渠道**：哪些接入渠道？（Web/App/微信/电话）
4. **约束**：延迟要求？预算限制？数据安全要求？

## 假设（如果面试官没有明确）

- 电商行业客服
- 日均 10 万轮对话
- 峰值并发 1000 用户
- 接入渠道：Web、App、微信小程序
- 延迟要求：首响 < 1s，回复间隔 < 3s

Step 2: 功能设计

Step 3: 核心模块详解

## 1. 对话管理（Dialogue Manager）

### 职责
- 会话生命周期管理
- 对话状态维护（有限状态机）
- 上下文管理（多轮对话）
- 意图路由

### 状态机设计

[开始] → [欢迎] → [意图识别] → [处理中]
↓ ↓ ↓
[结束] [澄清] [工具调用]
↓ ↓
[人工] [生成回复]


## 2. Agent 核心

### 推理引擎
- 采用 ReAct 框架
- Thought → Action → Observation 循环
- 最大迭代次数控制（默认 5 次）

### 记忆系统
- 短期记忆：Redis 存储对话历史
- 长期记忆：向量数据库存储用户画像

### 工具调用
- Function Calling 调用内部 API
- MCP 协议对接外部工具

## 3. RAG 模块

### 文档处理
- 多格式文档加载（PDF/Word/Markdown）
- 智能分块（语义分块 + 重叠）
- Embedding 向量化

### 检索策略
- 混合检索：向量相似度 + BM25
- 重排序：Cross-Encoder 精排
- 查询重写：扩展同义词

Step 4: 扩展性设计

## 扩展性考虑

### 水平扩展
- Agent 核心服务无状态化，支持多实例部署
- 向量数据库分片（按业务领域）
- Redis Cluster 缓存

### 容错设计
- LLM 调用：熔断 + 降级（备用模型）
- 工具调用：超时 + 重试
- 限流：Token Bucket 算法

### 监控体系
- QPS、延迟 P99、错误率
- LLM Token 消耗和成本
- 用户满意度评分

### 数据安全
- 输入：Prompt 注入检测
- 输出：PII 检测 + 敏感词过滤
- 传输：TLS 加密
- 存储：敏感字段加密

四、答题技巧

沟通技巧

时机 做法
开始时 先问需求，不要直接给方案
设计时 边说边画，用白板/纸笔
关键时刻 解释 trade-off，展示深度思考
结束时 总结要点，提出优化方向

避免的坑

  • ❌ 一上来就画架构图，不问需求
  • ❌ 过度设计，不考虑实际场景
  • ❌ 只讲组件不讲数据流
  • ❌ 不考虑容错和扩展性
  • ❌ 对某个技术点过于深入，忽略整体

五、其他常见题目

题目 2：设计一个代码生成 Agent

## 核心要点
1. **输入理解**：自然语言 → 结构化需求
2. **规划**：任务分解 → 代码模块划分
3. **生成**：代码生成 + 单元测试生成
4. **验证**：代码执行 + 测试验证
5. **迭代**：错误修复 + 优化

题目 3：设计一个多 Agent 协作系统

## 核心要点
1. **角色定义**：不同 Agent 的职责
2. **通信机制**：消息传递协议
3. **协作模式**：层级/平等/竞争
4. **冲突解决**：意见不一致时如何处理
5. **监控**：多 Agent 系统的可观测性
