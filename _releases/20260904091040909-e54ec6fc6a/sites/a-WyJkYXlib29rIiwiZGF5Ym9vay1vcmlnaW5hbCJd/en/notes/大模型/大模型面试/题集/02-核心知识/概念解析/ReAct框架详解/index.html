ReAct 框架详解

一、ReAct 概述

ReAct（Reasoning + Acting）是由 Google Research 于 2022 年提出的框架，核心思想是将推理（Reasoning）和行动（Acting）结合起来，让语言模型交替进行思考和行动，从而解决复杂任务。

核心论文

  • 论文: ReAct: Synergizing Reasoning and Acting in Language Models (Yao et al., 2022)
  • 核心贡献: 证明了 Reasoning 和 Acting 的结合能显著提升 LLM 解决复杂任务的能力

ReAct 的核心思想

核心洞察: 单纯的推理（如 CoT）缺乏与外部世界的交互，而单纯的行动缺乏深度思考。ReAct 将两者结合，形成思考-行动-观察的闭环。

二、ReAct 三大核心元素

1. Thought（思考）

Thought 是 Agent 对当前任务的推理过程，包括：

  • 分析当前状态
  • 分解任务目标
  • 制定下一步计划
  • 评估已有信息

Thought 示例：

Thought: 用户想知道北京今天的天气。我需要先获取当前的日期，
然后查询北京的天气预报。让我先调用日期工具获取今天日期。

2. Action（行动）

Action 是 Agent 基于思考做出的具体行为，通常表现为：

  • 调用某个工具（如搜索、API）
  • 向用户返回答案
  • 终止任务

Action 格式（标准化）：

Action: search_weather
Action Input: {"city": "北京", "date": "2024-01-15"}

3. Observation（观察）

Observation 是 Action 执行后的结果反馈，是 Agent 感知外部环境变化的主要途径。

Observation 示例：

Observation: {"temperature": "5°C", "weather": "晴", "humidity": "30%"}

五、ReAct 的代码实现

核心实现逻辑

class ReActAgent:
    """
    ReAct Agent 核心实现
    实现 Thought-Action-Observation 循环
    """
    
    def __init__(self, llm, tools, max_iterations=10):
        self.llm = llm  # 大语言模型
        self.tools = {tool.name: tool for tool in tools}  # 工具注册表
        self.max_iterations = max_iterations  # 最大迭代次数
        self.memory = []  # 对话历史/记忆
    
    def run(self, task: str) -> str:
        """执行 ReAct 循环"""
        # 初始化 prompt
        prompt = self._build_prompt(task)
        
        for i in range(self.max_iterations):
            # 1. 调用 LLM 生成 Thought 和 Action
            response = self.llm.generate(prompt)
            
            # 2. 解析输出
            thought = self._parse_thought(response)
            action = self._parse_action(response)
            action_input = self._parse_action_input(response)
            
            print(f"🧠 Thought: {thought}")
            print(f"⚡ Action: {action}")
            print(f"📥 Input: {action_input}")
            
            # 3. 判断是否为终止动作
            if action == "Finish":
                return action_input.get("answer", "任务完成")
            
            # 4. 执行工具调用
            if action in self.tools:
                tool = self.tools[action]
                try:
                    observation = tool.run(**action_input)
                except Exception as e:
                    observation = f"错误: {str(e)}"
            else:
                observation = f"错误: 未知工具 '{action}'"
            
            print(f"👁️ Observation: {observation}")
            
            # 5. 更新 prompt（追加 Thought-Action-Observation）
            prompt += f"\nThought: {thought}\n"
            prompt += f"Action: {action}\n"
            prompt += f"Action Input: {action_input}\n"
            prompt += f"Observation: {observation}\n"
        
        return "达到最大迭代次数，任务未完成"
    
    def _build_prompt(self, task: str) -> str:
        """构建初始 Prompt"""
        tools_desc = "\n".join([
            f"- {name}: {tool.description}" 
            for name, tool in self.tools.items()
        ])
        
        prompt = f"""你是一位智能助手，可以使用以下工具：

## 可用工具
{tools_desc}

## 指令
请按照以下格式思考并行动：
Thought: 你的思考过程
Action: 工具名称（或 Finish 表示完成）
Action Input: 工具参数（JSON格式）

## 当前任务
{task}

开始！
Thought:"""
        return prompt

完整的 ReAct Agent 运行示例

# 定义工具
class SearchTool:
    name = "search"
    description = "搜索引擎，用于查找信息"
    
    def run(self, query: str) -> str:
        # 实际实现会调用搜索API
        return f"搜索结果: {query} 的相关信息..."

class CalculatorTool:
    name = "calculator"
    description = "计算器，用于数学计算"
    
    def run(self, expression: str) -> str:
        try:
            result = eval(expression)  # 生产环境应使用更安全的方法
            return str(result)
        except:
            return "计算错误"

# 创建并运行 Agent
agent = ReActAgent(
    llm=OpenAI(model="gpt-4"),
    tools=[SearchTool(), CalculatorTool()]
)

result = agent.run("2024年诺贝尔奖得主是谁？他们的成就是什么？")
print(result)

ReAct vs Self-Ask vs Reflexion

框架 核心机制 特点 适用场景
ReAct Thought-Action-Observation 循环 简单直观，易于实现 工具调用、信息查询
Self-Ask 将问题分解为子问题 结构化思考过程 多步推理、分解问题
Reflexion 添加反思和记忆机制 从失败中学习 复杂任务、需要经验积累
LATS MCTS + ReAct 系统性探索 需要多路径尝试的问题

七、ReAct 的优缺点分析

优点

优点 说明
🧠 推理过程可解释 Thought 过程透明可见，便于调试和理解
🔧 与工具无缝集成 标准化的 Action 格式，易于扩展工具
🔄 自主循环执行 无需人工干预，自动完成多步任务
📈 性能显著提升 相比纯 CoT，任务完成率提高 10-30%
🎯 错误恢复能力 通过 Observation 反馈，可以调整策略

缺点与应对

缺点 影响 应对方案
🐌 循环延迟高 每轮都需要调用 LLM，延迟累积 使用更小的模型做初步筛选；并行执行
💰 Token 消耗大 历史记录随轮数线性增长 实现记忆压缩；设置最大轮数限制
🔄 可能陷入循环 反复执行相同操作 设置循环检测机制；限制最大迭代次数
🎯 对模型能力要求高 需要模型严格遵循输出格式 使用更强的模型；添加输出校验

八、ReAct 在生产环境的最佳实践

最佳实践清单

  1. 设置最大迭代次数（通常 5-15 次）
  2. 实现循环检测（检测重复的 Thought/Action 模式）
  3. 添加超时机制（单个工具调用和整体任务超时）
  4. 实现记忆压缩（定期总结历史，避免 prompt 过长）
  5. 添加日志记录（完整记录每轮 Thought-Action-Observation）
  6. 输入输出安全检查（防止 prompt 注入和有害输出）
  7. 工具权限控制（最小权限原则，沙箱执行）
  8. 实现优雅降级（LLM 不可用时返回静态响应）

九、常见面试题

Q1: ReAct 框架的核心思想是什么？

答: ReAct 将 Reasoning（推理） 和 Acting（行动） 结合，通过 Thought-Action-Observation 的循环，让 LLM 在思考后采取行动，然后根据观察结果调整下一步策略，形成闭环。

Q2: ReAct 和 CoT 的区别？

答: CoT 只关注推理过程（纯思考），而 ReAct 将推理与外部行动结合。CoT 适合纯逻辑推理问题，ReAct 适合需要与外部环境交互的复杂任务。

Q3: 如何处理 ReAct 陷入循环的问题？

答:

  1. 设置最大迭代次数
  2. 检测重复的 Thought/Action 模式
  3. 引入随机性或多样性采样
  4. 实现反思机制（Reflexion），从失败中学习

Q4: ReAct 中的 Observation 有什么作用？

答: Observation 是工具执行的结果反馈，是 Agent 感知外部环境变化的唯一途径。它为下一轮 Thought 提供事实依据，使 Agent 能够基于真实数据调整策略。
