MCP 协议详解

一、MCP 概述

MCP（Model Context Protocol，模型上下文协议）是由 Anthropic 于 2024 年推出的开源协议，旨在为 AI 模型与外部工具、数据源之间提供标准化的连接方式。

核心定位

MCP 的目标: 成为 AI 应用与外部世界交互的 "USB-C 接口"

就像 USB-C 统一了电子设备的连接标准，MCP 试图统一 AI 模型与各种工具、API、数据源的连接方式。

为什么需要 MCP？

二、MCP 核心架构

三大核心组件

组件详解

组件 角色 职责 示例
Host AI 应用的宿主进程 管理多个 Client，协调通信 Claude Desktop、IDE
Client 协议客户端 维持与 Server 的长连接，转发请求 Host 内的客户端实例
Server 工具提供方 暴露工具、资源、Prompt 模板 GitHub、数据库、文件系统

通信方式

通信方式 适用场景 优点 缺点
stdio 本地工具 简单、安全、无需网络 仅限本机
SSE 远程服务 实时推送、标准协议 需要服务器支持
HTTP 简单远程调用 通用性好 无状态、需要轮询

三、MCP 的核心能力

MCP Server 可以向 Client 暴露三种核心能力：

1. Tools（工具）

特点：

  • 工具具有输入参数（JSON Schema 定义）和返回值
  • Client 可以发现 Server 提供的所有工具
  • LLM 可以根据任务选择合适工具
  • 工具执行是有副作用的操作（如发送消息、修改文件）

示例：

{
  "name": "search_files",
  "description": "在指定目录中搜索匹配的文件",
  "inputSchema": {
    "type": "object",
    "properties": {
      "path": {"type": "string", "description": "搜索路径"},
      "pattern": {"type": "string", "description": "搜索模式"}
    },
    "required": ["path", "pattern"]
  }
}

2. Resources（资源）

特点：

  • 提供只读数据的访问（如文件内容、数据库记录）
  • 通过 URI 标识和访问
  • 支持订阅变更通知
  • 无副作用，可安全读取

示例：

资源 URI 格式:
- file:///path/to/file.txt
- db://database/table/record
- git://repo/branch/file

3. Prompts（Prompt 模板）

特点：

  • Server 可以预定义 Prompt 模板
  • 支持参数化填充
  • 用于标准化常见操作流程
  • 可由 Server 或用户定义

四、MCP 工具发现与调用流程

完整流程说明

  1. 连接建立: Host 启动 Server 进程，建立 stdio 或 SSE 连接
  2. 能力协商: Client 查询 Server 提供的工具、资源、Prompts
  3. 工具注册: Server 的工具描述传递给 LLM
  4. 工具选择: LLM 根据任务选择合适工具
  5. 工具执行: Client 调用 Server 的工具并返回结果
  6. 结果处理: LLM 基于工具结果生成最终回复

五、MCP 与 Function Calling 的对比

维度 Function Calling MCP
本质 模型能力 通信协议
工具定义位置 应用层定义 Server 自描述
供应商锁定 有（各厂商格式不同） 无（统一标准）
动态发现 不支持 支持运行时发现
工具生态 各平台独立实现 可共享复用
使用门槛 低（直接调用 API） 中（需要实现协议）
适用场景 单一应用 多工具生态

六、MCP Server 开发实战

Server 核心结构

from mcp.server import Server
from mcp.types import Tool, TextContent

# 创建 Server 实例
app = Server("my-mcp-server")

# 定义工具列表
@app.list_tools()
async def list_tools() -> list[Tool]:
    return [
        Tool(
            name="calculator",
            description="执行数学计算",
            inputSchema={
                "type": "object",
                "properties": {
                    "expression": {
                        "type": "string",
                        "description": "数学表达式，如 '2 + 3 * 4'"
                    }
                },
                "required": ["expression"]
            }
        ),
        Tool(
            name="get_time",
            description="获取当前时间",
            inputSchema={
                "type": "object",
                "properties": {}
            }
        )
    ]

# 定义工具执行逻辑
@app.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]:
    if name == "calculator":
        result = eval(arguments["expression"])
        return [TextContent(type="text", text=str(result))]
    
    elif name == "get_time":
        from datetime import datetime
        now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
        return [TextContent(type="text", text=now)]
    
    raise ValueError(f"未知工具: {name}")

七、MCP 生态与前景

当前生态

发展前景

趋势 说明
生态扩展 越来越多工具提供 MCP Server 实现
标准化 可能成为 AI 工具连接的事实标准
IDE 集成 Cursor、VS Code 等已开始支持
企业应用 内部工具标准化接入的统一方案

八、常见面试考点

Q1: MCP 的核心价值是什么？

答: MCP 的核心价值是标准化——统一 AI 应用与外部工具的连接方式，避免 N×M 的适配问题，实现"一次接入，处处可用"的工具体验。

Q2: MCP 的三大核心组件及其关系？

答: Host（管理多个 Client）、Client（与 Server 通信）、Server（提供工具/资源/Prompt）。Host 包含多个 Client，每个 Client 连接一个 Server，Server 暴露工具供 LLM 使用。

Q3: MCP 和 Function Calling 的关系？

答: MCP 是协议层标准，Function Calling 是模型能力。MCP 可以在底层使用 Function Calling 实现工具调用，但提供了更标准化的接口和更好的生态互操作性。

Q4: MCP Server 可以暴露哪些能力？

答: 三种核心能力：Tools（有副作用的操作）、Resources（只读数据访问）、Prompts（预定义 Prompt 模板）。
