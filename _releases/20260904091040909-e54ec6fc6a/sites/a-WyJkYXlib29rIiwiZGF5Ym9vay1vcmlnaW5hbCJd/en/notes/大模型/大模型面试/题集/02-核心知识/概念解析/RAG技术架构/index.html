RAG 技术架构详解

一、RAG 概述

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将信息检索与文本生成相结合的技术，通过从外部知识库中检索相关信息来增强 LLM 的回答质量。

核心动机

RAG 的核心公式

RAG = 检索器(Retriever) + 生成器(Generator)
     = 向量数据库 + Embedding模型 + LLM

二、RAG 的核心架构

三、RAG 的核心组件详解

1. 文档处理（Document Processing）

分块策略对比：

策略 原理 优点 缺点
固定长度 按固定字符/Token数切分 简单、均匀 可能切断语义
递归分块 按段落→句子→单词递归切分 保持段落完整 块大小不均匀
语义分块 按语义边界切分 语义完整 计算复杂
结构分块 按文档结构切分 保留层级关系 依赖文档格式

最佳实践：

  • 设置合理的块大小（通常 256-1024 tokens）
  • 设置重叠区域（overlap，通常 10-20%）防止信息丢失
  • 根据文档类型选择分块策略

2. Embedding 模型

主流 Embedding 模型对比：

模型 维度 语言支持 特点 适用场景
text-embedding-3 1536 多语言 OpenAI 官方，效果稳定 通用场景
text-embedding-ada-002 1536 多语言 性价比高 预算敏感
BGE-M3 1024 中英 开源，效果不错 中文场景
M3E 768 中英 轻量，速度快 实时应用
GTE 768 多语言 阿里开源 中文场景
E5 1024 多语言 Microsoft 开源 语义搜索

3. 向量数据库

主流向量数据库对比：

数据库 特点 适用场景
Chroma 轻量、易用、本地优先 原型开发、小型应用
Milvus 分布式、高性能 大规模生产环境
Qdrant Rust 实现、高性能 高性能需求
Pinecone 全托管、易用 无运维需求
Weaviate GraphQL 接口、模块化 复杂查询场景
PGVector PostgreSQL 扩展 已有 PG 基础设施
FAISS Meta 开源、纯库 嵌入式、研究

4. 检索策略

检索策略详解：

策略 原理 效果
向量检索 语义相似度搜索 理解同义词、语义关联
BM25 基于词频的统计方法 精确匹配关键词
混合检索 向量 + BM25，加权融合 兼顾语义和精确匹配
Reranker 用更精确的模型重排结果 提升 Top-K 质量
Multi-Query 生成多个查询变体检索 覆盖不同表达方式
HyDE 生成假设答案再检索 桥接查询与文档的语义差距

五、RAG 的优化技术

RAG 优化技术图谱

1. 查询重写（Query Rewriting）

# 查询重写示例
original_query = "RAG 是什么"

# 重写为更适合检索的查询
rewritten_queries = [
    "RAG 检索增强生成技术原理",
    "Retrieval Augmented Generation 介绍",
    "RAG 技术架构和工作流程"
]

# 用多个查询分别检索，合并结果
all_results = []
for q in rewritten_queries:
    results = vector_db.search(q, top_k=3)
    all_results.extend(results)

# 去重、重排、取 Top-K
final_results = rerank_and_deduplicate(all_results, top_k=5)

2. 重排序（Reranking）

from sentence_transformers import CrossEncoder

# 加载重排序模型
reranker = CrossEncoder('BAAI/bge-reranker-large')

# 对初步检索结果重排
query = "用户查询"
documents = [doc.text for doc in initial_results]

# 计算查询-文档相关性分数
scores = reranker.predict([(query, doc) for doc in documents])

# 按分数排序
ranked_results = sorted(
    zip(documents, scores),
    key=lambda x: x[1],
    reverse=True
)

3. 上下文压缩（Context Compression）

# 上下文压缩：只保留与查询最相关的部分
from langchain.retrievers.contextual_compression import ContextualCompressionRetriever

compressor = LLMChainExtractor.from_llm(llm)
compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=base_retriever
)

# 压缩后的上下文更精炼，减少 Token 消耗
compressed_docs = compression_retriever.get_relevant_documents(query)

六、RAG 的评估指标

指标 说明 评估方法
Context Precision 检索结果的相关性 人工标注或自动评估
Context Recall 是否检索到所有相关信息 对比参考答案
Answer Relevance 回答与问题的相关性 LLM 评估
Faithfulness 回答是否忠实于检索内容 幻觉检测
Answer Correctness 回答的正确性 对比标准答案
Latency 端到端延迟 性能测试

七、常见面试考点

Q1: RAG 的核心原理是什么？

答: RAG 将检索和生成结合，先从外部知识库中检索与用户问题相关的文档片段，然后将这些片段作为上下文提供给 LLM，引导 LLM 基于检索到的事实信息生成回答，从而减少幻觉并增强领域知识。

Q2: RAG 中分块策略的选择依据？

答: 分块策略应根据文档类型和查询模式选择：

  • 固定长度：通用场景，简单高效
  • 递归分块：保留文档结构层次
  • 语义分块：语义完整性要求高
  • 结构分块：HTML/Markdown 等结构化文档
  • 关键参数：块大小（256-1024 tokens）、重叠率（10-20%）

Q3: 混合检索的优势？

答: 向量检索擅长语义匹配（理解同义词、相关概念），BM25 擅长精确关键词匹配。混合检索结合两者优势，通过加权融合（如 RRF 算法）获得更全面的检索结果。

Q4: 如何减少 RAG 中的幻觉？

答:

  1. Faithfulness 检查：验证回答是否在检索内容中有依据
  2. 引用生成：要求模型标注每句话的来源
  3. 拒答机制：检索不到相关内容时拒绝回答
  4. 多路召回：增加检索覆盖面
  5. 重排序：提升检索结果质量
