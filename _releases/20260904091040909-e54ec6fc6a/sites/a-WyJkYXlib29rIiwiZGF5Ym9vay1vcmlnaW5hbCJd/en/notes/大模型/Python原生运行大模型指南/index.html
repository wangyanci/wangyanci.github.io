3. 方案一：Ollama

3.1. 什么是 Ollama

Ollama is a tool that lets you run large language models locally. It packages model weights, configurations, prompts, and a chat interface into one neat package.

—— ollama.com

Ollama 的核心贡献：

  • 把 llama.cpp / ggml 后端封装成一个守护进程。
  • 提供 ollama run 命令行交互。
  • 提供 REST API（默认 http://localhost:11434）与 OpenAI 兼容 API（/v1/chat/completions）。
  • 内置模型仓库（ollama pull qwen3.5:0.8b 一行下载）。

4. 方案二：Hugging Face Transformers

4.1. 适用场景

  • 想看完整模型结构（打印层、访问 attention weights）。
  • 需要微调 / 训练或加载 LoRA / PEFT。
  • 需要自定义推理逻辑（beam search、repetition_penalty、logits processor）。
  • 在 GPU 服务器上跑大参数模型（>10B）。

4.3. 最简示例

from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "Qwen/Qwen2.5-0.5B-Instruct"

# 加载分词器
tokenizer = AutoTokenizer.from_pretrained(model_id)

# 加载模型
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    device_map="auto",           # 自动分配到 GPU / CPU
    torch_dtype="auto",          # 自动选择精度
)

# 构造 prompt（ChatML 格式）
messages = [
    {"role": "system", "content": "你是一个简洁的助手。"},
    {"role": "user", "content": "用一句话介绍 Python"},
]

text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
)

# 推理
inputs = tokenizer(text, return_tensors="pt").to(model.device)
output_ids = model.generate(
    **inputs,
    max_new_tokens=128,
    temperature=0.7,
    top_p=0.9,
    do_sample=True,
)

# 解码（去掉 prompt 部分）
prompt_len = inputs.input_ids.shape[1]
response = tokenizer.decode(output_ids[0][prompt_len:], skip_special_tokens=True)
print(response)

4.5. 4-bit / 8-bit 量化加载

显存紧张时，用 bitsandbytes 把 7B 模型压到 ~5GB 显存也能跑。

from transformers import AutoModelForCausalLM, BitsAndBytesConfig

bnb = BitsAndBytesConfig(
    load_in_4bit=True,                        # 4-bit 量化
    bnb_4bit_quant_type="nf4",                # NormalFloat4
    bnb_4bit_compute_dtype="float16",
    bnb_4bit_use_double_quant=True,
)

model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B-Instruct",
    quantization_config=bnb,
    device_map="auto",
)
4-bit 量化的副作用
  • 精度有损（perplexity 通常上升 5%~15%）。
  • 首次推理前 bitsandbytes 会编译 CUDA 算子，需要几秒到几十秒"热身"。
  • 不支持 CPU 推理。

5. 方案三：llama-cpp-python 加载 GGUF

5.1. 为什么选 GGUF + llama-cpp

  • CPU 友好：纯 CPU 上跑 7B 量化模型，仅需 8GB 左右内存。
  • mmap 加载：模型文件不被全量读入内存，多个进程共享同一份权重副本。
  • 生态广泛：Hugging Face 上大量 *-GGUF 量化版本（TheBloke、bartowski 整理）。

7. NumPy 视角：Transformer 推理到底在算什么

这一节用 NumPy 写出最核心的矩阵乘法 + Softmax + Sampling，把"模型推理"翻译成你能看到、能改的代码。

7.1. Embedding 查表

import numpy as np

vocab_size = 50000
hidden_dim = 512

# 假设这是 embedding 矩阵
embedding = np.random.randn(vocab_size, hidden_dim).astype(np.float32)

# token id 序列
token_ids = np.array([101, 2034, 5623])  # 假设三个 token

# 查表 = 行索引
hidden = embedding[token_ids]   # shape: (3, 512)
print(hidden.shape)             # (3, 512)

没有任何"运算"——就是按 token id 取对应的行向量。

7.2. 多头自注意力（Self-Attention）

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)


def self_attention(X, Wq, Wk, Wv, Wo, n_heads):
    """
    X:  (seq_len, hidden_dim)
    Wq/Wk/Wv/Wo: (hidden_dim, hidden_dim)
    """
    seq_len, hidden_dim = X.shape
    head_dim = hidden_dim // n_heads

    Q = X @ Wq   # (seq_len, hidden_dim)
    K = X @ Wk
    V = X @ Wv

    # 拆多头：(seq_len, n_heads, head_dim) → (n_heads, seq_len, head_dim)
    Q = Q.reshape(seq_len, n_heads, head_dim).transpose(1, 0, 2)
    K = K.reshape(seq_len, n_heads, head_dim).transpose(1, 0, 2)
    V = V.reshape(seq_len, n_heads, head_dim).transpose(1, 0, 2)

    # QK^T / sqrt(d)
    scores = Q @ K.transpose(0, 2, 1) / np.sqrt(head_dim)  # (n_heads, seq_len, seq_len)

    # 因果 mask（看不到未来）
    mask = np.triu(np.ones((seq_len, seq_len), dtype=bool), k=1)
    scores = np.where(mask, -1e9, scores)

    # softmax → attention weights
    attn = softmax(scores, axis=-1)

    # 加权求和
    out = attn @ V  # (n_heads, seq_len, head_dim)
    out = out.transpose(1, 0, 2).reshape(seq_len, hidden_dim)

    return out @ Wo  # 投影回 hidden_dim
三个核心矩阵
  • Q @ K^T：算"每个 token 跟所有 token 的相关度"——一次矩阵乘法。
  • softmax：把分数变概率——指数 + 归一化。
  • attn @ V：按相关度加权求和——又是一次矩阵乘法。

Transformer 的"花活"基本都在围绕 Q/K/V 怎么投影、mask 怎么加。

7.3. 前馈网络（FFN）

def relu(x):
    return np.maximum(x, 0)


def ffn(x, W1, b1, W2, b2):
    """
    两层全连接 + ReLU，扩展维度再做非线性。
    """
    h = relu(x @ W1 + b1)   # (seq_len, 4 * hidden_dim)
    return h @ W2 + b2       # (seq_len, hidden_dim)

7.4. 输出 logits + 采样

def sample_next_token(logits, temperature=1.0, top_k=0, top_p=1.0):
    """
    logits: (vocab_size,)
    返回：单个 token id
    """
    logits = logits / max(temperature, 1e-5)

    # Top-K
    if top_k > 0:
        idx = np.argpartition(-logits, top_k - 1)[:top_k]
        mask = np.full_like(logits, -1e9)
        mask[idx] = logits[idx]
        logits = mask

    # Top-P (nucleus)
    sorted_idx = np.argsort(-logits)
    sorted_logits = logits[sorted_idx]
    probs = softmax(sorted_logits)
    cum = np.cumsum(probs)
    # 找到累计概率首次超过 top_p 的位置
    cut = np.searchsorted(cum, top_p) + 1
    keep = sorted_idx[:cut]
    mask = np.full_like(logits, -1e9)
    mask[keep] = logits[keep]
    logits = mask

    probs = softmax(logits)
    return int(np.random.choice(len(probs), p=probs))

7.5. 一次完整推理

def generate(prompt_ids, embedding, n_layers, sample, max_new_tokens):
    """
    极简版：把 prompt token 转成 hidden state，循环预测下一个 token。
    """
    x = embedding[prompt_ids]  # (seq_len, hidden_dim)

    for _ in range(max_new_tokens):
        # 实际中这里是 N 层 [Attention + FFN] + RMSNorm + 残差
        for layer in range(n_layers):
            x = x + self_attention(x, *layer["attn"])   # 残差
            x = x + ffn(x, *layer["ffn"])               # 残差

        # 最后一层 hidden state 取最后一个 token → lm_head → logits
        last_hidden = x[-1]
        logits = last_hidden @ lm_head.T  # (vocab_size,)
        next_id = sample(logits)

        # 把新 token 接上去继续
        prompt_ids = np.append(prompt_ids, next_id)
        x = np.vstack([x, embedding[next_id:next_id + 1]])

        if next_id == eos_id:
            break

    return prompt_ids
NumPy 实现 vs PyTorch 实现
  • NumPy 只能 CPU 单线程；PyTorch 自动用 GPU + cuBLAS。
  • 真实模型里 Wq/Wk/Wv 是合并成一个大矩阵 Wqkv 一次性算。
  • 注意力还有 GQA（Grouped-Query Attention）、FlashAttention 等优化。
  • 实际推理框架会用 KV Cache 避免每步重新算 K/V。

8.2. Safetensors

Safetensors is a new simple format for storing tensors safely (as opposed to pickle) and that is still fast (zero-copy).

—— huggingface.co/docs/safetensors

8.2.1. 关键特性

  • 零拷贝（zero-copy）读取：用 mmap 直接把文件映射成 tensor，不经过 pickle 反序列化。
  • 无 pickle 反序列化漏洞：不会被恶意构造的 pickle payload 执行任意代码。
  • 元数据头：开头一段固定大小的 JSON 描述每个 tensor 的名字、dtype、shape、offset。
  • 大端 / 小端无关：跨平台可读。

8.2.2. 文件结构

+------------------ Header (≤ 100MB JSON) ------------------+
| {"tensor_name": {"dtype": "F32", "shape": [512, 512],      |
|                  "data_offsets": [0, 1048576]},            |
|  ...其他 tensor...}                                        |
+------------------------------------------------------------+
|  Tensor 0 原始字节 (data_offsets[0]~data_offsets[1])       |
|  Tensor 1 原始字节                                         |
|  ...                                                       |
+------------------------------------------------------------+

8.3. GGUF

GGUF is the successor file format to GGML, GGMF and GGJT. It is a binary format that contains everything needed to load a model: weights, tokenizer, special tokens, metadata, and more.

—— github.com/ggml-org/llama.cpp

8.3.1. 关键特性

  • 自描述：模型权重 + tokenizer + 元信息都在一个文件里，复制即可用。
  • 支持多种量化：Q2_K / Q3_K / Q4_0 / Q4_K_M / Q5_K_M / Q6_K / Q8_0。
  • mmap 加载：多进程共享同一份权重。
  • 版本化协议：开头 magic + version，未来破坏性变更可平滑升级。
  • CPU 优化：底层 hand-written SIMD（AVX2 / AVX-512 / NEON）。

8.3.2. 文件结构

+---------------------- GGUF Header ----------------------+
| magic: "GGUF" (4 字节)                                 |
| version: u32 (e.g., 3)                                 |
| n_tensors: u64                                         |
| n_kv: u64                                              |
| ...                                                    |
+--------------------------------------------------------+
| General Metadata (KV pairs, key=string, value=typed)   |
| - general.architecture = "qwen2"                       |
| - qwen2.context_length = 32768                         |
| - qwen2.embedding_length = 896                         |
| - qwen2.block_count = 24                               |
| ...                                                    |
+--------------------------------------------------------+
| Tensor Infos (name + n_dims + dims[] + dtype + offset) |
+--------------------------------------------------------+
| Tensor Data (量化后的原始字节)                          |
+--------------------------------------------------------+

8.3.3. 关键元信息

general.architecture         模型架构名（llama / qwen2 / gemma2 / ...）
general.name                 模型人类可读名
general.file_type            量化方案（1=F32, 0=F16, 14=Q4_K_M, ...）
{arch}.context_length        最大上下文长度
{arch}.embedding_length      hidden_dim
{arch}.block_count           层数
{arch}.feed_forward_length   FFN 中间维度
{arch}.attention.head_count  注意力头数

8.3.4. 单文件目录结构

Qwen2.5-0.5B-Instruct-GGUF/

一个文件 = 一个模型

GGUF 是单文件协议——权重、tokenizer、模型架构元信息全在一个 .gguf 文件里。复制走就能用，不需要附带 config.json、tokenizer.json 等一系列小文件。

8.4. AWQ（Activation-aware Weight Quantization）

AWQ is a quantization method that protects ~1% salient weights by observing activation distributions instead of weights.

—— github.com/mit-han-lab/llm-awq

8.4.1. 关键特性

  • 4-bit weight-only 量化：显存占用降为 fp16 的 1/4，推理速度接近 fp16。
  • 保护显著权重：观察到 activation 后，对 ~1% 重要的权重保持高精度。
  • 需 GPU：4-bit GEMM 需要 CUDA 算子。
  • 与 Safetensors 容器兼容：本质上是把线性层权重量化成 4-bit，存到 .safetensors。

8.4.2. 目录结构

Qwen2.5-7B-Instruct-AWQ/
├── config.json
├── model.safetensors              # 里面存的是 4-bit 量化权重 + zero/scale
├── model.safetensors.index.json
├── quantization_config.json       # {"quant_method": "awq", "bits": 4, ...}
├── tokenizer.json
└── tokenizer_config.json
AWQ 的 GPU 依赖

AWQ 推理需要 CUDA + AutoAWQ 编译的 GEMM 算子。在纯 CPU 或 macOS Metal 上跑不起来——这是它与 GGUF 的最大区别。

8.5. Bin（PyTorch pickle）——被淘汰的格式

8.5.1. 历史

Hugging Face Transformers 早期版本默认把权重存为 pytorch_model.bin（PyTorch 的 torch.save 输出，本质是 pickle 协议）。

8.5.2. 文件结构

pytorch_model.bin
└── 一个巨大的 pickle 对象：
    {
      "model.embed_tokens.weight": tensor(...),
      "model.layers.0.self_attn.q_proj.weight": tensor(...),
      ...
    }

8.5.3. 为什么被淘汰

  • 安全风险：pickle 反序列化会执行任意代码——恶意构造的 .bin 文件可以在你加载模型时执行任意指令。
  • 加载慢：pickle 反序列化是 Python 端的，不能用 mmap，内存占用翻倍。
  • 跨版本兼容差：PyTorch 升级有时会破坏老 checkpoint。

8.5.4. 现状

从 Transformers 4.36（2024 年初）起，保存权重默认改为 Safetensors。pytorch_model.bin 已不再推荐。

# 老代码：可能还在用
model.save_pretrained("./model")  # 现在默认生成 .safetensors

# 强制用旧格式（不推荐）
model.save_pretrained("./model", safe_serialization=False)

9.4. Safetensors → AWQ

# 需要 AutoAWQ 库
from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer

model_path = "Qwen/Qwen2.5-7B-Instruct"
quant_path = "./qwen2.5-7b-awq"

# 加载模型
model = AutoAWQForCausalLM.from_pretrained(model_path)
tokenizer = AutoTokenizer.from_pretrained(model_path)

# 量化配置
quant_config = {
    "zero_point": True,
    "q_group_size": 128,
    "w_bit": 4,
    "version": "GEMM",
}

# 量化（需要少量校准数据）
model.quantize(tokenizer, quant_config=quant_config)

# 保存
model.save_quantized(quant_path)
tokenizer.save_pretrained(quant_path)
AWQ 需要校准数据

AWQ 不是简单的"权重量化"——它要观察 activation 分布，挑出 ~1% 显著权重。没有校准数据无法完成。
一般准备 32~512 条文本即可。

11. Bin 格式被淘汰的完整原因

11.1. 安全

# 理论上，恶意 .bin 文件加载时会执行任意代码
import torch
torch.load("malicious.bin")  # 🚨 可能在反序列化阶段执行 os.system("rm -rf /")

Hugging Face 上传过的模型如果用 .bin 格式：

  • 必须经过 Hugging Face 自己的恶意软件扫描。
  • 一旦被报恶意，整个仓库会被强制迁移到 Safetensors。

11.2. 性能

操作 Safetensors Bin (pickle)
首次加载（CPU） mmap，几乎即时 全量 Python 反序列化，几秒到几十秒
首次加载（GPU） mmap + H2D copy pickle + H2D copy
进程间共享 ✅ mmap 直接共享 ❌ 必须各加载一份

11.3. 兼容性

  • PyTorch 2.6 默认禁用 pickle（weights_only=True），老的 .bin 文件直接 FutureWarning。
  • Transformers 4.36 之后 save_pretrained 默认 safe_serialization=True。

16. 小结

  • 三种方案定位：Ollama = 一键本地服务；Transformers = 全功能框架；llama-cpp-python = CPU / 量化部署。
  • 选 Ollama 是 80% 个人 / 小团队场景的最优解：安装一行、模型一行、API 与 OpenAI 兼容。
  • 选 Transformers 的唯一理由：需要训练、微调或访问模型内部结构。
  • 选 llama-cpp-python：纯 CPU / 低显存 / 嵌入式场景，或想用 llama.cpp 生态做优化。
  • 模型格式选择：
    • Hugging Face 生态 → Safetensors
    • CPU / 边缘 → GGUF（Q4_K_M）
    • 显存紧张 + 有 GPU → AWQ
    • .bin 已经过时，不要再用。
  • NumPy 实现揭示了核心：Embedding 查表 + Attention 矩阵乘法 + Softmax + Sampling。所有大模型推理都是这套原型的工程化版本。
  • 2026 年实践建议：
    • 个人开发先跑 ollama pull qwen3.5:0.8b 试水；
    • 部署选 q4_K_M 量化版本，CPU 也能用；
    • 微调用 Transformers + LoRA + bitsandbytes；
    • 模型来源：优先 Hugging Face 官方仓库；Hugging Face 第三方下载 GGUF 用 bartowski / TheBloke。

19. 方案六：vLLM —— 高吞吐生产级推理服务

vLLM is a high-throughput and memory-efficient inference and serving engine for LLMs.

19.1. 核心创新：PagedAttention

传统推理中，KV Cache 是连续显存块，长度按最大上下文预留，浪费率 60%~80%。

vLLM 提出 PagedAttention：把 KV Cache 切成定长页（类似操作系统虚拟内存分页），按需分配：

传统 KV Cache（连续分配）：
[seq_1 ████████░░░░░░░░░░]   ← 浪费 60%
[seq_2 ████░░░░░░░░░░░░░░]   ← 浪费 80%

vLLM PagedAttention（分页）：
[seq_1: page0][page1][page2]
[seq_2: page0][page1]
[free:        ][page2][page3]

收益：

  • 显存利用率 4x~24x（具体取决于并发与序列长度分布）。
  • 吞吐比 Hugging Face Transformers 高 14x~24x。
  • 支持 continuous batching（一批生成完一条立即补充新请求）。

    model_name="unsloth/Qwen2.5-7B-Instruct-bnb-4bit",

    load_in_4bit=True,
    dtype=None,  # 自动选择

# 2. 注入 LoRA adapter
model = FastLanguageModel.get_peft_model(
    model,
    r=16,                       # LoRA rank
    target_modules=[            # 要注入的层
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_alpha=16,
    lora_dropout=0,
    use_gradient_checkpointing="unsloth",  # Unsloth 优化版
)

# 3. 准备数据
from datasets import load_dataset
dataset = load_dataset("yahma/alpaca-cleaned", split="train[:1000]")

def formatting_prompts_func(example):
    return example["text"]

# 4. 训练
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,
    dataset_text_field="text",
    max_seq_length=2048,
    args=TrainingArguments(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        num_train_epochs=3,
        learning_rate=2e-4,
        fp16=True,
        output_dir="./outputs",
    ),
    formatting_func=formatting_prompts_func,
)

trainer.train()

如果说 Unsloth 是给开发者的"瑞士军刀"，Unsloth Studio 就是给运营 / 数据科学家 / 非程序员的"电动工具箱"——点鼠标完成训练 + 推理 + 导出。

Unsloth Studio 同时承担两个角色（这一点容易被误解）：

┌──────────────────────────────────────────────────────────────┐
│  用户层：Unsloth Studio（桌面 / Web GUI）                     │
├──────────────────────────────────────────────────────────────┤
│  训练引擎：Unsloth Python 库（PyTorch + 自研 Triton kernel） │
│  推理引擎：                                                  │
│    ├── Windows / Linux：llama.cpp（GGUF）                    │
│    └── macOS（Apple Silicon）：MLX                           │
├──────────────────────────────────────────────────────────────┤
│  模型层：Hugging Face 模型 + 自定义数据集                    │
└──────────────────────────────────────────────────────────────┘
双引擎澄清

Unsloth Studio 不是单一引擎，而是两套引擎各管一摊：

任务 引擎 为什么
训练 / 微调 Unsloth 自家 Triton + PyTorch kernel llama.cpp 只能推理，不能训练
推理（Linux/Win） llama.cpp（GGUF 后端） 跨平台、CPU/GPU 通用、生态成熟
推理（macOS） MLX Apple Silicon 统一内存 + 原生 Metal

所以你说"Studio 底层是 llama.cpp"——只对了一半：训练不是，推理是。

22.2. 主要功能

功能 说明
可视化模型选择 下拉菜单选 Llama 3 / Qwen 2.5 / Mistral / Phi-4 等，无需手写路径
数据集上传 拖拽 CSV / JSONL / Parquet 到界面，自动预览 + 校验
参数滑块 LoRA rank、学习率、batch size、epoch 用滑块调节（无需记超参）
实时训练监控 loss 曲线、GPU 利用率、显存占用实时图表
一键导出 训练完直接导出为 LoRA / merged / GGUF / Ollama Modelfile
多平台 macOS (Apple Silicon) / Windows (NVIDIA) / Linux (NVIDIA)
Colab / Kaggle 集成 也提供网页版，无需本地 GPU
跨平台差异
平台 Unsloth 库 Unsloth Studio

Studio 在 macOS 上用 MLX 后端，这是它与 Unsloth 库的一个重要差异——把 Apple Silicon 用户也覆盖了。

22.3. 典型工作流

1. 启动 Unsloth Studio → 选择 base model（如 Qwen2.5-7B-Instruct）
2. 上传数据集：拖拽 alpaca_zh.jsonl 到界面
3. 配置参数：LoRA rank=16, lr=2e-4, epochs=3（滑块 / 下拉）
4. 点 [Start Training] → 实时看 loss 曲线
5. 训练完成 → 选择导出格式
   ├── LoRA adapter（几十 MB）
   ├── Merged 16-bit（全权重）
   ├── GGUF Q4_K_M（给 Ollama 用）
   └── Ollama Modelfile（一键打包）
6. 一键推送到 Ollama / Hugging Face Hub

23.1. 决策树（终极版）

要本地跑大模型？
├── 只想聊天 / 试玩 / 给非程序员用
│   ├── 想要 GUI、点鼠标 → LM Studio
│   └── 命令行也行      → Ollama
│
├── 跑在 Apple Silicon (M1/M2/M3/M4) 上
│   ├── 想要最快速度 + Python 集成 → MLX
│   └── 想要兼容 GGUF 生态         → llama.cpp (Metal) / Ollama
│
├── 需要企业级 API 服务（高并发）
│   └── vLLM（必须 Linux + NVIDIA GPU）
│
├── 需要微调 LoRA / QLoRA
│   ├── 只想点鼠标 / 不写代码 → Unsloth Studio（跨平台 GUI）
│   ├── 写代码 + 需精细控制  → Unsloth（Linux + NVIDIA）
│   └── 其他平台              → transformers + PEFT
│
├── 数据隐私 / 不能联网 / 纯 CPU
│   └── llama-cpp-python + GGUF (Q4_K_M)
│
└── 需要训练 / 访问模型内部结构
    └── transformers + Safetensors

模型格式该选什么？
├── Hugging Face 生态 + GPU → Safetensors / AWQ
├── CPU / 边缘部署           → GGUF (Q4_K_M)
├── Apple Silicon             → MLX 格式 / GGUF
└── ❌ 不要再用 .bin

24. 总结（终极版）

  • 三大「推理定位」：

    • Ollama / LM Studio：本地一键上手
    • llama.cpp / MLX / llama-cpp-python：底层引擎或集成
    • vLLM：生产高并发

  • 两大「微调方案」：

    • Unsloth 库（代码式，Linux + NVIDIA）
    • Unsloth Studio（GUI 式，全平台含 macOS / Windows）

  • 平台分布：

    平台 推荐方案
    Apple Silicon MLX（推理）/ Unsloth Studio（微调）/ Ollama / LM Studio / llama.cpp (Metal)
    Linux + NVIDIA GPU vLLM（服务）/ Unsloth（微调）/ Unsloth Studio（GUI 微调）/ Ollama / llama.cpp
    Windows + NVIDIA Unsloth Studio / Ollama / LM Studio / llama.cpp / vLLM (WSL2)
    纯 CPU / 边缘 llama.cpp / llama-cpp-python

  • 模型格式选择（不变）：

    • Hugging Face 生态 → Safetensors
    • CPU / 边缘 → GGUF (Q4_K_M)
    • Apple Silicon → MLX / GGUF
    • GPU 高吞吐 → AWQ / GPTQ
    • ❌ .bin 已过时

  • 2026 年实践路径：

    1. 个人试用：ollama pull qwen2.5:7b 或 LM Studio 搜 qwen2.5
    2. macOS 深度使用：pip install mlx-lm + mlx-community 模型
    3. 代码式微调：Unsloth + QLoRA → 导出 GGUF → Ollama 部署
    4. 非程序员微调：Unsloth Studio GUI → 一键导出 GGUF
    5. 企业 API 服务：vLLM + K8s + Prometheus
    6. 嵌入式 / IoT：llama.cpp CLI + Q4_K_M GGUF
