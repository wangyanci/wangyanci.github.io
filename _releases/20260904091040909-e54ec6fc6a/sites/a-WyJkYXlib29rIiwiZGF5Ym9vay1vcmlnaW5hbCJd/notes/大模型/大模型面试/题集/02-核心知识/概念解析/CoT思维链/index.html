CoT 思维链（Chain-of-Thought）

1. 一、CoT 概述

CoT（Chain-of-Thought，思维链）是 Google 于 2022 年提出的一种提示工程技术，通过在 Prompt 中引导大语言模型逐步推理，显著提升了模型在复杂任务上的表现。

1.1. 核心论文

  • 论文: Chain-of-Thought Prompting Elicits Reasoning in Large Language Models (Wei et al., NeurIPS 2022)
  • 核心发现: 在示例中加入推理步骤，能让 LLM 学会"一步步思考"

1.2. 核心思想

传统 Prompt: 问题 → 答案
CoT Prompt:   问题 → 推理步骤 → 答案

关键洞察: LLM 不是不会推理，而是需要被引导"说出思考过程"。

2. 二、CoT 为什么有效？

2.1. CoT 有效的三个原因

原因 解释
分解复杂性 将复杂问题分解为简单步骤，降低每步推理难度
增加计算量 生成更多 token，相当于投入更多"计算资源"
可解释性 推理过程可见，便于验证和调试

3. 三、CoT 的四种主要类型

3.1. Few-Shot CoT（少样本思维链）

在 Prompt 中提供几个包含推理过程的示例。

请回答以下数学问题：

示例 1：
问题：小明有 23 颗糖，给了小红 8 颗，又买了 15 颗，现在有多少颗？
推理：小明原本有 23 颗糖。给了小红 8 颗后，剩下 23 - 8 = 15 颗。
又买了 15 颗，所以现在有 15 + 15 = 30 颗。
答案：30

示例 2：
问题：一个长方形长 12 米，宽 8 米，面积是多少？
推理：长方形面积 = 长 × 宽 = 12 × 8 = 96。
答案：96 平方米

现在请回答：
问题：{用户问题}
推理：

特点：

  • ✅ 准确率最高
  • ❌ 需要人工编写高质量示例
  • ❌ 示例质量直接影响效果

3.2. Zero-Shot CoT（零样本思维链）

只需在问题后添加触发词，无需示例。

{问题}

让我们一步一步思考。

或英文版本：

{question}

Let's think step by step.

特点：

  • ✅ 无需示例，即插即用
  • ✅ 实现成本极低
  • ❌ 效果略逊于 Few-Shot CoT
  • ⚠️ 对模型能力有一定要求

3.3. Auto-CoT（自动思维链）

自动构建 Few-Shot 示例，减少人工成本。

核心步骤：

  1. 聚类：将问题按类型聚类
  2. 采样：从每类中选取代表性问题
  3. 生成：用 Zero-Shot CoT 自动生成推理链
  4. 筛选：过滤低质量推理链
  5. 组合：构建最终 Few-Shot Prompt

3.4. Self-Consistency（自一致性）

生成多条推理路径，通过投票选出最终答案。

实现方法：

  • 使用较高的 temperature 值（如 0.7-1.0）生成多样化结果
  • 采样多条推理路径（通常 5-10 条）
  • 对最终答案进行投票

4. 四、CoT 的技术演进时间线

5. 五、CoT 的适用与不适用场景

5.1. ✅ 适用场景

场景 说明 示例
数学计算 需要多步计算 算术、代数、概率
逻辑推理 条件判断、演绎推理 逻辑谜题、因果关系
常识推理 需要多步常识推断 物理常识、社会规则
符号操作 形式化推理 排列组合、字符串操作
代码理解 代码逻辑分析 代码执行结果预测

5.2. ❌ 不适用场景

场景 原因
简单事实问答 直接回答即可，不需要推理
创意生成 不需要严谨的推理步骤
需要外部信息 CoT 只能做内部推理，无法获取外部数据
实时信息查询 模型知识有截止日期

6. 六、CoT 的工程实践技巧

6.1. Prompt 设计最佳实践

## 高效 CoT Prompt 模板

### 1. 明确推理指令
"请逐步推理，先分析...再计算...最后得出..."

### 2. 结构化输出格式
"请按以下格式回答：
分析：...
步骤1：...
步骤2：...
结论：..."

### 3. 要求自我验证
"请检查每一步计算是否正确"
"请验证最终答案是否合理"

### 4. 提供验证标准
"最终答案应该是一个正整数"
"结果应该在 0 到 100 之间"

6.2. 温度参数选择

场景 Temperature 原因
精确推理 0.0 - 0.3 确定性输出，减少随机错误
Self-Consistency 采样 0.5 - 0.8 平衡多样性和质量
探索性任务 0.7 - 1.0 最大化推理路径多样性

7. 七、CoT 与其他技术的关系

8. 八、常见面试考点

8.1. Q1: CoT 的核心思想是什么？

答: 通过在 prompt 中引导 LLM 展示逐步推理过程（中间步骤），将复杂问题分解为多个简单步骤，从而提升模型在推理任务上的准确率和可解释性。

8.2. Q2: Few-Shot CoT 和 Zero-Shot CoT 的区别？

答: Few-Shot CoT 需要手动编写包含推理过程的示例，效果最好但成本高；Zero-Shot CoT 只需添加触发词（如"Let's think step by step"），无需示例，成本低但效果稍差。

8.3. Q3: Self-Consistency 的原理是什么？

答: 通过采样生成多条推理路径，对最终答案进行投票，选择出现频率最高的答案。这利用了"正确答案有多种推导方式"的直觉，能显著提升准确率。

8.4. Q4: CoT 对模型规模有什么要求？

答: CoT 效果与模型规模正相关。通常需要 100B 参数以上的模型才能展现出稳定的 CoT 能力。较小的模型可能无法理解或遵循推理指令。

8.5. Q5: CoT 和 ReAct 的关系？

答: CoT 是 ReAct 的基础。ReAct 在 CoT 的推理能力之上，增加了 Action（行动）维度，使模型能够与外部环境交互。CoT 负责"思考"，ReAct 负责"思考+行动"。
