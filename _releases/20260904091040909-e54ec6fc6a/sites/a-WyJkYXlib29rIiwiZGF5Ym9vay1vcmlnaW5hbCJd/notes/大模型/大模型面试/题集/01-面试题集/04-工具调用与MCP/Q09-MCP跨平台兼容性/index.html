MCP 的跨平台兼容性实现（stdio/HTTP/SSE）

问题

MCP 支持哪些传输方式？各有什么优缺点？如何实现跨平台兼容性？

答案

MCP 的跨平台能力来自于传输层的设计——协议层（JSON-RPC 2.0）与传输层解耦，使得同一份协议可以通过不同的传输方式实现。

三种传输方式对比

特性 stdio SSE (Server-Sent Events) Streamable HTTP
通信方式 本地进程管道 HTTP 长连接 + SSE 标准 HTTP + 动态流式升级
适用场景 本地开发、隐私数据 实时远程通知 云原生、分布式系统
网络依赖 无 必需 必需
多客户端 否（单客户端） 是 是
延迟 1-5ms 50ms+ 50ms+
安全等级 ★★★★★ ★★★★☆ ★★★★☆
跨平台 所有 OS 支持 stdio 依赖 HTTP 库 依赖 HTTP 库
协议演进 长期支持 即将废弃 官方推荐

stdio（标准输入输出）

MCP 默认的通信方式，Client 通过子进程启动 Server，通过 stdin/stdout 通信。

# Server 端（stdio 模式）
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("local-server")

@mcp.tool()
def read_file(path: str) -> str:
    """读取本地文件"""
    with open(path, 'r') as f:
        return f.read()

if __name__ == "__main__":
    mcp.run(transport="stdio")  # 从 stdin 读取，stdout 输出

# Client 端（stdio 模式）
from mcp import StdioServerParameters
from mcp.client.stdio import stdio_client

server_params = StdioServerParameters(
    command="python",
    args=["server.py"],
    env=None
)

async def connect():
    # stdio_client 启动 Server 子进程
    async with stdio_client(server_params) as (read, write):
        # read 读取 Server 的 stdout
        # write 写入 Server 的 stdin
        ...

消息格式：每条消息是一行 JSON-RPC 2.0 + 换行符

{"jsonrpc":"2.0","id":1,"method":"tools/list"}\n
{"jsonrpc":"2.0","id":1,"result":{"tools":[...]}}\n

优点：

  • 极低延迟（进程间通信，无网络开销）
  • 极高安全性（不暴露网络端口）
  • 简单实现（无需网络配置）
  • 所有操作系统原生支持

缺点：

  • 仅限本地（Client 和 Server 必须在同一台机器）
  • 单客户端（一个 Server 进程只能服务一个 Client）
  • 子进程崩溃可能影响主进程

Streamable HTTP（推荐方案）

SSE 的升级版，完全基于标准 HTTP 协议，支持动态升级为 SSE 流。

# Server 端（HTTP 模式）
from mcp.server.fastmcp import FastMCP
from mcp.server.sse import SseServerTransport

mcp = FastMCP("http-server")

@app.post("/message")
async def handle_message(request: Request):
    """处理客户端消息"""
    body = await request.body()
    # 解析 JSON-RPC 请求并处理
    ...

@app.get("/sse")
async def handle_sse(request: Request):
    """SSE 连接端点"""
    ...

核心优势：

  • 无状态支持：Server 可以完全无状态运行，适配云函数（AWS Lambda）
  • 基础设施兼容：与 CDN、API 网关、负载均衡无缝集成
  • HTTP/2/3 支持：支持多路复用和双向流
  • 动态流式升级：普通 HTTP 请求可按需升级为 SSE 流

跨平台兼容性最佳实践

class CrossPlatformMCPClient:
    """跨平台 MCP 客户端，自动适配传输方式"""
    
    @staticmethod
    async def connect_stdio(command: str, args: List[str]):
        """stdio 方式连接（本地）"""
        from mcp.client.stdio import stdio_client
        server_params = StdioServerParameters(command=command, args=args)
        return stdio_client(server_params)
    
    @staticmethod
    async def connect_http(url: str, headers: dict = None):
        """HTTP 方式连接（远程）"""
        from mcp.client.http import http_client
        return http_client(url, headers=headers)
    
    @staticmethod
    def auto_detect(server_config: dict):
        """根据配置自动选择传输方式"""
        if server_config.get("transport") == "stdio":
            return CrossPlatformMCPClient.connect_stdio(
                server_config["command"],
                server_config.get("args", [])
            )
        elif server_config.get("transport") == "http":
            return CrossPlatformMCPClient.connect_http(
                server_config["url"],
                server_config.get("headers")
            )
        else:
            raise ValueError(f"不支持的传输方式: {server_config}")

传输方式选择建议

场景 推荐方式 理由
本地开发调试 stdio 零配置、低延迟、高安全
本地隐私数据处理 stdio 数据不出本机
团队共享服务 Streamable HTTP 多客户端、可扩展
云函数部署 Streamable HTTP 无状态、按需计费
微服务架构 Streamable HTTP 服务发现、负载均衡

跨平台注意事项

  1. 路径分隔符：Windows 用 \，Linux/macOS 用 /——使用 pathlib 处理
  2. 进程启动方式：Windows 需要 shell=True 或 .cmd 后缀
  3. 环境变量：不同平台的环境变量设置方式不同
  4. 编码问题：统一使用 UTF-8

延伸追问

Q: SSE 为什么被淘汰？
A: SSE 有数据格式限制（只支持文本）、跨平台兼容性差、基于 HTTP/1.1 长连接性能有限。Streamable HTTP 是其升级替代方案。

Q: stdio 的双向通信有什么问题？
A: stdio 本应是单向的（stdin 输入、stdout 输出），MCP 将其改造为双向通信，这在 Unix/Linux 哲学中有点"反直觉"，但实现了零配置的本地通信。

常见误区

  1. 误区：stdio 只能用于简单场景。
    纠正：stdio 延迟最低、最安全，很多生产环境（如 Cursor）也在用。

  2. 误区：HTTP 方式一定比 stdio 好。
    纠正：HTTP 有网络开销，本地场景 stdio 更优。

  3. 误区：所有平台都可以随便选传输方式。
    纠正：Windows 上 stdio 可能需要额外处理路径和进程启动方式。
