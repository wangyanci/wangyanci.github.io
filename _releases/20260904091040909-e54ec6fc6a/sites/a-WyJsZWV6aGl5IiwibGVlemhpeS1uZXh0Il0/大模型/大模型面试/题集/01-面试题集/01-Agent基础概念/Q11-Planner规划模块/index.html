Agent 的 Planner 规划模块有哪些主流方法？各自适用什么场景？

问题

Agent 的规划（Planning）模块有哪些主流方法？如 CoT、ToT、Reflexion 等，各自的原理、优缺点和适用场景是什么？

1. 答案

规划模块是 Agent 处理复杂任务的核心能力，主流方法从简单到复杂演进：

规划方法演进路线：

CoT (链式思考) → ToT (思维树) → GoT (思维图) → Reflexion (反思)
   线性推理        多路径探索        网络结构          自我纠错

方法一：CoT（Chain-of-Thought，思维链）

  • 原理：引导 LLM 显式生成中间推理步骤，将复杂问题分解为子步骤
  • Prompt 技巧："Let's think step by step"
  • 优点：简单有效，显著提升复杂推理准确率
  • 缺点：线性推理，一旦某步错误无法回溯
  • 适用：数学计算、逻辑推理、单路径问题
# CoT Prompt 示例
cot_prompt = """
问题：一个农场有鸡和兔，头共35个，脚共94只。鸡兔各几只？

请逐步思考：
Step 1: 设鸡有 x 只，兔有 y 只
Step 2: 根据题意列方程：x + y = 35，2x + 4y = 94
Step 3: 解方程组...
"""

方法二：ToT（Tree of Thoughts，思维树）

  • 原理：将推理过程建模为树结构，每个节点是一个"思维"，可以探索多条路径
  • 流程：生成候选思维 → 评估每个思维的价值 → 选择最有希望的路径继续
  • 优点：支持多路径探索、可回溯、适合开放性问题
  • 缺点：计算成本高，需要多次 LLM 调用
  • 适用：创意生成、策略游戏、需要探索多种方案的问题
class TreeOfThoughts:
    """思维树实现"""
    
    def solve(self, problem: str, max_depth: int = 5, 
              branching_factor: int = 3) -> str:
        # 根节点：初始问题
        root = ThoughtNode(content=problem, parent=None)
        
        for depth in range(max_depth):
            # 1. 获取当前层所有叶子节点
            leaves = root.get_leaves()
            
            for leaf in leaves:
                if leaf.is_terminal:
                    continue
                    
                # 2. 生成多个候选思维（分支）
                candidates = self.generate_thoughts(
                    leaf, 
                    k=branching_factor
                )
                
                # 3. 评估每个候选的价值
                for candidate in candidates:
                    candidate.value = self.evaluate_thought(candidate)
                
                # 4. 保留 Top-K 最有价值的分支
                best_candidates = sorted(
                    candidates, 
                    key=lambda x: x.value, 
                    reverse=True
                )[:2]
                
                leaf.children.extend(best_candidates)
        
        # 返回最优路径的答案
        best_leaf = max(root.get_leaves(), key=lambda x: x.value)
        return self.trace_back(best_leaf)

方法三：Reflexion（反思）

  • 原理：Agent 对自己的行为和结果进行评估和反思，从错误中学习
  • 三个核心组件：Actor（执行者）、Evaluator（评估者）、Self-Reflection（自我反思）
  • 优点：能从失败中学习、持续改进、减少重复错误
  • 缺点：需要额外的 LLM 调用进行反思，增加延迟
  • 适用：代码生成、多步推理、需要高质量输出的任务
class ReflexionAgent:
    """Reflexion: 语言强化学习框架"""
    
    def __init__(self):
        self.actor = Actor()        # 生成行动
        self.evaluator = Evaluator() # 评估结果
        self.reflector = Reflector() # 生成反思
        self.memory = []            # 存储反思经验
    
    def run(self, task: str, max_trials: int = 3) -> str:
        for trial in range(max_trials):
            # Actor 执行任务（参考之前的反思经验）
            trajectory = self.actor.act(task, self.memory)
            
            # Evaluator 评估结果
            score, feedback = self.evaluator.evaluate(trajectory)
            
            if score >= self.success_threshold:
                return trajectory.final_answer
            
            # Self-Reflection 生成反思
            reflection = self.reflector.reflect(
                trajectory=trajectory,
                feedback=feedback
            )
            self.memory.append(reflection)
        
        return trajectory.final_answer  # 返回最佳尝试

方法四：Plan-and-Solve（先规划再解决）

  • 原理：先让 LLM 生成完整计划，再按步骤执行
  • 变体：Plan-and-Execute（含动态 replan）
  • 优点：全局视角，步骤间依赖关系清晰
  • 缺点：初期计划可能不适应执行中发现的新情况
  • 适用：步骤明确、依赖关系清晰的任务

方法五：LLM Compiler（DAG 规划）

  • 原理：让 LLM 生成有向无环图（DAG），明确任务间依赖关系，并行执行
  • 优点：最大化并行度，显著加速复杂任务
  • 缺点：需要准确的依赖分析
  • 适用：大规模数据处理、可并行化的复杂工作流
class LLMCompiler:
    """LLM Compiler - DAG 并行执行"""
    
    def plan(self, task: str) -> DAG:
        """生成任务 DAG"""
        prompt = f"将以下任务分解为 DAG，标注依赖关系：{task}"
        dag_text = self.llm.generate(prompt)
        return self.parse_dag(dag_text)
    
    def execute(self, dag: DAG) -> dict:
        """拓扑排序 + 并行执行"""
        results = {}
        for layer in dag.topological_layers():  # 按层执行
            # 同层任务并行执行
            with ThreadPoolExecutor() as executor:
                futures = {
                    executor.submit(self.run_task, task, results): task
                    for task in layer
                }
                for future in as_completed(futures):
                    task = futures[future]
                    results[task.id] = future.result()
        return results

方法对比总结：

方法 核心思想 适用场景 计算成本
CoT 线性逐步推理 数学、逻辑推理 低
ToT 树状多路径探索 创意、策略问题 高
Reflexion 自我反思纠错 代码、高质量输出 中
Plan-and-Solve 先规划再执行 流程型任务 中
LLM Compiler DAG 并行执行 大规模并行任务 中

2. 延伸追问

  1. 追问：如何选择合适的规划方法？

    • 答：简单确定性任务用 CoT；需要探索的开放问题用 ToT；要求高质量输出的用 Reflexion；流程固定用 Plan-and-Solve；大规模任务用 LLM Compiler。

  2. 追问：这些规划方法可以组合使用吗？

    • 答：可以。如先用 Plan-and-Solve 做全局规划，每个子任务内部用 CoT 或 ToT，最后用 Reflexion 检查质量。

3. 常见误区

  • 误区：ToT 一定比 CoT 好
  • 纠正：ToT 计算成本高，对于确定性问题 CoT 更高效。选择方法要考虑任务特性和成本约束
