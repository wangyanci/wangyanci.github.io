如何设计 Agent 的全链路可观测体系？

问题

生产环境的 Agent 系统需要监控哪些指标？如何设计全链路可观测体系？

答案

一、Agent 可观测的三大支柱

支柱 工具示例 Agent 专项内容
Trace (链路追踪) OpenTelemetry, LangSmith, Langfuse 完整请求链路：意图识别 → RAG检索 → LLM调用 → 工具执行 → 答案生成
Metrics (指标监控) Prometheus + Grafana TTFT, TBT, Token消耗, 幻觉率, 工具调用成功率
Logs (日志) ELK/Loki 结构化日志：trace_id, model, token_count, latency, cost

二、Agent 专项指标体系

# Agent 核心监控指标定义
AGENT_METRICS = {
    # === 延迟指标 ===
    "ttft_p50": "首字延迟 P50 (ms)",           # 目标 < 500ms
    "ttft_p99": "首字延迟 P99 (ms)",           # 目标 < 2000ms
    "tbt_avg": "Token 间平均延迟 (ms)",         # 目标 < 50ms
    "e2e_latency_p50": "端到端延迟 P50 (ms)",  # 目标 < 3000ms
    
    # === 成本指标 ===
    "token_input_per_req": "每请求 Input Token",
    "token_output_per_req": "每请求 Output Token", 
    "cost_per_req_usd": "每请求成本 (USD)",
    "daily_cost_usd": "日总成本 (USD)",
    
    # === 质量指标 ===
    "hallucination_rate": "幻觉率 (%)",         # 目标 < 2%
    "tool_call_success_rate": "工具调用成功率 (%)",  # 目标 > 99%
    "intent_accuracy": "意图识别准确率 (%)",    # 目标 > 95%
    "user_satisfaction": "用户满意度 (CSAT)",   # 目标 > 4.2/5
    
    # === 系统指标 ===
    "request_qps": "每秒请求数",
    "error_rate": "错误率 (%)",                 # 目标 < 0.5%
    "cache_hit_rate": "缓存命中率 (%)",         # 目标 > 30%
    "model_degrade_rate": "模型降级率 (%)",     # 目标 < 5%
}

三、LangSmith/Langfuse 等工具的核心能力

# LangSmith 追踪示例
from langsmith import traceable
from langchain_openai import ChatOpenAI

@traceable(run_type="llm")  # 自动追踪 LLM 调用
def agent_step(query: str, context: dict) -> str:
    llm = ChatOpenAI(model="gpt-4o")
    # 每个步骤自动记录：输入、输出、token消耗、延迟
    response = llm.invoke(f"基于上下文 {context} 回答：{query}")
    return response.content

# 追踪结果包含：
# - 完整调用链（Trace Tree）
# - 每个节点的 Input/Output
# - Token 使用量
# - 延迟分解
# - 模型名称和参数

四、AI 特有的漂移检测

# Golden Set 持续评估
class DriftDetector:
    def __init__(self, golden_set: list[EvalCase]):
        self.golden_set = golden_set  # 标准测试集（100-500条）
        self.baseline_score = self._evaluate()
    
    def daily_check(self) -> Alert | None:
        current_score = self._evaluate()
        
        # 答案质量分数下降 > 5% 触发告警
        if self.baseline_score - current_score > 0.05:
            return Alert(
                level="P1",
                message=f"质量漂移 detected: {self.baseline_score:.3f} -> {current_score:.3f}",
                possible_causes=[
                    "知识库文档过期",
                    "模型版本切换",
                    "Prompt 被错误修改",
                    "工具 API 返回格式变化"
                ]
            )
        return None

五、告警分级体系

级别 触发条件 响应时间 处理方案
P0 模型全量不可用、消息丢失 5 分钟 自动降级 + 人工介入
P1 错误率 > 5%、TTFT > 5s 30 分钟 熔断 + 扩容
P2 准确率下降、成本异常 次日处理 分析 + 优化

延伸追问

  • "你提到 LangSmith，能具体说说怎么落地的吗？"
    • 在所有 LLM 调用处添加 @traceable 装饰器
    • 定义统一的 Tag 体系：project, environment, model_version
    • 设置每日 Golden Set 自动评估 Pipeline
    • 集成 Slack/PagerDuty 告警

常见误区

  • ❌ "只监控系统指标就够了" — Agent 需要专门的业务指标（幻觉率、满意度）
  • ❌ "等用户投诉再发现问题" — 需要主动的质量漂移检测
