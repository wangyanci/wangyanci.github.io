ToT 树状推理（Tree of Thoughts）

一、ToT 概述

ToT（Tree of Thoughts，树状推理）是 2023 年由 Princeton 和 Google DeepMind 的研究者提出的高级推理框架。它在 CoT（思维链）的基础上引入了树形搜索，允许模型探索多条推理路径，而不是像 CoT 那样只有单一的线性推理链。

核心论文

  • 论文: Tree of Thoughts: Deliberate Problem Solving with Large Language Models (Yao et al., Long 2023)
  • 核心贡献: 将 LLM 推理从线性链式结构升级为树状搜索结构，显著提升复杂问题解决能力

核心思想

CoT: 问题 → 步骤1 → 步骤2 → 步骤3 → 答案 （单一路径）
ToT: 问题 → [步骤1A, 步骤1B, 步骤1C] → 评估 → 选择 → ... （多路径探索）

关键洞察: 人类解决问题时会尝试多种思路，评估后选择最有希望的方向。ToT 模拟了这一过程。

二、ToT 与 CoT 的核心区别

维度 CoT ToT
结构 线性链 树形结构
路径数 单一路径 多条并行路径
回溯能力 无（单向前进） 有（可回退重试）
评估机制 无中间评估 每步评估并选择
计算成本 低（O(N)） 较高（O(b^d)）
适用问题 确定性推理 需要探索的决策问题
实现复杂度 简单 较复杂

三、ToT 的核心组件

1. 思维生成（Thought Generation）

在每个节点，LLM 负责生成多个可能的下一步思考。

两种生成策略：

策略 方法 适用场景
采样策略 从同一 prompt 多次采样，生成多样化思路 创意类问题
提议策略 显式要求模型生成 k 个不同方案 决策类问题

示例：

问题：24点游戏，给定数字 [4, 9, 10, 13]

候选思路 1: 先尝试 13 + 10 = 23
候选思路 2: 先尝试 13 - 9 = 4
候选思路 3: 先尝试 4 × 9 = 36

2. 状态评估（State Evaluation）

评估每个候选思路的"前景"，决定哪些值得继续探索。

三种评估方法：

方法 描述 成本
价值评估 让 LLM 对状态打分（1-10） 低
投票评估 多条推理投票选出最佳 中
启发式评估 基于规则或函数评估 低

示例：

评估候选思路 1 (13+10=23):
- 23 距离 24 很近，只需要再得到 1
- 剩余数字 [4, 9]，可以得到 1 (如 9-4=5, 不行)
- 评分: 7/10（有潜力但不确定）

评估候选思路 2 (13-9=4):
- 得到 4，剩余 [4, 10]
- 4 × 4 + 10 = 26 ≠ 24
- 评分: 4/10

3. 搜索算法（Search Algorithm）

ToT 支持多种经典搜索算法：

BFS（广度优先搜索）

def bfs_search(problem, beam_width=3, max_depth=5):
    """ToT 广度优先搜索"""
    current_level = [problem.initial_state]
    
    for depth in range(max_depth):
        candidates = []
        
        # 扩展所有当前节点
        for state in current_level:
            thoughts = generate_thoughts(state, k=beam_width)
            candidates.extend(thoughts)
        
        # 评估所有候选
        scored = [(state, evaluate(state)) for state in candidates]
        scored.sort(key=lambda x: x[1], reverse=True)
        
        # 保留 top-k
        current_level = [s for s, _ in scored[:beam_width]]
        
        # 检查是否找到解
        for state in current_level:
            if is_solution(state):
                return state
    
    return best_state

DFS（深度优先搜索）

def dfs_search(state, depth=0, max_depth=5, threshold=0.5):
    """ToT 深度优先搜索"""
    if is_solution(state):
        return state
    if depth >= max_depth:
        return None
    
    # 生成候选
    thoughts = generate_thoughts(state, k=3)
    
    for thought in thoughts:
        score = evaluate(thought)
        if score < threshold:  # 剪枝
            continue
        
        result = dfs_search(thought, depth + 1, max_depth, threshold)
        if result:
            return result
    
    return None

四、ToT 完整流程示例

以 24点游戏 为例，展示 ToT 的完整推理过程：

推理过程说明：

  1. 第一层：从初始状态生成 4 个候选操作
  2. 评估：10-4=6 评分最高（得到 6，距离 24 需要乘 4）
  3. 第二层：从 6 + [9, 13] 继续探索
  4. 发现：13-9=4，然后 6×4=24，找到解！

五、ToT 的适用场景

✅ 最适合的场景

场景 原因 典型应用
游戏问题 需要探索多种策略 24点、数独、棋类
创意写作 需要生成多种创意方案 故事生成、文案创作
决策规划 需要评估多个方案 路径规划、资源分配
数学证明 需要尝试多种证明思路 几何证明、逻辑证明
代码生成 多种实现方案对比 算法实现、代码优化

❌ 不太适合的场景

场景 原因
简单事实问答 不需要探索
确定性计算 CoT 足够
实时交互 搜索耗时较长
高并发请求 计算成本高

六、ToT 的工程实现要点

关键参数调优

参数 作用 建议值
branching_factor 每层分支数 3-5
beam_width BFS 保留数 2-3
max_depth 最大搜索深度 5-10
evaluation_threshold DFS 剪枝阈值 0.3-0.5
temperature 生成多样性 0.5-0.8

性能优化策略

  1. 缓存评估结果：相同状态的评估结果缓存复用
  2. 并行评估：多个候选节点并行评估
  3. 早停机制：找到满意解后提前终止
  4. 渐进式深度限制：先浅层搜索，必要时加深
  5. 评估模型蒸馏：用小模型做初步筛选

七、ToT 的演进：GoT（Graph of Thoughts）

GoT 在 ToT 的基础上：

  • 支持任意图结构（不只是树）
  • 允许节点聚合（合并多个思路）
  • 支持循环和反馈（迭代优化）
  • 更灵活的拓扑（适应更复杂的问题）

八、常见面试考点

Q1: ToT 和 CoT 的根本区别？

答: CoT 是线性链式推理，只有一条路径；ToT 是树状推理，可以同时探索多条路径，并在每步进行评估和选择，支持回溯。

Q2: ToT 的三个核心组件是什么？

答:

  1. 思维生成：在每个节点生成多个候选思路
  2. 状态评估：评估每个候选的前景分数
  3. 搜索算法：BFS、DFS 或 MCTS 决定搜索策略

Q3: ToT 为什么比 CoT 更适合决策问题？

答: 决策问题通常有多种可行方案，需要评估比较。ToT 的多路径探索和评估机制正好匹配这一需求，而 CoT 的线性结构可能一开始就选择了错误方向。

Q4: ToT 的计算成本高，如何优化？

答:

  1. 限制分支数和深度
  2. 使用 Beam Search 限制节点数
  3. 实现评估缓存
  4. 并行评估候选节点
  5. 使用较小的模型做初步筛选
