MCP vs Function Calling 对比分析

一、本质区别

一句话概括区别：

  • Function Calling 是 LLM 的能力（模型决定调用什么函数）
  • MCP 是协议标准（规定工具如何被描述、发现和调用）

二、详细对比

对比维度总览

对比维度 Function Calling MCP 说明
抽象层次 应用层 API 传输层协议 FC 是 LLM API 的一部分；MCP 是独立协议
控制主体 模型决定 Host 管理 FC 由模型输出决定；MCP 由 Host 协调
工具定义 应用层传入 Server 自描述 FC 在请求时传入工具定义；MCP Server 主动暴露
工具发现 静态传入 动态发现 FC 工具列表固定；MCP 可运行时发现
供应商锁定 有（各厂商格式不同） 无（统一标准） MCP 旨在消除供应商锁定
生态共享 各平台独立 可跨平台复用 MCP Server 可被任意 Host 使用
通信方式 无（直接函数调用） stdio/SSE/HTTP MCP 定义了通信规范
实现复杂度 低（直接调 API） 中（需实现协议） MCP 需要额外的协议实现

三、架构位置对比

Function Calling 在系统中的位置

MCP 在系统中的位置

四、关系：互补而非竞争

关键理解：

  • MCP 可以使用 Function Calling 作为底层机制
  • MCP 不替代 Function Calling，而是在其上增加标准化层
  • Function Calling 不依赖 MCP，可独立使用

五、使用场景对比

场景 推荐方案 原因
简单工具调用（1-3个） Function Calling 简单直接，无需额外依赖
复杂工具生态（10+工具） MCP 标准化管理，动态发现
跨应用共享工具 MCP Server 可被多个 Host 使用
快速原型开发 Function Calling 低门槛，快速验证
企业级工具平台 MCP 标准化、可管理、可观测
单一应用内部 Function Calling 无需引入额外复杂度
IDE 插件 MCP 标准化的工具接入

六、代码对比

Function Calling 方式

import openai
import json

# 定义工具
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string"}
                },
                "required": ["city"]
            }
        }
    }
]

# 调用
response = client.chat.completions.create(
    model="gpt-4",
    messages=[{"role": "user", "content": "北京天气"}],
    tools=tools
)

# 手动执行函数
if response.choices[0].message.tool_calls:
    tool_call = response.choices[0].message.tool_calls[0]
    result = execute_function(tool_call.function.name, 
                             json.loads(tool_call.function.arguments))

MCP 方式

# Server 端（独立进程）
from mcp.server import Server

app = Server("weather-server")

@app.list_tools()
async def list_tools():
    return [Tool(name="get_weather", ...)]

@app.call_tool()
async def call_tool(name, arguments):
    return get_weather(**arguments)

# Host 端
from mcp import ClientSession, StdioServerParameters

# 启动 Server 并建立连接
server_params = StdioServerParameters(command="python", args=["weather_server.py"])
async with ClientSession(server_params) as session:
    # 动态发现工具
    tools = await session.list_tools()
    
    # 工具列表传递给 LLM
    response = llm.chat(messages, tools=tools)
    
    # 通过 MCP 调用
    if response.tool_calls:
        result = await session.call_tool(
            response.tool_calls[0].name,
            response.tool_calls[0].arguments
        )

七、常见面试考点

Q1: MCP 和 Function Calling 的本质区别？

答: Function Calling 是模型能力（LLM 决定调用什么函数）；MCP 是通信协议（标准化工具连接方式）。MCP 可以使用 Function Calling 作为底层实现。

Q2: 什么时候用 MCP，什么时候用 Function Calling？

答: 简单场景用 Function Calling；需要管理大量工具、跨应用共享工具、构建工具生态时用 MCP。

Q3: MCP 能消除供应商锁定吗？

答: 在工具层可以。MCP 统一了工具连接标准，不同 LLM 可以通过 MCP 使用相同的工具集。但 LLM 本身仍有供应商锁定。
