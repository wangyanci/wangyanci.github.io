项目二：财报解析智能体开发

• 设计并实现 5 个核心 Agent（数据预处理、时序审计、指标计算、风险分析、信息收集），通过工作流编排实现多 Agent 协作与数据流转

职责

• 设计并实现 5 个核心 Agent（数据预处理、时序审计、指标计算、风险分析、信息收集），通过工作流编排实现多 Agent 协作与数据流转

• 设计双 LLM 并发架构，将 Markdown 报告与 JSON 结构化数据分离到独立 LLM 并发生成

• 实现表达式驱动的财务指标计算引擎，支持多期趋势分析与环比增长率计算

职责说明

1. 核心Agent

2. Agent协作与数据流转

采用 agentUniverse 的 Workflow DAG 编排，通过 YAML 文件定义节点和边，无需代码即可调整流程。核心工作流 financial_report_workflow 的 DAG 结构：

Start
  │
  ▼
IngestionAgent (数据预处理)
  │
  ├──→ IntegrityAgent (时序审计) ──→ CalcAgent (指标计算) ──→┐
  │                                                          │
  └──────────────────────────────────────────────────────────┤
                                                             ▼
                                                    AnalysisAgent → End
关键设计：IngestionAgent 的输出同时流入 IntegrityAgent 和 AnalysisAgent，实现数据并行处理。

每个 Agent 的输入输出通过 引用机制（reference） 连接。YAML 中定义：

# IngestionAgent 的输出 → CalcAgent 的输入
input_param:
  - name: input
    value:
      type: reference
      content:
        - agent-cea0105a   # IngestionAgent 的节点 ID
        - output           # 引用其 output 字段
数据在节点间自动传递，Workflow 引擎负责 DAG 拓扑排序和并行调度。
Agent 输入 输出 职责
IngestionAgent user_input (base64 PDF + 元数据) gent 标准化 JSON: {task_id, company_id, company_name, data: [...]} PDF 解析 → LLM 清洗 → 科目映射 → ES 存储
IntegrityAgent IngestionAgent.output {audit_result: {time_series_continuity, trend_analysis_feasibility, ...}} 检查数据连续性，验证完整性

Collection user messages {collected_data, status, ready_for_analysis} 多轮对话收集信息

3. 双LLM并发架构

单 LLM 同时生成报告和 JSON 容易截断，所以我把 Markdown 和 JSON 分离到两个独立 LLM 并发生成。

输出 用途 格式 要求
Markdown 报告 人工阅读，风险分析报告 自然语言，可读性强
JSON 数据 前端渲染图表、风险评分展示 严格结构化，必须完整

单 LLM 同时生成两部分时存在三个致命问题：
问题一：JSON 截断

LLM 生成 Markdown 报告通常需要 2000-3000 tokens，JSON 数据需要 1000-2000 tokens。当 max_tokens 限制或网络超时时，JSON 经常被截断，导致括号不匹配、字段缺失，前端无法解析。
问题二：目标相互干扰
Markdown 要求"语言流畅、逻辑清晰"，JSON 要求"结构严谨、字段完整"。一个 prompt 同时要求 LLM 做两件风格完全不同的事，生成质量互相拖累。
问题三：流式输出矛盾
Markdown 适合流式输出（用户实时看到报告生成），但 JSON 必须完整才能解析。如果 JSON 也流式输出，前端收到一半的 { "meta": { "company_name": "XX 是没法用的。

还有可以使用不同的温度，JSON格式温度可以更低。

4. 计算引擎

表达式驱动的财务指标计算引擎，把 14 个财务指标的计算公式配置化，通过安全 eval() 执行，支持多期趋势分析和环比增长率自动计算。

CalcAgent 的职责是把原始财务科目数据转换成业务可用的财务指标。比如从资产负债表的"资产总计"和"负债合计"算出"资产负债率"。

核心是 METRIC_FORMULAS 字典 + 安全 eval()：

METRIC_FORMULAS = {
    "资产负债率": "100 * BS_4000 / BS_3000",
    "流动比率": "BS_1000 / BS_5000",
    "速动比率": "(BS_1000 - BS_1401) / BS_5000",
    "净资产收益率(ROE)": "100 * IS_6701 / BS_7000",
    # ... 共 14 个指标
}

原始财务数据                     科目数值字典                    指标结果
{                               {                              
  "balance_sheet": [             "BS_3000": 10000,              "资产负债率": 40.0
    {subject_code: "3000",       "BS_4000": 4000,               "流动比率": 2.0
     field_value: 10000},        "BS_1000": 6000,               "ROE": 5.33
    ...                          "IS_6001": 20000,               ...
  ]                              ...
}                                }
     ↓                                ↓
  _build_subject_values    →    eval("100 * BS_4000 / BS_3000")
  (科目名→编码映射)              (安全执行公式)

安全 eval() 的关键：

result = eval(expr, {"__builtins__": {}}, local_vars)
#                     ↑ 禁用所有内置函数    ↑ 只注入科目数值
# 这样 LLM 或用户无法注入恶意代码，只能做数学运算
  1. "eval() 不安全怎么办？"

    通过 {"builtins": {}} 禁用了所有内置函数，变量只注入了数值类型的科目数据，无法执行文件操作或系统命令。并且公式是固定配置，不是用户输入的。

  2. "科目编码怎么来的？"

    有两层：一是 subject_mapping.py 定义了 57 个科目中文名到编码的映射；二是 IngestionAgent 通过 LLM 做科目映射，给每个字段打上 subject_code。CalcAgent 优先用 subject_code，没有时 fallback 到 field_name 映射。

  3. "如果科目数据缺失怎么办？"

    公式中任意变量为 None 或分母为 0，该指标返回 None，不会报错。CalcAgent 还会自动补算缺失的合计科目（如流动资产合计 = 各流动资产之和）。

5. 如何确保财报数据的准确性

  1. 科目映射双保险
    科目中文名 ──→ subject_mapping.py (57个硬编码映射)
    ──→ IngestionAgent LLM 映射 (动态匹配)
    优先使用 subject_code（如 BS_3000），没有时 fallback 到 field_name 映射。避免因科目名称中英文差异导致数据错位

  2. 数据格式标准化
    IngestionAgent 的 _normalize_financial_data() 统一处理多种输入格式：

  • 识别报表类型（资产负债表/利润表/现金流量表）
  • 统一字段结构：{flag, subject_code, field_name, field_value}
  • 自动计算季度 period_date（_calculate_quarter_period_date()）

二、计算过程：防御性编程

  1. 安全 eval()
result = eval(expr, {"__builtins__": {}}, local_vars)
# 禁用内置函数，只注入数值变量
# 分母为 0 返回 None，不抛异常
  1. 缺失科目自动补算
_calculate_missing_totals() 自动计算缺失的合计科目：
# 如果 BS_1000（流动资产合计）缺失
# 自动累加：应收款项融资 + 其他应收款 + 存货 + 合同资产 + ...
# 如果 BS_4000（负债合计）缺失
# 自动计算：BS_5000（流动负债） + BS_6000（非流动负债）
  1. 空值安全处理
def _get_value(self, data, key):
    value = data.get(key)
    return float(value) if value is not None else None
# 任意变量为 None → 该指标返回 None（不报错）
# 分母为 0 → 返回 None（不抛 ZeroDivisionError）

三、数据验证：多层交叉校验

  1. CalcAgent 内置单测
def _test_all_metrics(self):
    # 构造已知输入，验证输出是否匹配手工计算结果
    raw_input = {
        "balance_sheet": [
            {"subject_code": "3000", "field_value": 10000},  # 资产总计
            {"subject_code": "4000", "field_value": 4000},   # 负债合计
        ],
        ...
    }
    # 预期：资产负债率 = 100 * 4000 / 10000 = 40.0
    assert abs(metrics["资产负债率"] - 40.0) < 1e-6
  1. IntegrityAgent 时序审计
    在指标计算之前，先验证数据完整性：
  • 检查时间序列是否连续（季度数据是否缺失）
  • 判断是否满足趋势分析要求（至少 2 期数据）
  • 生成审计结论，供 AnalysisAgent 参考
  1. AnalysisAgent 交叉验证
    Prompt 中要求 LLM 将指标计算结果与原始财务数据交叉验证：

    "从 indictor 中提取多期财务指标，与 data_preprocessing 中的原始数据进行交叉验证"

我从四个层面保障数据准确性：

源头：IngestionAgent 做数据标准化，科目映射有硬编码字典和 LLM 动态匹配双保险，统一输出 {subject_code, field_value} 格式。

计算：CalcAgent 用安全 eval() 执行公式，禁用内置函数；任意变量缺失或分母为 0 返回 None 不报错；还会自动补算缺失的合计科目。

验证：IntegrityAgent 在计算前先做时序审计，检查数据连续性和完整性；CalcAgent 自带单测，用已知输入验证输出是否匹配手工计算。

交叉：AnalysisAgent 拿到指标后，与原始财务数据交叉验证，发现异常会在报告中标注。

6. 如何提高PDF的识别准确率

一、当前方案：双层解析架构

PDF 文件
  │
  ├──→ 优先：外部 API (192.168.10.149 专业财报解析服务)
  │         │
  │         ├── 成功 → 返回结构化结果
  │         └── 失败 ↓
  │
  └──→ Fallback：pdfplumber 本地解析
            │
            ├── 提取表格 → 转 HTML → 分类
            └── 提取纯文本

为什么用双层？ 专业 OCR 服务识别率高但可能不可用（网络、部署），pdfplumber 免费可靠但对扫描件效果差。双层保证系统永远有输出。

二、提高准确率的具体手段

  1. 表格分类：双重匹配
    关键词匹配 + 内容特征匹配
self.balance_sheet_keywords = ['资产负债表', 'balance sheet']
self.balance_sheet_content_keywords = [
    '资产总计', '负债总计', '所有者权益合计',
    '流动资产合计', '货币资金', '应收账款', '存货'
]

不只看表格标题，还看表格内容是否包含该类报表的特征科目。避免标题被截断时仍能正确分类。

  1. 科目名称标准化
    不同企业财报的科目名称可能不同（如"应收账款" vs "应收款项"），通过 subject_mapping.py 的 57 个映射统一到标准编码：
    "应收账款": "1122",
    "应收票据": "1121",
    "存货": "1401",
    LLM 清洗阶段也会做名称归一化。

  2. 数据清洗：LLM 辅助
    IngestionAgent 调用 LLM 对 pdfplumber 提取的原始数据做清洗：

  • 识别并纠正 OCR 识别错误（如 0 vs O，1 vs l）
  • 提取嵌套在表格中的数值
  • 从非结构化文本中抽取科目和金额
  1. 合计行自动补算
CalcAgent._calculate_missing_totals() 在计算前自动补算缺失的合计科目：
# 如果"流动资产合计"缺失
# 自动累加：货币资金 + 应收账款 + 存货 + 预付款项 + ...
if "BS_1000" not in subject_values:
    current_assets = sum(各项流动资产)
    subject_values["BS_1000"] = current_assets

即使 pdfplumber 提取时漏掉了合计行，指标计算仍能正常进行。

  1. 多页表格拼接
def extract_tables_from_pdf(self, pdf_data):
    for page_num, page in enumerate(pdf.pages):
        page_tables = page.extract_tables()
        # 每页的表格都提取，后续按类型归类

跨页表格会被拆成多个子表，分类后合并到同一报表类型下。

追问预判

  1. "扫描件 PDF 怎么处理？"

    pdfplumber 对扫描件效果差，需要 OCR 服务。当前 fallback 方案依赖外部 API（192.168.10.149），如果需要纯本地处理，可以集成 Tesseract 或 PaddleOCR。

  2. "如果表格线不清晰怎么办？"

    pdfplumber 的 extract_tables() 依赖表格线检测。对于无边框表格，可以改用 extract_text() + 正则解析，或调用外部 OCR 服务。

  3. "识别错了怎么发现？"

    CalcAgent 的指标计算会暴露问题——如果科目值为 None 或异常大/小，对应的指标会返回 None 或异常值。AnalysisAgent 在报告中标注数据异常。
