问题

解释 Agent 长期记忆使用向量数据库的原因，详细说明 Embedding、相似度计算和 ANN（近似最近邻）搜索的原理，以及工程实现中的选型要点。

1. 答案

为什么用向量数据库：

Agent 的长期记忆需要支持语义检索——用自然语言查询找到相关的记忆，而不是精确匹配关键词。向量数据库通过将文本转换为高维向量（Embedding），使得语义相似的文本在向量空间中距离相近，从而实现"意思相近就能找到"的检索效果。

核心流程：

文本 → Embedding 模型 → 高维向量 → 存入向量数据库
查询文本 → Embedding → 向量检索 → 返回最相似的 Top-K 条记忆

Embedding 原理：

Embedding 是将离散的文本（token）映射到连续的向量空间的过程。现代 Embedding 模型（如 OpenAI text-embedding-ada-003、BGE、M3E）通过大规模预训练学习语义表示，使得：

  • 语义相似的文本 → 向量距离近
  • 语义不同的文本 → 向量距离远

向量维度通常为 384-dim（轻量模型）到 1536-dim（OpenAI）或 1024-dim（BGE）。

相似度计算：

常用的向量相似度度量方式：

  1. 余弦相似度（Cosine Similarity）：
    最常用，范围 [-1, 1]，只考虑方向不考虑大小。

  2. 欧氏距离（Euclidean Distance）：
    考虑绝对距离，适合需要严格距离度量的场景。

  3. 点积（Dot Product）：
    计算简单，但受向量长度影响。

import numpy as np

def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    """计算余弦相似度"""
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

def euclidean_distance(a: np.ndarray, b: np.ndarray) -> float:
    """计算欧氏距离"""
    return np.linalg.norm(a - b)

def top_k_similar(query_embedding: np.ndarray, 
                  memory_embeddings: np.ndarray,
                  k: int = 5) -> List[int]:
    """找到最相似的 Top-K 个向量"""
    similarities = np.dot(memory_embeddings, query_embedding)
    top_k_indices = np.argsort(similarities)[::-1][:k]
    return top_k_indices.tolist()

ANN 搜索原理：

当记忆数量达到百万级以上时，暴力计算所有相似度太慢。ANN（Approximate Nearest Neighbor）通过牺牲少量精度换取大幅速度提升。

常用 ANN 算法：

  1. HNSW（Hierarchical Navigable Small World）：

    • 构建多层图结构，上层稀疏、下层密集
    • 搜索时从顶层开始，逐层向下逼近最近邻
    • 优点：搜索速度快、支持动态增删
    • 缺点：内存占用较大

  2. IVF（Inverted File Index）：

    • 将向量空间聚类为多个簇（Voronoi 单元）
    • 搜索时先找到最近的几个簇，只在簇内搜索
    • 常与 PQ（Product Quantization）压缩结合

  3. PQ（Product Quantization）：

    • 将高维向量分割为子向量，分别量化
    • 大幅减少存储，适合亿级数据
# 使用 Faiss 构建 ANN 索引的简单示例
import faiss
import numpy as np

def build_ann_index(embeddings: np.ndarray, index_type="HNSW"):
    """构建 ANN 索引"""
    dim = embeddings.shape[1]
    
    if index_type == "HNSW":
        # HNSW 索引
        index = faiss.IndexHNSWFlat(dim, 32)  # 32 = M (邻居数)
        index.hnsw.efConstruction = 200
        index.add(embeddings)
    elif index_type == "IVF":
        # IVF 索引
        nlist = 100  # 簇数量
        quantizer = faiss.IndexFlatIP(dim)
        index = faiss.IndexIVFFlat(quantizer, dim, nlist)
        index.train(embeddings)
        index.add(embeddings)
    else:
        # 暴力搜索（小数据量）
        index = faiss.IndexFlatIP(dim)
        index.add(embeddings)
    
    return index

def ann_search(index, query_embedding: np.ndarray, k: int = 5):
    """ANN 检索"""
    scores, indices = index.search(query_embedding.reshape(1, -1), k)
    return indices[0], scores[0]

混合检索（Hybrid Search）：

实际工程中，纯向量检索可能不够精确，常结合关键词检索（BM25）：

def hybrid_search(query: str, vector_results, keyword_results, alpha=0.5):
    """
    alpha: 向量检索权重 (0-1)
    1-alpha: 关键词检索权重
    """
    # 归一化分数
    vector_scores = {doc: score for doc, score in vector_results}
    keyword_scores = {doc: score for doc, score in keyword_results}
    
    all_docs = set(vector_scores.keys()) | set(keyword_scores.keys())
    
    final_scores = {}
    for doc in all_docs:
        v_score = vector_scores.get(doc, 0)
        k_score = keyword_scores.get(doc, 0)
        final_scores[doc] = alpha * v_score + (1 - alpha) * k_score
    
    return sorted(final_scores.items(), key=lambda x: x[1], reverse=True)

2. 延伸追问

  • 追问 1：Embedding 模型怎么选型？答：根据语言（中文用 BGE-M3、M3E，英文用 OpenAI、E5）、维度限制、是否需要多模态综合考虑。
  • 追问 2：向量检索的召回率不够怎么办？答：增大 top-k、使用 Reranker（Cross-Encoder）做精排、使用多向量表示。
  • 追问 3：如何更新向量数据库中的已有记忆？答：删除旧向量后重新插入新向量；或者支持增量更新的向量数据库（如 Milvus 的 upsert）。

3. 常见误区

  • 误区 1：向量相似度等同于语义相关。实际上向量距离近只说明语义相似，不代表对当前查询有用。
  • 误区 2：ANN 索引不需要维护。实际上数据分布变化后需要重新训练索引。
  • 误区 3：只用向量检索就够了。实际上混合检索（向量+关键词）往往效果更好。
