问题

请解释 Function Calling（工具调用）的基本原理，包括它的核心流程和各角色的职责分工。

答案

Function Calling 是一套让大语言模型（LLM）以结构化方式调用外部工具（函数）的机制。它由 OpenAI 在 2023 年推出，目前 Claude、Gemini、Qwen 等主流模型都原生支持。

核心原理

Function Calling 的本质是 "模型决策、代码执行" 的分工机制：

  1. 开发者定义工具：用 JSON Schema 描述每个工具的名称、功能、参数类型和约束
  2. 模型判断意图：模型根据用户问题和工具描述，决定是否调用工具
  3. 模型输出结构化调用请求：生成包含 tool_calls 的 JSON，指定函数名和参数
  4. 应用程序执行工具：宿主代码解析 JSON，真正执行函数调用
  5. 结果返回模型：工具执行结果塞回对话，模型生成最终回答

完整流程（两轮对话模型）

第 1 轮：
  用户提问 + 工具定义 → LLM
  LLM → 输出 tool_calls（不直接回答）
  
应用层执行：
  解析 tool_calls → 执行真实函数 → 获取结果

第 2 轮：
  工具结果 → LLM
  LLM → 生成最终自然语言回答

三个核心角色

角色 职责 类比
开发者 编写工具 JSON Schema（"职位说明书"） HR
LLM 判断是否需要调工具，生成调用指令 经理
应用代码 真正执行函数、访问网络/数据库 员工

关键点：模型全程只输出结构化 JSON，不亲自执行任何代码，也没有直接访问网络的权限。

代码示例

import json
from openai import OpenAI

client = OpenAI()

# 1. 定义工具 Schema
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查询指定城市的实时天气，仅支持中国大陆城市",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {
                    "type": "string",
                    "description": "城市名称，如'北京''上海'，不要带省份前缀"
                },
                "unit": {
                    "type": "string",
                    "enum": ["celsius", "fahrenheit"],
                    "description": "温度单位，默认摄氏度"
                }
            },
            "required": ["city"]
        }
    }
}]

# 2. 第一轮：让模型决定调用什么工具
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "北京今天天气怎么样？"}],
    tools=tools,
    tool_choice="auto"
)

message = response.choices[0].message

# 3. 检查是否需要工具调用
if message.tool_calls:
    tool_call = message.tool_calls[0]
    function_name = tool_call.function.name
    arguments = json.loads(tool_call.function.arguments)
    print(f"模型请求调用: {function_name}({arguments})")
    
    # 4. 应用层执行真实函数（模拟）
    def get_weather(city: str, unit: str = "celsius"):
        return {"city": city, "temperature": 25, "condition": "晴"}
    
    result = get_weather(**arguments)
    
    # 5. 第二轮：将工具结果返回给模型
    final_response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "user", "content": "北京今天天气怎么样？"},
            {"role": "assistant", "content": None, "tool_calls": message.tool_calls},
            {"role": "tool", "tool_call_id": tool_call.id, "content": json.dumps(result)}
        ],
        tools=tools
    )
    print(final_response.choices[0].message.content)

延伸追问

Q: 模型真的会执行函数吗？
A: 不会。模型只生成结构化的 tool_calls JSON，真正的函数执行由应用层代码完成。这是面试中必须强调的核心设计。

Q: 如果工具描述写得不清晰会怎样？
A: 模型会"瞎猜"——传错误参数、选错工具、硬塞不匹配的输入。description 字段是模型判断的唯一依据，必须精确具体。

常见误区

  1. 误区：模型自己执行了函数。
    纠正：模型只输出 JSON，执行是应用层的事。

  2. 误区：Function Calling 和 Prompt 工程里的工具调用是一回事。
    纠正：Function Calling 是模型原生输出结构化 JSON；Prompt 工程靠解析自然语言，格式稳定性差很多。

  3. 误区：一次 Function Calling 就能完成复杂任务。
    纠正：复杂任务通常需要多轮工具调用，甚至并行调用多个工具。
