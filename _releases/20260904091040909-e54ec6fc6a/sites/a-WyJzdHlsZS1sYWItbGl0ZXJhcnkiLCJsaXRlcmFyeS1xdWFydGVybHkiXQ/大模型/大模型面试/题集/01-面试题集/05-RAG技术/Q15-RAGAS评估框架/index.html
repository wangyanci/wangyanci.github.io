## 问题
RAG 系统的评估指标体系是怎样的？RAGAS 框架的核心指标有哪些？如何构建测试集并实施评估？

## 答案

RAG 系统的评估需要**分层进行**，不能只看最终答案，要从检索层、生成层、端到端层分别评估。

**评估指标体系：**

┌─────────────────────────────────────────────────────────────────┐
│ RAG 评估分层体系 │
├────────────────────────┬────────────────────────────────────────┤
│ 检索层指标 │ 生成层指标 │
├────────────────────────┼────────────────────────────────────────┤
│ • Hit Rate@K │ • Faithfulness（忠实度） │
│ • Recall@K │ • Answer Relevancy（答案相关性） │
│ • Precision@K │ • Correctness（正确性） │
│ • MRR │ • Completeness（完整性） │
│ • NDCG@K │ • Harmfulness（有害性） │
├────────────────────────┴────────────────────────────────────────┤
│ 端到端层指标 │
├─────────────────────────────────────────────────────────────────┤
│ • 任务完成率 / 首问解决率 │
│ • 用户满意度 / 人工评分 │
│ • 延迟 (P50/P99) │
│ • 成本 (Token 消耗 / 调用次数) │
│ • 引用准确率 │
└─────────────────────────────────────────────────────────────────┘


**核心指标详解：**

**检索层指标：**

| 指标 | 说明 | 计算方式 |
|------|------|---------|
| **Hit Rate@K** | Top-K 中是否命中相关文档 | 命中的查询数 / 总查询数 |
| **Recall@K** | 相关文档被找回的比例 | 找回的相关文档 / 所有相关文档 |
| **Precision@K** | Top-K 中相关文档的比例 | 相关文档 / K |
| **MRR** | 第一个相关文档的排名倒数均值 | Σ(1/rank_i) / N |
| **NDCG@K** | 考虑分级相关性的排序质量 | 折扣累积增益的标准化版本 |

**生成层指标（RAGAS 核心）：**

| 指标 | 说明 | 关注点 |
|------|------|--------|
| **Faithfulness** | 忠实度：答案中的声明是否能被上下文支持 | 防幻觉最关键指标 |
| **Answer Relevancy** | 答案相关性：答案是否与问题匹配 | 防止答非所问 |
| **Context Precision** | 上下文精度：检索结果中信噪比 | 上下文是否干净 |
| **Context Recall** | 上下文召回率：回答所需信息是否被覆盖 | 是否漏检关键证据 |

**RAGAS 使用示例：**

```python
from ragas import evaluate
from ragas.metrics import (
    faithfulness,
    answer_relevancy,
    context_precision,
    context_recall,
    answer_correctness
)
from datasets import Dataset

# 准备测试数据（需要预先标注）
test_data = Dataset.from_dict({
    "question": ["什么是RAG？", "如何减少幻觉？"],
    "answer": ["RAG是检索增强生成...", "可以通过以下方式..."],
    "contexts": [
        ["RAG (Retrieval-Augmented Generation)..."],
        ["幻觉是LLM编造信息的问题..."]
    ],
    "ground_truth": ["RAG是检索增强生成技术", "使用RAG和Prompt约束"]
})

# 执行评估
result = evaluate(
    dataset=test_data,
    metrics=[
        faithfulness,
        answer_relevancy,
        context_precision,
        context_recall,
        answer_correctness
    ]
)

print(result)
# 输出示例：
# {'faithfulness': 0.85, 'answer_relevancy': 0.92, 
#  'context_precision': 0.78, 'context_recall': 0.88,
#  'answer_correctness': 0.82}

Faithfulness 的计算原理：

Step 1: 将答案拆分为独立的事实声明
  "RAG是检索增强生成技术，由Facebook在2020年提出"
  → ["RAG是检索增强生成技术", "RAG由Facebook在2020年提出"]

Step 2: 逐一验证每个声明是否被上下文支持
  "RAG是检索增强生成技术" → ✅ 有依据
  "RAG由Facebook在2020年提出" → ✅ 有依据

Step 3: 计算得分
  Faithfulness = 被支持的声明数 / 总声明数 = 2/2 = 1.0

测试集构建方法：

# 测试集构建流程
def build_test_set(documents, num_questions=100):
    """
    基于文档构建测试集
    """
    test_cases = []
    
    for doc in documents:
        # 使用 LLM 生成问题-答案对
        qa_pairs = llm.invoke(f"""

        问题应该覆盖文档的关键信息。

        输出格式（JSON）：
        [
          {{"question": "...", "answer": "...", "source": "..."}}
        ]
        """)
        
        test_cases.extend(qa_pairs)
    
    return test_cases

不同场景的评估侧重：

场景 优先指标 目标值
客服问答 Faithfulness, Answer Relevancy >0.85
知识检索 Context Recall, Hit Rate@K >0.90
内容生成 Correctness, Completeness >0.80

延伸追问

Q: 如果 Recall 高但 Faithfulness 低，说明什么问题？

A: 说明检索召回了很多文档，但引入了大量噪声。解决方案：1) 提高相似度阈值；2) 加 Rerank 层；3) 优化 Chunk 策略；4) 做上下文压缩。

Q: RAGAS 的评估依赖 LLM，如果 LLM 判断不准确怎么办？

A: 1) 使用更强的 LLM 做评估（如 GPT-4）；2) 对关键 Case 做人工抽检；3) 结合多个评估框架交叉验证。

常见误区

  1. 只看单一指标 — RAG 评估需要多维度综合判断
  2. 忽略检索层评估 — 只评估生成质量，不评估检索质量
  3. 测试集太小 — 至少 100+ 个测试用例才有统计意义
  4. 人工评估和自动评估二选一 — 最佳实践是自动评估初筛 + 人工抽检
