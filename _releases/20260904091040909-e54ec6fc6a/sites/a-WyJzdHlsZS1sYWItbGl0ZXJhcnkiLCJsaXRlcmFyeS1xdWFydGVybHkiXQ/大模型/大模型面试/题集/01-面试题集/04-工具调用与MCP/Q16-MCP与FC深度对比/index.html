MCP 与 Function Calling 的关系和区别（深度对比）

问题

从架构层面深入分析 MCP 和 Function Calling 的关系和区别。为什么有了 Function Calling 还需要 MCP？

答案

MCP 和 Function Calling 不是竞争关系，而是不同层面、协作配合的关系。深入理解二者的层级关系是面试考察的重点。

核心区别

维度 Function Calling MCP
本质 模型的一种原生能力 一套通信协议标准
关注点 模型如何表达"我要调用工具" 工具如何被标准化暴露给 AI 应用
层面 模型调用层 应用接入层
谁实现 模型提供商（OpenAI、Anthropic 等） 开发者搭建 Server，Host 连接
作用范围 模型 ↔ 调用方之间 AI 应用 ↔ 外部工具之间
类比 你会"打电话"这个技能 约定用"普通话"交流

一句话概括

Function Calling 是"决策层"，MCP 是"通信层"。

  • Function Calling：模型说"我要调用 get_weather，参数是 city='北京'"
  • MCP：标准化地把 get_weather 这个能力从 Server 暴露给 Host，让任何 AI 应用都能发现和使用

协作关系

用户提问
    ↓
AI 模型使用 Function Calling 能力 → 决定调用哪个工具、生成参数
    ↓
MCP Client 将调用转换为 MCP 协议格式
    ↓
MCP Server 接收请求，执行实际操作（查数据库、调 API 等）
    ↓
结果通过 MCP 返回给模型
    ↓
模型生成最终回答

形象比喻

  • Function Calling = 手（抓取工具的能力）
  • MCP = 标准化的工具把手/接口（USB-C）
  • A2A = 使用工具分工合作的团队（Agent 间协作）

实际系统中的配合方式

# 实际系统的工作流程示例
async def agent_with_mcp(user_query: str):
    # 1. MCP 发现工具（应用层）
    all_tools = []
    for server in mcp_servers:
        tools = await server.list_tools()
        all_tools.extend(tools)
    
    # 2. 将 MCP 工具转换为 Function Calling Schema（格式转换层）
    function_schemas = [
        {
            "type": "function",
            "function": {
                "name": t.name,
                "description": t.description,
                "parameters": t.inputSchema
            }
        }
        for t in all_tools
    ]
    
    # 3. Function Calling：模型决策调用哪个工具（模型层）
    response = await llm.chat.completions.create(
        messages=[{"role": "user", "content": user_query}],
        tools=function_schemas,
        tool_choice="auto"
    )
    
    # 4. MCP 执行工具调用（通信层）
    if response.choices[0].message.tool_calls:
        tool_call = response.choices[0].message.tool_calls[0]
        result = await mcp_client.call_tool(
            tool_call.function.name,
            json.loads(tool_call.function.arguments)
        )
        
        # 5. 结果返回模型，生成最终回答
        final = await llm.chat.completions.create(
            messages=[...],
        )
        return final.choices[0].message.content

OpenAI 官方对 MCP 的集成

OpenAI 在 Responses API 中直接支持 MCP Server 作为 type: "mcp" 的工具接入，说明业界趋势是将 MCP 作为工具来源，Function Calling 作为模型调用方式。

延伸追问

Q: 没有 MCP 之前怎么接入工具？
A: 开发者需要为每个工具手写桥接代码（胶水代码），每个 AI 应用都要单独适配每个工具。MCP 出现后，工具开发者实现一次 MCP Server，任何 MCP Host 都能自动发现和连接。

Q: 三者层级关系 Function Calling / MCP / Skill 怎么理解？
A: 从底到顶的三层架构：

  • Function Calling（底层调用语言）→ MCP（工具标准化接入）→ Skill（流程模板封装）
  • 类比：FC 是手，MCP 是 USB 接口，Skill 是"操作手册"

常见误区

  1. 误区：MCP 出来以后 Function Calling 被淘汰了。
    纠正：MCP 底层仍然依赖 Function Calling 作为模型的调用机制，二者是互补关系。

  2. 误区：MCP 和 Function Calling 是同一层面的竞争方案。
    纠正：一个是协议层（MCP），一个是模型能力层（FC），解决的问题完全不同。

  3. 误区：用了 MCP 就不需要写工具代码了。
    纠正：MCP 只解决连接和通信问题，工具的具体业务逻辑仍需开发者实现。
