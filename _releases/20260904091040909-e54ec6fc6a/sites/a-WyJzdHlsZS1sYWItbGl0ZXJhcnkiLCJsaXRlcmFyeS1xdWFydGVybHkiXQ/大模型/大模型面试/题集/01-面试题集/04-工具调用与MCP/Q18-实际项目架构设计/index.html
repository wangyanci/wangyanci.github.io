问题

在实际项目中，如何设计一套结合 Function Calling 和 MCP 的 Agent 工具调用架构？需要考虑哪些工程问题？

答案

在实际项目中，Function Calling 和 MCP 需要协同工作，构成"模型决策层 + 协议通信层 + 工具执行层"的三层架构。

关键工程考量

1. 工具路由层

class ToolRouter:
    """工具路由器：根据工具名称路由到对应的 MCP Client"""
    
    def __init__(self):
        self.clients: Dict[str, MCPClient] = {}
        self.tool_registry: Dict[str, str] = {}  # tool_name -> client_id
    
    def register_client(self, client_id: str, client: MCPClient):
        """注册 MCP Client 并发现其工具"""
        self.clients[client_id] = client
        tools = client.list_tools()
        for tool in tools:
            self.tool_registry[tool.name] = client_id
    
    async def route_tool_call(self, tool_name: str, arguments: dict):
        """路由工具调用到正确的 Client"""
        client_id = self.tool_registry.get(tool_name)
        if not client_id:
            raise ValueError(f"未找到工具 '{tool_name}' 的注册信息")
        
        client = self.clients[client_id]
        return await client.call_tool(tool_name, arguments)

2. Schema 转换层

class SchemaConverter:
    """将 MCP 工具定义转换为 Function Calling Schema"""
    
    @staticmethod
    def mcp_to_function_schema(mcp_tools: List[dict]) -> List[dict]:
        """MCP Tool Schema → Function Calling Schema"""
        return [
            {
                "type": "function",
                "function": {
                    "name": tool["name"],
                    "description": tool["description"],
                    "parameters": tool.get("inputSchema", {})
                }
            }
            for tool in mcp_tools
        ]
    
    @staticmethod
    def function_to_mcp_call(function_call: dict) -> dict:
        """Function Calling 输出 → MCP 工具调用"""
        return {
            "name": function_call["name"],
            "arguments": json.loads(function_call["arguments"])
        }

3. 安全执行层

class SecureToolExecutor:
    """安全工具执行器（完整实现）"""
    
    def __init__(self, router: ToolRouter, acl: ToolACL):
        self.router = router
        self.acl = acl
        self.audit_logger = AuditLogger()
        self.rate_limiter = RateLimiter()
    
    async def execute(self, user_id: str, tool_call: dict, context: dict):
        tool_name = tool_call["name"]
        
        # 1. 权限检查
        if not self.acl.can_execute(user_id, tool_name):
            raise PermissionError(f"无权调用工具 {tool_name}")
        
        # 2. 限流检查
        if not self.rate_limiter.allow(user_id, tool_name):
            raise RateLimitError("调用过于频繁，请稍后重试")
        
        # 3. 审计记录
        self.audit_logger.log_call(user_id, tool_call)
        
        # 4. 执行工具调用
        try:
            result = await self.router.route_tool_call(
                tool_name, 
                tool_call["arguments"]
            )
            self.audit_logger.log_success(user_id, tool_call, result)
            return result
        except Exception as e:
            self.audit_logger.log_failure(user_id, tool_call, str(e))
            raise

4. 会话状态管理

class SessionManager:
    """会话状态管理器"""
    
    def __init__(self, redis_client):
        self.redis = redis_client
        self.session_ttl = 3600  # 1小时过期
    
    async def get_session(self, session_id: str) -> dict:
        """获取会话状态"""
        data = await self.redis.get(f"session:{session_id}")
        if data:
            return json.loads(data)
        return {"messages": [], "tool_calls": [], "created_at": time.time()}
    
    async def update_session(self, session_id: str, session: dict):
        """更新会话状态"""
        await self.redis.setex(
            f"session:{session_id}",
            self.session_ttl,
            json.dumps(session)
        )
    
    async def add_tool_call(self, session_id: str, tool_call: dict, result: dict):
        """记录工具调用历史"""
        session = await self.get_session(session_id)
        session["tool_calls"].append({
            "tool": tool_call,
            "result": result,
            "timestamp": time.time()
        })
        await self.update_session(session_id, session)

延伸追问

Q: 如何处理 MCP Server 宕机的情况？
A: 实现健康检查 + 自动重连 + 熔断机制。Server 不可用时暂时从工具列表中移除，恢复后自动重新发现。

Q: 工具调用的性能瓶颈通常在哪？
A: 主要在三个环节：LLM 推理延迟（工具决策）、MCP 通信延迟（网络 IO）、工具执行延迟（数据库查询等）。应分别优化。

常见误区

  1. 误区：Function Calling 和 MCP 只需要简单拼接。
    纠正：中间需要 Schema 转换、路由、安全校验等多个环节。

  2. 误区：会话状态可以存在内存里。
    纠正：生产环境必须用 Redis 等外部存储，支持多实例部署和断点续传。

  3. 误区：所有工具走同一个超时设置。
    纠正：不同工具的执行时间差异很大，应该按工具类型设置不同超时。
