Plan-and-Execute vs ReAct

问题

对比 Plan-and-Execute 和 ReAct 两种 Agent 规划模式的区别，分析各自的优缺点和适用场景。在实际工程中如何设计混合架构？

答案

核心区别：

对比维度 ReAct Plan-and-Execute
核心思想 边思考边做，每步动态决策 先全局规划，再逐步执行
计划生成 无完整计划，走一步看一步 执行前生成完整步骤列表
灵活性 高，每步可根据观察调整 低，计划一旦生成按顺序执行
全局视角 可能跑偏，缺乏全局观 全局规划，步骤依赖清晰
Token 消耗 每步都重新思考，消耗高 规划一次执行多次，消耗低
适用场景 开放式探索、工具调用不确定 流程型任务、步骤有强依赖
长任务表现 容易迷失方向、重复调用 结构清晰，不易偏离

Plan-and-Execute 的执行流程：

输入任务 → Planner 生成完整计划 → 按步骤执行 → 观察结果 → Replan（如需）→ Final Answer
  1. 规划阶段：Planner（通常是强模型如 GPT-4）分析任务，生成完整的执行计划（步骤列表）
  2. 执行阶段：Executor 按顺序执行每个步骤，可以调用工具
  3. 重规划：如果执行中发现计划不合理，触发 Replanner 调整计划

各自适用场景：

ReAct 适合：

  • 短链路、动态决策任务（查订单、查天气）
  • 工具调用不确定，需要根据中间结果灵活调整
  • 用户意图可能在对话中变化（客服场景）
  • 需要实时反馈的交互式任务

Plan-and-Execute 适合：

  • 多步骤、长流程的复杂任务（数据分析报告、竞品分析）
  • 步骤之间有强先后依赖关系
  • 执行顺序基本固定的流程型任务
  • 需要预估资源消耗的任务

混合架构设计：

class HybridAgent:
    """混合架构：Plan-and-Execute 做全局规划，ReAct 做局部灵活执行"""
    
    def __init__(self, planner_llm, executor_llm, tools):
        self.planner = planner_llm   # 强模型做规划
        self.executor = executor_llm # 执行模型
        self.tools = tools
        self.replan_threshold = 0.5   # 重规划触发阈值
    
    def run(self, task: str) -> str:
        # 1. 全局规划
        plan = self._create_plan(task)
        print(f"Generated plan: {plan}")
        
        results = []
        for step_idx, step in enumerate(plan.steps):
            # 2. 每个步骤内部用 ReAct 灵活执行
            executor = ReActAgent(self.executor, self.tools, max_iterations=5)
            step_result = executor.run(step.description)
            results.append(step_result)
            
            # 3. 检查是否需要重规划
            if self._should_replan(step_result):
                remaining_task = f"已完成: {results}\n剩余任务: {plan.steps[step_idx+1:]}"
                plan = self._replanner(remaining_task, step_result)
                print(f"Replanned: {plan}")
        
        return self._synthesize_results(results)
    
    def _create_plan(self, task: str) -> Plan:
        prompt = f"""将以下任务分解为可执行的步骤计划：
任务: {task}
要求: 
- 每个步骤要具体、可执行
- 标明步骤之间的依赖关系
- 估计每个步骤的复杂度

请输出 JSON 格式的计划:"""
        
        response = self.planner.generate(prompt)
        return Plan.parse(response)
    
    def _should_replan(self, step_result: str) -> bool:
        """判断是否需要重规划"""
        # 工具调用失败、结果异常、偏离目标等情况
        error_indicators = ["error", "failed", "unable", "not found"]
        return any(indicator in step_result.lower() for indicator in error_indicators)
    
    def _replanner(self, context: str, failure_reason: str) -> Plan:
        """基于失败原因重新规划"""
        prompt = f"""原始计划执行遇到问题，请重新规划：
{context}
失败原因: {failure_reason}
请输出调整后的计划:"""
        return Plan.parse(self.planner.generate(prompt))

工程实践建议：

  1. 分层策略：简单查询（单步任务）走 ReAct 单次循环；复杂任务（多步骤）先用 Plan-and-Execute 生成粗粒度 Plan，每个步骤内部用 ReAct 执行
  2. Planner 选型：规划用强模型（如 GPT-4），执行可以用更快更便宜的模型（如 GPT-3.5）
  3. 重规划触发条件：工具调用失败、结果不符合预期、用户意图变化
  4. 监控指标：规划准确率、重规划频率、步骤成功率、端到端延迟

延伸追问

  • 追问 1：Plan-and-Execute 中的"规划谬误"怎么解决？答：规划中预留 buffer 步骤、设置重规划触发条件、使用更保守的复杂度估计。
  • 追问 2：如果执行中发现某步不可行怎么办？答：触发 Replanner，基于已完成的步骤和失败原因重新生成剩余计划。
  • 追问 3：多 Agent 场景下如何协调 Planning？答：可以使用 Master Agent 做全局规划，子 Agent 各自执行分配到的子任务。

常见误区

  • 误区 1：认为必须二选一。实际上混合架构往往效果最好。
  • 误区 2：Plan-and-Execute 中规划一次就不再调整。实际需要动态重规划能力。
  • 误区 3：忽视 Planner 和执行器的模型选型差异。规划需要强推理能力，执行可以更轻量。
