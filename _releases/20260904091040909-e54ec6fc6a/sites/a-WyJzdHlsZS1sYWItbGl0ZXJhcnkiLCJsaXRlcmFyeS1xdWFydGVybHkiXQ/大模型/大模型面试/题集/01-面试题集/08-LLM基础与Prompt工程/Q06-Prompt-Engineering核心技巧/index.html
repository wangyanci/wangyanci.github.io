Prompt Engineering 的核心技巧有哪些？

问题

Prompt Engineering 有哪些核心技巧？如何系统性地优化 Prompt？

答案

一、核心技巧矩阵

技巧 核心思想 适用场景 示例
零样本提示 直接下达清晰指令 简单任务 "用一句话解释量子计算"
少样本提示 (Few-shot) 提供范例让模型模仿 格式严格、专业任务 提供 2-3 个输入-输出对
思维链 (CoT) 要求展示推理步骤 数学、逻辑推理 "让我们一步步思考"
自洽性 多次推理投票选共识 减少随机错误 多次采样取最一致答案
思维树 (ToT) 多分支探索择优 创意、规划 "提出三种方案并评估"
反思机制 自我审查修正 高质量要求 "检查并改进你的回答"

二、Prompt 结构最佳实践

OPTIMAL_PROMPT_STRUCTURE = """
# 1. 角色定义（放在最前面 - Lost in the Middle 效应）
你是一位资深{role}，擅长{skills}。

# 2. 任务描述
请完成以下任务：{task_description}

# 3. 输入数据
## 用户问题
{user_query}

## 参考资料
{retrieved_context}

# 4. 约束条件（放在最后强化）
- 只能使用参考资料中的信息
- 不确定的内容说"无法确认"
- 回答控制在 200 字以内
- 输出 JSON 格式

# 5. 输出格式示例（Few-shot）
## 示例
输入：...
输出：{...}
"""

三、Lost in the Middle 效应

LLM 对上下文窗口中间位置的信息关注度最低，开头和结尾关注度高。

应对策略：

  • 核心指令放开头（System Prompt 最前面）
  • 关键约束放结尾
  • 避免在 Prompt 中间放关键信息

四、Prompt 评估方法

class PromptEvaluator:
    """工业级 Prompt 评估"""
    
    def evaluate(self, prompt: str, test_cases: list) -> dict:
        results = []
        for case in test_cases:
            output = llm.invoke(prompt.format(**case.input))
            results.append({
                "accuracy": self._score_accuracy(output, case.expected),
                "format_adherence": self._check_format(output, case.format),
                "token_count": self._count_tokens(output),
                "consistency": self._check_consistency(prompt, case.input)
            })
        
        return {
            "avg_accuracy": sum(r["accuracy"] for r in results) / len(results),
            "format_compliance": sum(r["format_adherence"] for r in results) / len(results),
            "avg_tokens": sum(r["token_count"] for r in results) / len(results)
        }
    
    def ab_test(self, prompt_a: str, prompt_b: str, test_cases: list) -> str:
        """A/B 对比两个 Prompt"""
        score_a = self.evaluate(prompt_a, test_cases)
        score_b = self.evaluate(prompt_b, test_cases)
        
        # 重点关注：哪些 case 从对变错（新问题）
        # 哪些 case 从错变对（修复了什么）
        return "A" if score_a["avg_accuracy"] > score_b["avg_accuracy"] else "B"

延伸追问

  • "Prompt 优化有什么陷阱？" — 在测试集上过拟合、忽视 token 成本、没有系统评估
  • "Few-shot 给多少个示例合适？" — 通常 2-4 个，质量比数量重要。要给正反例
