问题

Agent 的记忆系统中，当新信息与已有记忆冲突时如何处理？如何设计时间衰减机制避免记忆膨胀？

1. 答案

记忆冲突的处理：

记忆冲突发生在当新获取的信息与已有记忆矛盾时，比如：

  • 用户之前说"我喜欢React"，现在说"我改用Vue了"
  • 之前记录"产品价格为100元"，现在查到"价格为120元"

冲突处理原则：

  1. 时间戳优先：新信息优先（带时间戳）
  2. 用户确认权重高：用户明确修正的信息覆盖旧信息
  3. 保留历史版本：不删除旧记忆，标记为"过期"
  4. 一致性校验：定期检测冲突，提示人工确认
class MemoryConflictResolver:
    """记忆冲突解决器"""
    
    def __init__(self, llm):
        self.llm = llm
    
    def detect_conflict(self, new_memory: MemoryEntry, 
                        existing_memories: List[MemoryEntry]) -> List[MemoryEntry]:
        """检测与已有记忆的冲突"""
        conflicts = []
        for mem in existing_memories:
            # 语义相似度判断
            sim = cosine_similarity(new_memory.embedding, mem.embedding)
            if sim > 0.85:  # 相似度过高，可能是同一主题
                # 进一步检查是否矛盾
                if self._is_contradictory(new_memory.content, mem.content):
                    conflicts.append(mem)
        return conflicts
    
    def _is_contradictory(self, text1: str, text2: str) -> bool:
        """判断两段文本是否矛盾"""
        prompt = f"""判断以下两段信息是否矛盾，只回答 Yes 或 No：
信息1: {text1}
信息2: {text2}
是否矛盾？"""
        result = self.llm.generate(prompt, max_tokens=5)
        return "yes" in result.lower()
    
    def resolve_conflict(self, new_memory: MemoryEntry, 
                         conflicting: List[MemoryEntry]) -> Resolution:
        """解决冲突"""
        for old in conflicting:
            if old.source == "user_explicit":
                # 用户之前明确声明的，需要确认
                return Resolution(
                    action="confirm",
                    message=f"您之前说'{old.content}'，现在'{new_memory.content}'，请确认？"
                )
        
        # 默认：新信息覆盖旧信息，但保留旧版本
        return Resolution(
            action="update",
            updates=[(old, "archived") for old in conflicting],
            insert=new_memory
        )

时间衰减机制：

class MemoryDecayManager:
    """记忆衰减管理器"""
    
    def __init__(self):
        self.decay_config = {
            "event_memory": {"half_life_days": 7},    # 事件记忆：7天半衰期
            "task_memory": {"half_life_days": 30},     # 任务记忆：30天
            "user_profile": {"half_life_days": 365},   # 用户画像：1年
            "core_fact": {"half_life_days": None}      # 核心事实：不衰减
        }
    
    def compute_score(self, memory: MemoryEntry) -> float:
        """计算记忆当前的有效分数"""
        config = self.decay_config.get(memory.memory_type, {})
        half_life = config.get("half_life_days")
        
        if half_life is None:
            # 不衰减
            time_decay = 1.0
        else:
            # 艾宾浩斯衰减
            age_days = (time.time() - memory.timestamp) / 86400
            time_decay = 0.5 ** (age_days / half_life)
        
        # 访问频率提升
        freq_boost = 1 + 0.1 * memory.access_count
        
        # 重要性权重
        importance = memory.importance
        
        return importance * time_decay * freq_boost
    
    def should_archive(self, memory: MemoryEntry) -> bool:
        """判断是否应该归档"""
        score = self.compute_score(memory)
        return score < 0.1
    
    def cleanup(self, memories: List[MemoryEntry]) -> List[MemoryEntry]:
        """清理低价值记忆"""
        retained = []
        for mem in memories:
            if not self.should_archive(mem):
                retained.append(mem)
            else:
                self._archive(mem)  # 归档而非删除
        return retained
    
    def _archive(self, memory: MemoryEntry):
        """归档记忆"""
        # 移动到归档存储（低成本长期存储）
        archive_storage.save(memory)

多因子评分模型：

score = α × importance + β × recency + γ × frequency + δ × relevance

其中：
- importance: 初始重要度（由 LLM 或规则打分）
- recency: 时间衰减因子
- frequency: 访问频次加成
- relevance: 与当前查询的相关度

2. 延伸追问

  • 追问 1：用户说"我之前说的不对"怎么处理？答：找到之前相关记忆，标记为无效，更新为新信息。
  • 追问 2：衰减参数怎么调？答：根据业务场景设置半衰期，通过 A/B 测试找到最佳参数。
  • 追问 3：归档的记忆还能恢复吗？答：可以，归档是低成本存储，检索时可以扩展到归档层。

3. 常见误区

  • 误区 1：冲突时直接覆盖旧记忆。应该保留历史版本，标记过期而非删除。
  • 误区 2：所有记忆用同一种衰减参数。不同类型记忆应该有不同衰减速度。
  • 误区 3：衰减就是定时删除。衰减应该是分数降低→归档→可能的清理，不是直接删除。
