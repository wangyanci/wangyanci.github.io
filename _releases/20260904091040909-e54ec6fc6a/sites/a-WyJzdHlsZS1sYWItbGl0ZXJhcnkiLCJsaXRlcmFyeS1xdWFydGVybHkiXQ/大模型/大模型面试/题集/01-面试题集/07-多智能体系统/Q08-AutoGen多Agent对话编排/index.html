AutoGen的多Agent对话编排

问题

请深入分析AutoGen的多Agent对话编排机制，包括GroupChat的发言人选择策略、对话终止条件、人机协作模式，以及其在企业场景中的应用边界。

答案

AutoGen的多Agent对话编排核心

AutoGen的多Agent协作基于对话驱动的设计理念，核心组件包括GroupChat（群聊环境）和GroupChatManager（调度器）。

1. GroupChatManager的发言人选择机制

GroupChatManager决定"下一个谁说话"，支持多种策略：

策略 工作原理 适用场景
auto LLM读取对话历史，返回下一个发言Agent的名字 动态讨论、需要智能调度
round_robin 按固定顺序轮询每个Agent 平等参与、确保每个Agent都发言
random 随机选择下一个发言人 头脑风暴、打破固定模式
manual 人工指定下一个发言人 人工控制讨论走向
custom 用户自定义选择函数 特殊业务逻辑

auto策略的内部实现：

# AutoGen GroupChatManager的发言人选择（简化）
class GroupChatManager:
    def select_speaker(self, last_speaker, groupchat):
        # 构建选择Prompt
        speaker_selection_prompt = f"""
        你是一个讨论主持人，负责选择下一个发言的人。

        可选参与者：{[agent.name for agent in groupchat.agents]}
        讨论历史：{groupchat.messages}

        请根据讨论内容，选择下一个最合适的发言人。
        只返回人名，不要解释。
        """

        # 调用LLM选择
        response = self.llm.create(
            messages=[{"role": "system", "content": speaker_selection_prompt}]
        )
        next_speaker_name = response.content.strip()

        # 返回对应的Agent
        return next(
            agent for agent in groupchat.agents
            if agent.name == next_speaker_name
        )

2. 对话终止条件

# AutoGen的终止条件配置
termination = {
    "max_round": 10,           # 最大对话轮数
    "termination_message": {    # 终止触发词
        "角色": ["总结者"],
        "关键词": ["总结", "结论", "TERMINATE"]
    },
    "is_termination_msg": lambda msg: "TERMINATE" in msg.get("content", "")
}

3. 人机协作（Human-in-the-loop）模式

AutoGen原生支持三种人机协作模式：

模式 说明 配置方式
ALWAYS 每轮对话后都征求人工输入 human_input_mode="ALWAYS"
TERMINAL 仅在Agent请求时暂停等待人工 human_input_mode="TERMINAL"
NEVER 完全自动运行 human_input_mode="NEVER"

代码示例：企业级代码审查系统

from autogen import AssistantAgent, UserProxyAgent, GroupChat, GroupChatManager

# 代码审查Agent团队
code_reviewer = AssistantAgent(
    name="代码审查员",
    system_message="你负责检查代码规范、逻辑正确性和最佳实践。"
                   "发现问题时提出具体修改建议。"
                   "审查完成后回复'APPROVED'或'REVIEW_COMPLETE'。",
    llm_config={"config_list": config_list, "temperature": 0.3}
)

security_expert = AssistantAgent(
    name="安全专家",
    system_message="你负责检查安全漏洞（SQL注入、XSS、CSRF等）。"
                   "发现安全问题立即标记为BLOCKER。",
    llm_config={"config_list": config_list, "temperature": 0.2}
)

performance_expert = AssistantAgent(
    name="性能专家",
    system_message="你检查性能瓶颈（N+1查询、内存泄漏、算法复杂度）。"
                   "标记性能问题并给出优化建议。",
    llm_config={"config_list": config_list, "temperature": 0.3}
)

# 人类开发者（关键决策点介入）
human_developer = UserProxyAgent(
    name="开发者",
    system_message="你是代码提交者。在审查通过后确认合并，"
                   "或在有争议时做出最终决定。",
    human_input_mode="TERMINAL",  # 关键节点人工介入
    max_consecutive_auto_reply=5
)

# 配置群聊
groupchat = GroupChat(
    agents=[code_reviewer, security_expert, performance_expert, human_developer],
    messages=[],
    max_round=8,
    speaker_selection_method="auto",
    allow_repeat_speaker=False  # 不允许连续发言
)

manager = GroupChatManager(groupchat=groupchat, llm_config=llm_config)

# 启动审查
human_developer.initiate_chat(
    manager,
    message="请审查以下代码：[代码内容]"
)

AutoGen在企业场景中的边界：

优势 局限
对话驱动，符合人类直觉 Token消耗高（多Agent×多轮次）
原生支持人机协作 对话可能偏离主题
灵活的群聊机制 缺乏持久化（需外部实现）
代码执行能力（UserProxyAgent） 大规模并行能力有限
微软生态集成 学习曲线较陡

延伸追问

  • 追问1：GroupChat的auto策略在选择发言人时可能有什么问题？
    • 答：LLM可能选择不合适的发言人（如刚发过言的Agent）；在讨论偏题时无法有效纠正；Token消耗随对话历史增长而增加。可以通过allow_repeat_speaker=False和自定义选择函数优化。
  • 追问2：AutoGen v0.4的重大变化是什么？
    • 答：v0.4进行了全面重构，核心变化包括：新的异步架构、改进的健壮性（指标提升300%）、更好的可观测性支持、A2A协议兼容。

常见误区

  • 误区：AutoGen适合所有多Agent协作场景。
  • 纠正：AutoGen的对话驱动模式适合讨论型、创意型任务，但不适合严格流程控制、低延迟响应、大规模并发的场景。在这些场景下，LangGraph或CrewAI可能更合适。
