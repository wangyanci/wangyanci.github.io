MCP（Model Context Protocol）协议是什么？

问题

什么是 MCP（Model Context Protocol）协议？请解释它的核心概念、架构组件和设计目标。

答案

MCP（Model Context Protocol，模型上下文协议）是由 Anthropic 于 2024 年推出的开放协议，用于标准化 AI 应用与外部工具、数据源和提示模板之间的连接。

核心定位

MCP 类比为 AI 世界的 USB-C 接口：

  • 就像 USB-C 统一了各种设备的充电和数据连接
  • MCP 统一了 AI 应用与外部工具、数据库、API 的连接方式

核心架构（Host-Client-Server 三层模型）

┌─────────────────────────────────────────────────────┐
│                    MCP Host                         │
│  (AI 应用：Claude Desktop、Cursor、IDE 等)           │
│                                                     │
│  ┌──────────────┐    ┌──────────────┐              │
│  │  MCP Client 1 │    │  MCP Client 2 │              │
│  │ (连接Server 1)│    │ (连接Server 2)│              │
│  └──────┬───────┘    └──────┬───────┘              │
└─────────┼──────────────────┼──────────────────────┘
          │                  │
    ┌─────▼─────┐     ┌─────▼─────┐
    │ MCP Server │     │ MCP Server │
    │  (文件系统) │     │  (数据库)  │
    └────────────┘     └────────────┘

三个核心角色

角色 职责 示例
Host AI 应用本身，负责用户交互、模型调用、权限和上下文聚合 Claude Desktop、Cursor、ChatGPT
Client Host 内部连接某个 Server 的组件，维护连接、处理请求/响应 SDK 中的 Client 实例
Server 暴露工具(Tools)、资源(Resources)、提示(Prompts)的服务端 文件系统 Server、数据库 Server

一个 Host 可以有多个 Client，每个 Client 通常对应一个 Server。

Server 暴露的三类能力

能力类型 英文 说明 类比
工具 Tools 模型可以主动调用的动作（查数据库、发消息、调 API） "做什么"
资源 Resources 只读的上下文数据（文件内容、数据库 schema、API 文档） "看什么"
提示 Prompts 可复用的提示模板，指导模型按流程使用工具和资源 "怎么做"

通信协议

MCP 基于 JSON-RPC 2.0 进行通信，传输层支持多种方式：

传输方式 适用场景 特点
stdio 本地进程通信 极低延迟、高安全性、仅限本地
SSE (HTTP) 远程通信（逐步淘汰） 支持多客户端、长连接
Streamable HTTP 云原生/分布式（推荐） 基于 HTTP/2/3、支持多路复用

设计目标

  1. 标准化工具接入：一次定义，多处使用
  2. 跨平台复用：同个 MCP Server 可被 Claude、Cursor、LangChain 等任何兼容平台使用
  3. 解耦：将"工具怎么被 AI 使用"和"工具怎么被实现"彻底解耦
  4. 安全可控：内置权限控制、会话隔离、审计日志

代码示例：MCP Server 最简实现

# server.py - 一个简单的 MCP Server（文件系统工具）
from mcp.server.fastmcp import FastMCP

# 创建 MCP Server 实例
mcp = FastMCP("filesystem-server")

# 定义一个 Tool
@mcp.tool()
async def read_file(path: str) -> str:
    """读取指定路径的文件内容。仅支持读取文本文件。"""
    with open(path, 'r', encoding='utf-8') as f:
        return f.read()

# 定义一个 Resource
@mcp.resource("file://{path}")
def get_file_content(path: str) -> str:
    """将文件内容作为资源暴露"""
    with open(path, 'r', encoding='utf-8') as f:
        return f.read()

if __name__ == "__main__":
    mcp.run(transport="stdio")

# client.py - MCP Client 连接并使用 Server
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

# 配置 Server 启动参数
server_params = StdioServerParameters(
    command="python",
    args=["server.py"],
    env=None
)

async def use_mcp():
    async with stdio_client(server_params) as (read, write):
        async with ClientSession(read, write) as session:
            # 初始化连接
            await session.initialize()
            
            # 发现可用工具
            tools = await session.list_tools()
            print(f"可用工具: {[t.name for t in tools.tools]}")
            
            # 调用工具
            result = await session.call_tool("read_file", {"path": "test.txt"})
            print(f"结果: {result}")

延伸追问

Q: MCP 和 Function Calling 有什么关系？
A: MCP 不是 Function Calling 的替代品。Function Calling 是模型侧的调用格式（模型输出 tool_calls），MCP 是应用侧的工具接入协议（标准化发现、连接、调用工具）。实际系统中，MCP 提供工具来源，Function Calling 是模型选择和调用工具的方式，二者配合使用。

Q: MCP Server 怎么被 LLM 用到？
A: Host 通过 MCP Client 获取 Server 的工具列表，将工具描述转换成模型支持的 Function Calling / Tool Use 格式，然后让模型决定调用哪个工具。

常见误区

  1. 误区：MCP 是 Function Calling 的升级版/替代品。
    纠正：二者解决不同层面的问题。Function Calling 关注模型怎么调用工具，MCP 关注工具怎么标准化接入 AI 应用。

  2. 误区：MCP 只支持本地工具。
    纠正：MCP 支持 stdio（本地）和 HTTP/SSE（远程）多种传输方式。

  3. 误区：MCP 是 Anthropic 独占的技术。
    纠正：MCP 是开放协议，任何 AI 应用都可以实现 Host/Client/Server。
