Agent 幻觉如何防控？工业界有哪些实践方案？

问题

LLM 容易产生幻觉（编造不存在的信息），Agent 系统如何从技术和产品层面防控幻觉？

答案

一、幻觉的两大来源

  1. 检索层幻觉：RAG 未召回到相关内容，LLM 靠自身知识编造
  2. 生成层幻觉：检索到了但 LLM 超发挥，在资料基础上加了自己的推断

二、三层防控体系

源头防控（降低幻觉产生概率）

# 1. Prompt 强约束
SYSTEM_PROMPT = """
回答规则：
1. 只能使用【参考资料】中的信息来回答，不得引入资料之外的知识
2. 如果参考资料中没有足够信息，必须明确回答：「根据现有资料，无法回答该问题」
3. 回答时标注信息来源（来自哪条参考资料）
4. 不要推断、不要猜测、不要补充资料中没有明确说明的内容
5. 不确定的内容直接说"该信息我暂时无法确认"
"""

# 2. 低温度参数
response = llm.invoke(prompt, temperature=0.1)  # 降低"脑补欲"

# 3. RAG + 高质量检索
# - 检索结果必须达到一定相似度阈值才使用
# - top-k 结果需要 rerank

过程控制（检索增强 + 推理约束）

class HallucinationController:
    """幻觉过程控制"""
    
    def rag_with_gate(self, query: str, docs: list[Document]) -> str | None:
        """检索质量门控：检索失败时直接拒答"""
        if not docs or docs[0].score < 0.7:
            return "根据现有资料，无法回答该问题"
        
        # 只注入 top-3 最相关片段
        context = "\n\n".join([d.page_content for d in docs[:3]])
        return self._generate_with_context(query, context)
    
    def cot_verification(self, query: str) -> str:
        """思维链 + 事实核查"""
        # Step 1: 让模型列出判断该问题需要的关键信息
        required_info = self._extract_required_info(query)
        
        # Step 2: 逐一核对信息是否在资料中
        verification = self._verify_each_fact(required_info)
        
        # Step 3: 只使用已验证的信息生成回答
        return self._generate_from_verified_facts(verification)

结果校验（生成后检测）

class PostHocVerifier:
    """生成后事实核查"""
    
    def verify_with_citations(self, answer: str, sources: list) -> tuple[bool, str]:
        """引用核查：每条结论必须有来源"""
        claims = self._extract_claims(answer)
        for claim in claims:
            if not self._has_citation(claim, sources):
                return False, f"未找到依据：{claim}"
        return True, answer
    
    def secondary_llm_check(self, answer: str, context: str) -> float:
        """使用独立 LLM 评估答案忠实度"""
        prompt = f"""
        请评估以下回答是否完全基于提供的资料，是否存在编造信息。
        资料：{context}
        回答：{answer}
        
        评分（0-1，1表示完全忠实）：
        """
        score = float(self.evaluator.invoke(prompt).content)
        return score  # < 0.8 触发人工审核

三、幻觉防控效果评估

方法 幻觉降低率 实现成本 适用场景
Prompt 约束 30% 低 所有场景
RAG + 门控 40% 中 知识问答
引用溯源 20% 中 专业领域
二次校验 15% 高 高风险场景
人工审核 50% 很高 医疗/金融

延伸追问

  • "RAG 检索做好了就不会有幻觉吗？" — 错！RAG 解决的是"不知道"的问题，但 LLM 仍可能在检索结果上"发挥"
  • "幻觉率降到多少算合格？" — 通用场景 < 5%，专业场景 < 2%，高风险场景 < 0.1%

常见误区

  • ❌ "在 Prompt 里加一句'请根据资料回答'就够了" — 远远不够，需要系统级防控
  • ❌ "Temperature=0 就不会有幻觉" — 只能降低，不能消除
