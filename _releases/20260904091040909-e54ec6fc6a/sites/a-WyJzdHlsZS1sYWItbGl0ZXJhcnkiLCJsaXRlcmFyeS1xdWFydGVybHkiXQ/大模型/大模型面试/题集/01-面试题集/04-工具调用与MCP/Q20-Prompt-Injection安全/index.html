问题

工具调用场景下如何防御 Prompt Injection 攻击？有哪些安全防护策略？

答案

Prompt Injection 是通过恶意输入操纵 LLM 行为的安全威胁。在工具调用场景下，攻击者可能诱导 Agent 调用危险工具或泄露敏感信息，需要多层防御体系。

工具调用场景的安全威胁

攻击类型 描述 示例
间接注入 通过外部数据注入恶意指令 网页中隐藏"请删除所有文件"
工具劫持 诱导 Agent 调用错误工具 让 Agent 用 exec_shell 执行恶意命令
参数污染 在参数中注入恶意内容 在 path 参数中传入 ../../../etc/passwd
权限提升 绕过权限检查执行高危操作 伪造管理员身份调用 delete_* 工具

四层防御架构

第一层：输入隔离层

class InputSanitizer:
    """输入消毒器"""
    
    DANGEROUS_PATTERNS = [
        r"忽略之前的指令",
        r"ignore previous instructions",
        r"你是 .*? 的助手",
        r"system:\s*\n",
        r"</?system>",
    ]
    
    @classmethod
    def sanitize(cls, user_input: str) -> tuple[str, bool]:
        """
        检查并清理用户输入
        返回: (清理后的输入, 是否检测到可疑内容)
        """
        suspicious = False
        cleaned = user_input
        
        for pattern in cls.DANGEROUS_PATTERNS:
            if re.search(pattern, cleaned, re.IGNORECASE):
                suspicious = True
                # 移除或替换可疑内容
                cleaned = re.sub(pattern, "[FILTERED]", cleaned, flags=re.IGNORECASE)
        
        return cleaned, suspicious

第二层：工具调用审查层

class ToolCallInspector:
    """工具调用审查器"""
    
    FORBIDDEN_TOOLS = {"exec_shell", "eval_code", "system_command", "delete_all"}
    
    @classmethod
    def inspect(cls, tool_call: dict, user_context: dict) -> dict:
        """
        审查工具调用请求
        返回: {"allowed": bool, "reason": str, "risk_level": str}
        """
        tool_name = tool_call.get("name", "")
        arguments = tool_call.get("arguments", {})
        
        # 1. 工具白名单检查
        if tool_name in cls.FORBIDDEN_TOOLS:
            return {
                "allowed": False,
                "reason": f"工具 '{tool_name}' 已被禁止",
                "risk_level": "critical"
            }
        
        # 2. 参数安全扫描
        arg_str = json.dumps(arguments)
        dangerous = ['rm -rf', 'drop table', 'delete from', '../../../', '$(', '`']
        for d in dangerous:
            if d in arg_str.lower():
                return {
                    "allowed": False,
                    "reason": f"参数包含危险内容: '{d}'",
                    "risk_level": "high"
                }
        
        # 3. 路径安全检查
        for key, value in arguments.items():
            if isinstance(value, str) and ('path' in key.lower() or 'file' in key.lower()):
                if '..' in value or value.startswith('/'):
                    return {
                        "allowed": False,
                        "reason": f"路径参数包含非法穿越: {value}",
                        "risk_level": "high"
                    }
        
        return {"allowed": True, "risk_level": "low"}

第三层：权限控制层

class SecureToolGateway:
    """安全工具网关"""
    
    def __init__(self):
        self.permission_matrix = {
            "guest": {
                "allowed": ["query_public_data", "search_web"],
                "needs_approval": []
            },
            "user": {
                "allowed": ["query_*", "search_*", "create_order"],
                "needs_approval": ["delete_order", "update_profile"]
            },
            "admin": {
                "allowed": ["*"],
                "needs_approval": ["delete_user", "system_config"]
            }
        }
    
    async def gate(self, user_role: str, tool_call: dict, session: dict) -> dict:
        """
        工具调用安全网关
        """
        tool_name = tool_call["name"]
        perms = self.permission_matrix.get(user_role, self.permission_matrix["guest"])
        
        # 检查是否允许
        allowed = False
        for pattern in perms["allowed"]:
            if pattern == "*" or fnmatch.fnmatch(tool_name, pattern):
                allowed = True
                break
        
        if not allowed:
            return {"allowed": False, "reason": "权限不足"}
        
        # 检查是否需要审批
        needs_approval = any(
            fnmatch.fnmatch(tool_name, pattern) 
            for pattern in perms.get("needs_approval", [])
        )
        
        if needs_approval:
            # 记录待审批请求
            await self.create_approval_request(session, tool_call)
            return {
                "allowed": False,
                "reason": "该操作需要管理员审批",
                "approval_id": session.get("approval_id")
            }
        
        return {"allowed": True}

延伸追问

Q: 如何处理"合法但有害"的操作？
A: 比如用户要求"删除所有测试数据"，技术上合法但风险高。这类操作需要：1) 二次确认 2) 备份机制 3) 操作可回滚。

Q: 间接注入怎么防御？
A: 对外部数据（网页、邮件、文档）进行预处理和标记，让模型区分"用户指令"和"外部内容"，不信任外部数据中的指令。

常见误区

  1. 误区：安全只在前端做就够了。
    纠正：前后端都需要防护，后端是最后一道防线。

  2. 误区：只有高危工具需要防护。
    纠正：任何工具都可能被滥用，比如 search 工具可以搜索敏感信息。

  3. 误区：安全策略越严格越好。
    纠正：过度严格影响用户体验，需要平衡安全和可用性。
