问题

在设计和实现 Agent 系统时，有哪些最佳实践？常见的陷阱有哪些？请结合实际工程经验给出建议。

1. 答案

Agent 设计的十大最佳实践：

1. 从小处着手（Start Small）

# 不要一上来就构建复杂系统
# Phase 1: 先做一个能用的单工具 Agent
phase1_agent = ReActAgent(tools=[search_tool])

# Phase 2: 添加记忆
phase2_agent = ReActAgent(tools=[search_tool], memory=ShortTermMemory())

# Phase 3: 增加规划能力
phase3_agent = PlanAndExecuteAgent(tools=[search_tool, calc_tool], 
                                   memory=TieredMemory())

# Phase 4: 生产级（状态机 + 监控 + 安全）
phase4_agent = ProductionAgent(
    state_machine=True, monitoring=True, security_policy=strict
)

2. 工具描述要精确简洁

# 不好的工具描述
bad_description = "搜索工具，可以搜索各种东西"

# 好的工具描述
good_description = """
search_web: 使用 Google 搜索网页信息
参数:
  - query (string, required): 搜索关键词，建议 3-10 个词
返回:
  - 搜索结果列表，每条包含标题、摘要、URL
注意事项:
  - 适用于查找事实性信息
  - 不适用于数学计算（请使用 calculator 工具）
"""

3. 提供 Few-shot 示例

FEW_SHOT_PROMPT = """

{user_input}

4. 实现完善的错误处理

class RobustToolExecutor:
    """健壮的工具执行器"""
    
    async def execute_with_retry(self, tool, params, max_retries=3):
        """带重试的工具执行"""
        for attempt in range(max_retries):
            try:
                result = await tool.run(**params)
                return ToolResult.success(result)
            except RateLimitError:
                # 指数退避
                wait = 2 ** attempt
                await asyncio.sleep(wait)
            except ToolNotFoundError:
                # 不可恢复错误
                return ToolResult.error(f"工具不存在: {tool.name}")
            except Exception as e:
                if attempt == max_retries - 1:
                    return ToolResult.error(str(e))
        
        return ToolResult.error("达到最大重试次数")

5. 设置安全边界（Guardrails）

class SafetyGuardrails:
    """安全边界"""
    
    DANGEROUS_PATTERNS = [
        r"rm\s+-rf\s+/",           # 删除文件系统
        r"DROP\s+TABLE",           # 删除数据库
        r"<script>.*</script>",    # XSS 攻击
    ]
    
    SENSITIVE_TOOLS = ["send_money", "delete_data", "grant_access"]
    
    def check_input(self, user_input: str) -> SafetyCheck:
        """检查用户输入"""
        for pattern in self.DANGEROUS_PATTERNS:
            if re.search(pattern, user_input, re.IGNORECASE):
                return SafetyCheck.blocked(f"检测到危险模式: {pattern}")
        return SafetyCheck.safe()
    
    def check_tool_call(self, tool_name: str, params: dict, 
                        user: User) -> SafetyCheck:
        """检查工具调用"""
        if tool_name in self.SENSITIVE_TOOLS:
            if not user.has_permission(f"tool.{tool_name}"):
                return SafetyCheck.blocked("权限不足")
            
            # 敏感操作需要二次确认
            return SafetyCheck.requires_confirmation(
                f"确认执行 {tool_name}({params})?"
            )
        return SafetyCheck.safe()

class ObservableAgent:
    """可观测的 Agent"""
    
    async def run(self, user_input: str) -> str:
        trace_id = generate_trace_id()
        
        with self.tracer.start_span("agent_run", trace_id) as span:
            span.set_attribute("user_input", user_input)
            
            try:
                # 记录每个步骤
                for step in self.execute(user_input):
                    self.logger.info(f"Step {step.number}", 
                                   extra={"trace_id": trace_id, 
                                          "thought": step.thought,
                                          "action": step.action,
                                          "observation": step.observation})
                    
                    # 发送指标
                    self.metrics.record_step(step)
                
            except Exception as e:
                self.logger.error(f"Agent error: {e}", 
                                extra={"trace_id": trace_id})

7. 设计 Human-in-the-loop

class HumanInTheLoop:
    """人机协作机制"""
    
    CONFIDENCE_THRESHOLD = 0.7
    
    def should_ask_human(self, decision: Decision) -> bool:
        """判断是否需要人工确认"""
        # 低置信度
        if decision.confidence < self.CONFIDENCE_THRESHOLD:
            return True
        
        # 高成本操作
        if decision.estimated_cost > 100:
            return True
        
        # 敏感操作
        if decision.involves_sensitive_data:
            return True
        
        # 不可逆操作
        if decision.is_irreversible:
            return True
        
        return False

常见陷阱与避坑指南：

陷阱 描述 解决方案
过度设计 一上来就搞多 Agent、复杂编排 从单 Agent 开始，逐步迭代
工具过多 一次暴露太多工具给 LLM 每次最多 8 个工具，动态加载
忽视安全 没有输入校验和权限控制 沙箱执行、权限检查、审计日志
忽略成本 不注意 Token 消耗 设置预算上限、监控每任务成本
缺乏监控 上线后不知道运行状况 完善的日志、指标、告警
Prompt 脆弱 Prompt 对模型版本敏感 多模型测试、Prompt 版本管理
无降级方案 工具失败就整体失败 设计 fallback 策略、优雅降级
忽视用户体验 响应慢、不可解释 流式输出、显示思考过程

2. 延伸追问

  1. 追问：Agent 系统的最大技术难点是什么？

    • 答：可控性 vs 自主性的平衡。太可控则不够智能，太自主则不安全。解决方案：分层的权限设计、渐进式授权、关键操作人工确认。

  2. 追问：如何保证 Agent 系统在不同 LLM 模型间的迁移性？

    • 答：①抽象 LLM 接口 ②Prompt 模板化管理 ③针对不同模型做适配层 ④统一的功能测试覆盖

3. 常见误区

  • 误区：Agent 可以完全替代人工
  • 纠正：当前 Agent 适合处理明确边界内的任务，复杂决策、创意工作和情感交互仍需人类参与。Agent 是"辅助"而非"替代"
