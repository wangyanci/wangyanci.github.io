多Agent协作模式（层级、平等、竞争）

问题

请详细说明多智能体系统中常见的协作模式，包括层级式、平等式、竞争式等，并分析各自的优缺点和适用场景。

答案

三大协作模式详解

多智能体系统的协作模式描述"谁说了算、信息怎么流、何时并行/串行"。

1. 中心化/层级模式（Hierarchical / Boss-Worker）

        ┌───────────┐
        │  Manager  │  任务分解、分配、汇总
        │ (调度者)   │
        └─────┬─────┘
              │ 委派任务
    ┌─────────┼─────────┐
    ▼         ▼         ▼
┌───────┐ ┌───────┐ ┌───────┐
│Agent A│ │Agent B│ │Agent C│  执行具体任务
│(研究员)│ │(分析师)│ │(作家) │
└───────┘ └───────┘ └───────┘
  • 结构：一个Planner/Manager负责任务分解、分配与汇总；多个Worker执行子任务
  • 优点：决策路径清晰，易做权限与审计，Manager可统一批准工具调用
  • 缺点：Manager成为瓶颈和单点故障，若规划错误会放大到全局
  • 适用：项目管理、软件研发流水线、需要统一控制的场景
  • 代表：CrewAI的Hierarchical Process、Google ADK三层架构

2. 流水线模式（Pipeline / Sequential）

┌───────┐    ┌───────┐    ┌───────┐    ┌───────┐
│Agent A│───→│Agent B│───→│Agent C│───→│Agent D│
│(需求)  │    │(开发)  │    │(测试)  │    │(部署)  │
└───────┘    └───────┘    └───────┘    └───────┘
 上游输出作为下游输入
  • 结构：Agent A → B → C，上游输出作为下游输入，可加质检环
  • 优点：适合文档/数据处理、固定SOP，易测试每段I/O
  • 缺点：错误逐级传递，难以处理需要"回到第一步重想"的大改动
  • 适用：内容创作流水线、数据ETL、CI/CD流程
  • 代表：CrewAI的Sequential Process

3. 民主讨论/辩论模式（Debate & Consensus）

┌─────────┐    辩论    ┌─────────┐
│ Agent A │ ←──────→ │ Agent B │
│ (正方)  │          │ (反方)  │
└────┬────┘          └────┬────┘
     │                    │
     └────────┬───────────┘
              ▼
        ┌───────────┐
        │  Agent C  │  裁决
        │  (裁判)    │
        └───────────┘
  • 结构：多个对等Agent多轮发言，由协调者负责流程而非内容独裁
  • 优点：适合头脑风暴、策略博弈、多角度审稿，能消除单一视角偏见
  • 缺点：易空转与重复，若无终止条件会Token爆炸，需要投票/仲裁机制
  • 适用：创意生成、方案评审、事实核查、伦理判断
  • 代表：AutoGen的GroupChat、Multi-Agent Debate框架

三种模式对比：

维度 层级模式 流水线模式 辩论模式
通信方式 星型（上下级） 线性（相邻） 网状（全连接）
决策速度 快（自上而下） 中（顺序执行） 慢（多轮讨论）
容错性 低（单点故障） 中（逐级影响） 高（冗余观点）
创新性 低 中 高
Token消耗 中 低 高

代码示例：辩论模式实现

# 辩论模式：多角度方案评审
from autogen import AssistantAgent, GroupChat, GroupChatManager

# 正方Agent
pro_agent = AssistantAgent(
    name="方案支持者",
    system_message="你支持采用微服务架构，请从技术角度论证优势。"
)

# 反方Agent
con_agent = AssistantAgent(
    name="方案反对者",
    system_message="你认为单体架构更合适，请从成本和维护角度论证。"
)

# 裁判Agent
judge_agent = AssistantAgent(
    name="技术总监",
    system_message="你听取双方意见后，综合技术、成本、团队能力做出最终决策。"
)

# 配置群聊辩论
groupchat = GroupChat(
    agents=[pro_agent, con_agent, judge_agent],
    messages=[],
    max_round=6,
    speaker_selection_method="round_robin"  # 轮流发言
)

manager = GroupChatManager(groupchat=groupchat)
# 发起辩论
debate_result = manager.initiate_chat(
    manager,
    message="我们需要为新产品选择技术架构，请从各自角度论证。"
)

延伸追问

  • 追问1：这三种模式可以混合使用吗？给出一个混合使用的场景。
    • 答：可以。例如软件开发流程：整体用层级模式（项目经理协调），开发阶段内部用流水线模式（需求→开发→测试），技术选型阶段用辩论模式（多方论证后决策）。
  • 追问2：如何选择合适的协作模式？
    • 答：根据任务性质选择：确定性高、需严格控制→层级模式；线性依赖、标准化流程→流水线模式；需要创新、多视角→辩论模式。

常见误区

  • 误区：辩论模式一定能得到更好的结果。
  • 纠正：辩论模式消耗大量Token且可能陷入无意义的争论。需要精心设计终止条件（如最大轮数、共识达成判定）和Agent的System Message。
