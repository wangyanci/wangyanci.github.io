问题

知识图谱在 Agent 记忆系统中扮演什么角色？与向量检索相比各有什么优缺点？如何设计混合记忆方案？

答案

知识图谱在 Agent 记忆中的作用：

知识图谱（KG）以 (实体, 关系, 实体) 的三元组形式存储结构化知识，与向量检索相比具有以下特点：

维度 向量检索 知识图谱
检索方式 语义相似度 关系遍历
擅长查询 "找相似的内容" "找关联的实体"
多跳推理 弱 强（A→B→C）
可解释性 弱（黑盒相似度） 强（显式关系路径）
更新灵活性 高（随时插入） 低（需要维护 schema）
存储成本 中 高
构建成本 低 高

Agent 记忆的知识图谱应用：

  1. 用户画像存储：(用户A, 喜欢, React), (用户A, 工作于, 某公司)
  2. 事实关系维护：(产品X, 属于, 类别Y), (产品X, 价格为, 100元)
  3. 经验规则存储：(问题类型A, 解决方案, 方法B), (方法B, 成功率, 0.95)
from py2neo import Graph, Node, Relationship

class KGMemory:
    """知识图谱记忆模块"""
    
    def __init__(self, uri, user, password):
        self.graph = Graph(uri, auth=(user, password))
    
    def add_fact(self, subject: str, relation: str, obj: str, 
                 confidence: float = 1.0, source: str = ""):
        """添加事实三元组"""
        tx = self.graph.begin()
        
        # 创建或获取节点
        s_node = Node("Entity", name=subject)
        o_node = Node("Entity", name=obj)
        tx.merge(s_node, "Entity", "name")
        tx.merge(o_node, "Entity", "name")
        
        # 创建关系
        rel = Relationship(s_node, relation, o_node, 
                          confidence=confidence, source=source)
        tx.create(rel)
        tx.commit()
    
    def query_related(self, entity: str, relation: str = None, 
                      depth: int = 1) -> List[Dict]:
        """查询相关实体"""
        if relation:
            query = """
            MATCH (e:Entity {name: $entity})-[:$relation]->(related)
            RETURN related.name as name, type(r) as relation
            """
        else:
            query = """
            MATCH (e:Entity {name: $entity})-[r]-(related)
            RETURN related.name as name, type(r) as relation, r.confidence as conf
            LIMIT 20
            """
        return list(self.graph.run(query, entity=entity))
    
    def multi_hop_query(self, start: str, end: str, max_hops: int = 3):
        """多跳路径查询"""
        query = """
        MATCH path = (start:Entity {name: $start})-[:*1..$max_hops]-(end:Entity {name: $end})
        RETURN path
        LIMIT 5
        """
        return list(self.graph.run(query, start=start, end=end, max_hops=max_hops))
    
    def update_fact(self, subject: str, relation: str, new_obj: str):
        """更新事实（带时间戳版本控制）"""
        # 先标记旧关系为过期
        query = """
        MATCH (s:Entity {name: $subject})-[r:$relation]->(o:Entity)
        SET r.valid_until = timestamp()
        """
        self.graph.run(query, subject=subject, relation=relation)
        
        # 添加新关系
        self.add_fact(subject, relation, new_obj)

混合记忆方案设计：

class HybridMemorySystem:
    """混合记忆系统：向量检索 + 知识图谱 + 结构化数据库"""
    
    def __init__(self, vector_store, knowledge_graph, relational_db):
        self.vector_store = vector_store      # 语义检索
        self.kg = knowledge_graph              # 关系推理
        self.db = relational_db                # 精确查询
    
    def retrieve(self, query: str, query_type: str = "auto") -> Dict:
        """
        智能路由检索
        query_type: auto / semantic / relational / structured
        """
        if query_type == "auto":
            query_type = self._classify_query(query)
        
        results = {}
        
        if query_type in ("semantic", "auto"):
            # 向量语义检索
            results["semantic"] = self.vector_store.similarity_search(query, k=5)
        
        if query_type in ("relational", "auto"):
            # 知识图谱关系检索
            entities = self._extract_entities(query)
            for entity in entities:
                results["relational"] = self.kg.query_related(entity, depth=2)
        
        if query_type in ("structured", "auto"):
            # 结构化数据库精确查询
            results["structured"] = self.db.execute_query(query)
        
        return self._merge_results(results)
    
    def _classify_query(self, query: str) -> str:
        """自动判断查询类型"""
        # 包含"谁"、"什么"等 → 语义检索
        # 包含关系词 → 关系检索
        # 包含精确条件 → 结构化查询
        if any(w in query for w in ["谁", "什么", "哪些", "相关"]):
            return "semantic"
        elif any(w in query for w in ["关系", "关联", "连接"]):
            return "relational"
        return "auto"
    
    def store_memory(self, content: str, memory_type: str, metadata: Dict):
        """统一存储接口"""
        if memory_type == "dialogue":
            # 对话存向量库
            embedding = get_embedding(content)
            self.vector_store.add(embedding, content, metadata)
        
        elif memory_type == "fact":
            # 事实抽三元组存知识图谱
            triples = self._extract_triples(content)
            for s, r, o in triples:
                self.kg.add_fact(s, r, o, source=metadata.get("source"))
        
        elif memory_type == "structured":
            # 结构化数据存关系数据库
            self.db.insert(metadata["table"], metadata["data"])

延伸追问

  • 追问 1：知识图谱的 schema 怎么设计？答：围绕核心实体（用户、产品、概念）定义实体类型和关系类型，保持简洁可扩展。
  • 追问 2：向量检索和知识图谱如何互补？答：先用向量检索找到相关内容，再从中提取实体到知识图谱做关系推理。
  • 追问 3：知识图谱的维护成本怎么降低？答：使用 LLM 自动抽取三元组、定期质量检查、增量更新而非全量重建。

常见误区

  • 误区 1：知识图谱可以完全替代向量检索。两者各有擅长领域，应该互补使用。
  • 误区 2：知识图谱越全越好。实际上维护成本很高，应该聚焦核心实体和关系。
  • 误区 3：三元组抽取可以完全自动化。LLM 抽取有一定错误率，需要人工校验或规则过滤。
