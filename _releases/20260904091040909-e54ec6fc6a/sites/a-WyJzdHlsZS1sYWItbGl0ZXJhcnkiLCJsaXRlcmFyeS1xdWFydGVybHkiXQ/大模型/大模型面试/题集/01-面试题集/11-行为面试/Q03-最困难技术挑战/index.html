描述一个你遇到的最困难的技术挑战及解决过程

问题

在 Agent 项目中，你遇到过最困难的技术挑战是什么？如何解决的？

答案

一、回答结构

1. 挑战描述（具体、有技术深度）
2. 影响分析（为什么这是个严重问题）
3. 解决过程（尝试了哪些方案，为什么选最终方案）
4. 最终成果（量化结果）
5. 经验总结（学到了什么）

二、完整示例：Agent 幻觉问题

挑战：
"上线后发现 Agent 在处理退款政策咨询时，有 15% 的回答存在幻觉——会编造不存在的退款规则。这在金融场景是严重风险，可能导致合规问题。"

影响：
"有用户因为错误的退款信息投诉，监管机构也关注到了。团队面临下架风险。"

解决过程：

"我分析了幻觉来源，发现两个原因：

  1. RAG 检索质量不高，没召回到正确的政策文档
  2. LLM 在检索结果不足时会'发挥'

我尝试了三个方案：

  • 方案 1（快速修复）：Prompt 加约束'不确定就说不知道' → 幻觉降到 10%，但太多'不知道'体验差
  • 方案 2（RAG 优化）：换 embedding 模型 + 文档分片优化 + rerank → 幻觉降到 6%
  • 方案 3（系统级防控）：RAG 优化 + 检索质量门控（相似度 < 0.7 直接拒答）+ 输出事实核查 → 幻觉降到 1.5%

最终采用方案 3，但增加了人工审核通道，高风险回答必须人工确认。"

成果：
"幻觉率从 15% 降到 1.5%，用户投诉归零，通过监管审查。"

经验：
"幻觉防控不能只靠 Prompt，需要系统级方案。RAG 质量是基础，输出校验是保险。"

延伸追问

  • "如果再来一次，你会怎么做不同？" — 展示反思能力，如更早引入评估体系、做更多边界测试
  • "团队其他成员不同意你的方案怎么办？" — 用数据说服，做 A/B 测试
