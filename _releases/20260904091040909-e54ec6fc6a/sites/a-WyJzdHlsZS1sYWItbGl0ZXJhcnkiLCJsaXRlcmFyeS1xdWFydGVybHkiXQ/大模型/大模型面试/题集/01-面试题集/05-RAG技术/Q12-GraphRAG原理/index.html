## 问题
什么是 GraphRAG？它与传统 RAG 的核心区别是什么？请描述其工作流程和适用场景。

## 答案

**GraphRAG** 是由微软研究院开发的一种增强型 RAG 框架，它通过**知识图谱**来组织和理解信息，解决传统 RAG 在关系推理、跨文档关联和全局总结上的不足。

**传统 RAG vs GraphRAG：**

| 维度 | 传统 RAG | GraphRAG |
|------|---------|----------|
| **检索单元** | 文本 Chunk（基于相似度） | 实体、关系、社区摘要 |
| **知识表示** | 平面向量空间 | 结构化图（节点+边） |
| **擅长问题** | "是什么"（单点事实） | "为什么""有什么关联"（关系推理） |
| **跨文档能力** | 弱（每篇文档独立切片） | 强（实体关联跨文档） |
| **全局理解** | 弱 | 强（社区摘要提供全局视角） |

**GraphRAG 的核心工作流程：**

┌─────────────────────────────────────────────────────────────────┐
│ GraphRAG 流程 │
├────────────────────────┬────────────────────────────────────────┤
│ 索引阶段 │ 查询阶段 │
├────────────────────────┼────────────────────────────────────────┤
│ 1. 文档解析与切片 │ 1. 判断查询类型 │
│ 2. 实体抽取(人/组织/概念) │ ├── 局部查询 ──▶ 实体层图检索 │
│ 3. 关系抽取(边) │ └── 全局查询 ──▶ 社区摘要检索 │
│ 4. 知识图谱构建 │ 2. 图遍历获取相关上下文 │
│ 5. 社区发现(Leiden算法) │ 3. LLM 生成答案 │
│ 6. 社区摘要生成 │ │
└────────────────────────┴────────────────────────────────────────┘


**详细步骤：**

**索引阶段（离线）：**

1. **实体抽取**：LLM 从文档中提取实体（人名、组织、概念等）
2. **关系抽取**：识别实体之间的关系（"工作于"、"属于"、"导致"等）
3. **知识图谱构建**：将实体和关系组织成图结构
4. **社区发现**：使用 Leiden 算法将图划分为社区（相关概念的集群）
5. **社区摘要**：为每个社区生成摘要，捕捉主要观点

**查询阶段（在线）：**

- **局部搜索**：针对具体实体的问题，在图中遍历相关节点和边
- **全局搜索**：针对概括性问题，利用社区摘要生成答案

**核心优势：**

传统 RAG 解决："在哪个片段里"
GraphRAG 解决："这些片段之间是什么关系"

示例问题："张三在公司里扮演什么角色？"
传统 RAG：可能找到提到"张三"的片段，但无法知道他的完整角色
GraphRAG：可以遍历图发现 "张三 --工作于--> 技术部 --负责--> AI项目"


**GraphRAG vs LightRAG：**

| 维度 | GraphRAG（微软） | LightRAG（港大） |
|------|-----------------|-----------------|
| 知识结构 | 知识图谱 + Leiden 社区层级 | 双层图谱（实体层 + 关系层） |
| 全局理解 | 预计算社区摘要（Map-Reduce） | 关系层图谱实时检索 |
| 索引成本 | 高（2-5x 源 token） | 中（少约 40-60%） |
| 增量更新 | 难（需重建社区） | 易（直接加节点和边） |
| 查询模式 | 局部 + 全局 | 朴素 + 局部 + 全局 + 混合 |

**适用场景：**

| 场景 | 说明 |
|------|------|
| 法律文档分析 | 案件之间关系、判例关联 |
| 医疗文献 | 药物相互作用、症状-疾病关联 |
| 企业知识 | 组织架构、项目依赖关系 |
| 情报分析 | 实体关系网络、影响分析 |

## 延伸追问

**Q: GraphRAG 什么时候不值得用？**

A: 如果：1) 问题都是简单的单点事实查询；2) 知识库很小（<1000 篇文档）；3) 预算有限（GraphRAG 索引成本高）；4) 知识更新频繁（图谱更新成本高）。这些场景传统 RAG 更简单高效。

**Q: GraphRAG 和知识图谱问答(KGQA)有什么区别？**

A: KGQA 依赖预构建的知识图谱（如 Wikidata），GraphRAG 的图谱是从非结构化文档中自动抽取构建的。KGQA 图谱质量高但覆盖有限，GraphRAG 覆盖广但抽取可能有误差。

## 常见误区

1. **GraphRAG 替代传统 RAG** — 两者是互补关系，最佳实践是组合使用
2. **GraphRAG 一定更好** — 简单场景下传统 RAG 更简单高效
3. **忽略图谱构建成本** — GraphRAG 索引阶段需要大量 LLM 调用，成本高
