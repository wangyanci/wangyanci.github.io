问题

Agent 的记忆系统是如何设计的？短期记忆和长期记忆有什么区别？各自有哪些技术实现方案？请给出代码示例。

答案

记忆系统概述：

Agent 的记忆系统类比人类记忆，分为不同层级，解决不同问题。核心挑战在于平衡成本、延迟和上下文完整性。

记忆层级架构：

┌─────────────────────────────────────────────────────────────┐
│                    记忆系统四层架构                            │
├──────────────┬──────────────┬──────────────┬────────────────┤
│   短期记忆    │   工作记忆    │   长期记忆    │   认知记忆      │
│  Short-Term  │   Working    │   Long-Term  │   Cognitive    │
├──────────────┼──────────────┼──────────────┼────────────────┤
│ 对话上下文    │ 任务状态追踪  │ 用户画像偏好  │ 知识图谱规则   │
│ 滑动窗口管理  │ 中间结果缓存  │ 向量数据库存储│ 结构化知识     │
│ 内存中       │ 内存中       │ 持久化存储   │ 图数据库       │
└──────────────┴──────────────┴──────────────┴────────────────┘

短期记忆（Short-Term Memory）：

  • 本质：LLM 的 Context Window，承载当前对话的上下文
  • 内容：当前会话的对话历史、最近 N 轮消息
  • 特点：访问快、容量有限、会话结束即消失
  • 管理策略：滑动窗口、Token 限制、摘要压缩
class ShortTermMemory:
    """短期记忆 - 滑动窗口管理"""
    
    def __init__(self, max_messages: int = 20, max_tokens: int = 4000):
        self.max_messages = max_messages
        self.max_tokens = max_tokens
        self.messages: List[Dict] = []
        self.token_count = 0
    
    def add(self, role: str, content: str):
        """添加消息，自动维护窗口"""
        msg = {"role": role, "content": content, 
               "tokens": estimate_tokens(content)}
        
        self.messages.append(msg)
        self.token_count += msg["tokens"]
        
        # 按消息数裁剪
        while len(self.messages) > self.max_messages:
            removed = self.messages.pop(0)
            self.token_count -= removed["tokens"]
        
        # 按 Token 数裁剪
        while self.token_count > self.max_tokens and len(self.messages) > 1:
            removed = self.messages.pop(0)
            self.token_count -= removed["tokens"]
    
    def get_context(self) -> List[Dict]:
        """获取当前上下文"""
        return [{"role": m["role"], "content": m["content"]} 
                for m in self.messages]
    
    def summarize_old_messages(self, llm_client):
        """对较早消息进行摘要压缩"""
        if len(self.messages) < 10:
            return
        
        old_msgs = self.messages[:5]
        summary = llm_client.summarize(
            "\n".join([f"{m['role']}: {m['content']}" for m in old_msgs])
        )
        
        # 用摘要替换原始消息
        self.messages = [{"role": "system", "content": f"历史摘要：{summary}"}] \
                        + self.messages[5:]

长期记忆（Long-Term Memory）：

  • 本质：跨会话的持久化知识库
  • 内容：用户偏好、历史决策、领域知识、经验总结
  • 特点：容量大、持久化、需要检索机制
  • 技术方案：向量数据库 + Embedding + 语义检索
from langchain.vectorstores import Chroma
from langchain.embeddings import OpenAIEmbeddings
from datetime import datetime

class LongTermMemory:
    """长期记忆 - 向量数据库存储 + 语义检索"""
    
    def __init__(self, collection_name: str = "agent_memory"):
        self.embeddings = OpenAIEmbeddings()
        self.vectorstore = Chroma(
            collection_name=collection_name,
            embedding_function=self.embeddings,
            persist_directory="./memory_db"
        )
    
    def store(self, content: str, memory_type: str = "general",
              importance: float = 0.5, metadata: dict = None):
        """
        存储记忆到向量数据库
        
        Args:
            content: 记忆内容
            memory_type: 记忆类型 (fact/experience/preference)
            importance: 重要性评分 (0-1)
            metadata: 附加元数据
        """
        doc = Document(
            page_content=content,
            metadata={
                "type": memory_type,
                "importance": importance,
                "timestamp": datetime.now().isoformat(),
                **(metadata or {})
            }
        )
        self.vectorstore.add_documents([doc])
        self.vectorstore.persist()
    
    def retrieve(self, query: str, top_k: int = 5, 
                 filter_dict: dict = None) -> List[str]:
        """
        语义检索相关记忆
        
        Args:
            query: 查询语句
            top_k: 返回数量
            filter_dict: 元数据过滤条件
        """
        results = self.vectorstore.similarity_search(
            query=query,
            k=top_k,
            filter=filter_dict
        )
        return [doc.page_content for doc in results]
    
    def get_user_preferences(self, user_id: str) -> Dict:
        """获取用户偏好"""
        return self.retrieve(
            query=f"用户 {user_id} 的偏好",
            filter_dict={"type": "preference", "user_id": user_id}
        )

完整分层记忆系统：

class TieredMemorySystem:
    """分层记忆系统 - 工业级实现"""
    
    def __init__(self):
        # L1: 本地缓存（Redis）- 热数据
        self.cache = redis.Redis(host='localhost', port=6379, db=0)
        # L2: 向量数据库 - 语义检索
        self.vector_db = LongTermMemory()
        # L3: 关系数据库 - 结构化数据
        self.sql_db = asyncpg.create_pool(dsn="postgresql://...")
        # L4: 对象存储 - 大文件
        self.object_store = boto3.client('s3')
    
    async def remember(self, user_id: str, query: str, 
                       level: str = "auto") -> List[str]:
        """分层获取记忆"""
        memories = []
        
        if level in ("auto", "cache"):
            # L1: 查缓存
            cached = await self._get_from_cache(user_id, query)
            if cached:
                memories.extend(cached)
        
        if level in ("auto", "vector") and len(memories) < 3:
            # L2: 向量检索
            vector_results = self.vector_db.retrieve(query, top_k=5)
            # 写入缓存
            await self._write_to_cache(user_id, query, vector_results)
            memories.extend(vector_results)
        
        if level in ("auto", "sql"):
            # L3: 结构化查询
            sql_results = await self._query_sql_db(user_id, query)
            memories.extend(sql_results)
        
        return memories
    
    async def memorize(self, user_id: str, content: str, 
                       importance: float = 0.5):
        """分层存储记忆"""
        # 重要记忆写入长期存储
        if importance > 0.6:
            self.vector_db.store(content, importance=importance,
                               metadata={"user_id": user_id})
        
        # 同时更新缓存
        await self._invalidate_cache(user_id)

短期记忆 vs 长期记忆对比：

特性 短期记忆 长期记忆
生命周期 会话内 跨会话持久化
存储位置 内存（Context Window） 向量数据库/关系数据库
容量 有限（受 Token 限制） 大
访问速度 快 较慢（需检索）
内容 对话历史 用户偏好、经验、知识
管理策略 滑动窗口、摘要压缩 向量化、语义检索、遗忘机制

延伸追问

  1. 追问：长期记忆和 RAG 有什么区别？

    • 答：技术相似（都用向量库），但服务对象不同。RAG 挂载共享知识源（公司文档），长期记忆管理个性化经验（用户偏好）。两者通常配合使用。

  2. 追问：记忆系统如何防止"记忆污染"？

    • 答：①重要性评分机制 ②记忆可信度标记 ③定期清理过时记忆 ④冲突检测与合并策略

常见误区

  • 误区：记忆越多越好
  • 纠正：过多无关记忆会干扰决策（"噪音干扰"），需要遗忘机制和重要性筛选
