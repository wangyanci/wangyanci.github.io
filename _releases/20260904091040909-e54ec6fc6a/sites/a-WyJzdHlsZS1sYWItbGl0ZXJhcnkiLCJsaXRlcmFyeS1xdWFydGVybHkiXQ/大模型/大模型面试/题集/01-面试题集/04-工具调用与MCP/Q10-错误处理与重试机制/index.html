问题

Agent 的工具调用失败时（API 超时、返回错误、参数不正确等），应该如何设计错误处理和重试机制？

答案

生产环境中，工具调用失败是常态而非例外。一个健壮的 Agent 必须具备完善的分层错误处理、智能重试和优雅降级能力。

错误分类与处理策略

错误类型 示例 处理策略
临时错误 网络超时、API 限流、连接断开 指数退避重试（最多 3 次）
参数错误 SQL 语法错误、参数类型不匹配 返回错误给 LLM，让其修正参数
权限错误 无访问权限、Token 过期 告知用户，建议联系管理员
数据错误 查无此订单、数据不存在 告知用户，建议核实信息
系统错误 服务不可用、内部错误 降级处理或切换备用方案

指数退避重试实现

import asyncio
import random
import logging
from tenacity import (
    retry, stop_after_attempt, wait_exponential, 
    retry_if_exception_type, before_sleep_log
)

logger = logging.getLogger(__name__)

class ToolExecutorWithRetry:
    """带重试机制的工具执行器"""
    
    def __init__(self, max_retries: int = 3, base_delay: float = 1.0):
        self.max_retries = max_retries
        self.base_delay = base_delay
    
    @retry(
        stop=stop_after_attempt(3),                          # 最多重试 3 次
        wait=wait_exponential(multiplier=1, min=1, max=10),  # 指数退避：1, 2, 4, 8...
        retry=retry_if_exception_type((TimeoutError, ConnectionError)),  # 只对网络错误重试
        before_sleep=before_sleep_log(logger, logging.WARNING)  # 重试前记录日志
    )
    async def execute_with_retry(self, tool_func, **kwargs):
        """执行工具调用，带重试逻辑"""
        return await tool_func(**kwargs)

# 更精细的重试控制
class SmartRetry:
    """智能重试策略"""
    
    async def execute(self, tool_func, **kwargs):
        for attempt in range(1, self.max_retries + 1):
            try:
                result = await asyncio.wait_for(
                    tool_func(**kwargs), 
                    timeout=30  # 每次调用 30 秒超时
                )
                return result
                
            except asyncio.TimeoutError:
                if attempt < self.max_retries:
                    delay = self.base_delay * (2 ** (attempt - 1)) + random.uniform(0, 1)
                    logger.warning(f"第 {attempt} 次超时，{delay:.1f}s 后重试")
                    await asyncio.sleep(delay)
                else:
                    raise  # 重试耗尽，抛出异常
                    
            except ConnectionError as e:
                if attempt < self.max_retries:
                    delay = self.base_delay * (2 ** (attempt - 1))
                    logger.warning(f"第 {attempt} 次连接失败: {e}，{delay:.1f}s 后重试")
                    await asyncio.sleep(delay)
                else:
                    raise

降级策略（Fallback）

当重试仍然失败时，需要启用降级策略，保证 Agent 不卡死：

class FallbackStrategy:
    """多级降级策略"""
    
    async def search_with_fallback(self, query: str) -> str:
        """搜索工具的多级降级"""
        
        # 一级：专业搜索（Tavily）
        try:
            return await self.tavily_search(query)
        except Exception:
            logger.warning("Tavily 搜索失败，降级到 Google")
        
        # 二级：通用搜索（Google）
        try:
            return await self.google_search(query)
        except Exception:
            logger.warning("Google 搜索失败，降级到 Bing")
        
        # 三级：备用搜索（Bing）
        try:
            return await self.bing_search(query)
        except Exception:
            logger.warning("所有搜索都失败，使用模型自带知识")
        
        # 四级：最终兜底
        return f"无法搜索到'{query}'的实时结果，请稍后重试或使用其他关键词。"


class DataServiceWithFallback:
    """数据服务的降级策略"""
    
    def __init__(self):
        self.cache = {}  # 本地缓存
    
    async def get_user_data(self, user_id: str):
        try:
            # 1. 尝试从主数据库获取
            result = await self._fetch_from_remote_db(user_id)
            self.cache[user_id] = result  # 更新缓存
            return result, "REAL_TIME"
            
        except Exception as e:
            logger.warning(f"实时数据获取失败: {e}")
            
            # 2. 降级：使用缓存数据
            cached = self.cache.get(user_id)
            if cached:
                return cached, "CACHED (DEGRADED)"
            
            # 3. 最终兜底：返回默认值
            return {"name": "Unknown", "level": 0}, "DEFAULT_VALUE"

Agent 级别的错误恢复

class ResilientAgent:
    """具备自愈能力的 Agent"""
    
    async def handle_tool_error(self, error_info: dict, messages: list) -> str:
        """
        工具调用失败后的恢复策略
        将错误信息返回给 LLM，让模型决定下一步
        """
        # 将错误信息结构化后返回给模型
        error_message = {
            "tool_call_status": "failed",
            "error_type": error_info.get("type"),
            "error_message": error_info.get("message"),
            "suggestions": self._get_error_suggestions(error_info)
        }
        
        messages.append({
            "role": "system",
            "content": f"工具调用失败: {json.dumps(error_message)}"
        })
        
        # 让 LLM 基于错误信息决定下一步
        response = await self.llm.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=self.available_tools
        )
        
        # LLM 可能选择：
        # 1. 修改参数重新调用
        # 2. 尝试替代工具
        # 3. 告知用户无法完成
        return response.choices[0].message
    
    def _get_error_suggestions(self, error_info: dict) -> list:
        """根据错误类型给出建议"""
        suggestions = {
            "timeout": ["检查网络连接", "稍后重试", "尝试简化查询"],
            "permission_denied": ["联系管理员授权", "使用其他账号"],
            "not_found": ["检查参数是否正确", "尝试其他关键词"],
            "rate_limited": ["降低请求频率", "稍后重试"]
        }
        return suggestions.get(error_info.get("type"), ["请稍后重试"])

熔断机制

import time
from enum import Enum

class CircuitState(Enum):
    CLOSED = "closed"      # 正常
    OPEN = "open"          # 熔断
    HALF_OPEN = "half_open"  # 半开（试探）

class CircuitBreaker:
    """熔断器"""
    
    def __init__(self, failure_threshold=5, recovery_timeout=60):
        self.failure_threshold = failure_threshold  # 连续失败阈值
        self.recovery_timeout = recovery_timeout    # 恢复超时时间
        self.failure_count = 0
        self.last_failure_time = None
        self.state = CircuitState.CLOSED
    
    async def call(self, func, *args, **kwargs):
        if self.state == CircuitState.OPEN:
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = CircuitState.HALF_OPEN
            else:
                raise Exception("熔断器已打开，服务暂时不可用")
        
        try:
            result = await func(*args, **kwargs)
            self._on_success()
            return result
        except Exception as e:
            self._on_failure()
            raise e
    
    def _on_success(self):
        self.failure_count = 0
        self.state = CircuitState.CLOSED
    
    def _on_failure(self):
        self.failure_count += 1
        self.last_failure_time = time.time()
        if self.failure_count >= self.failure_threshold:
            self.state = CircuitState.OPEN

生产级最佳实践

  1. 分层限流：API 网关层 → 租户级 → 用户级
  2. 错误信息标准化：统一错误码和错误格式，便于 LLM 理解
  3. 断点续传：复杂任务中间状态持久化到 Redis，崩溃后可恢复
  4. 完整链路追踪：记录 trace_id，覆盖工具调用全链路
  5. 监控告警：工具调用成功率、延迟、错误率实时监控

延伸追问

Q: 重试次数越多越好吗？
A: 不是。过多重试会浪费资源、增加延迟、可能导致级联故障。建议最多 3 次，配合熔断机制。

Q: 所有错误都应该重试吗？
A: 不是。参数错误、权限错误重试没有意义，只对临时性错误（网络超时、连接断开）重试。

Q: 降级后用户感知怎么控制？
A: 透明的数据降级用户可能无感知；功能降级需要明确告知用户"当前使用离线模式"。

常见误区

  1. 误区：工具失败就直接报错给用户。
    纠正：应该先尝试重试、降级，最后才告知用户。

  2. 误区：错误信息直接暴露给 LLM。
    纠正：敏感信息（如数据库密码）需要脱敏后再返回。

  3. 误区：重试间隔固定。
    纠正：应使用指数退避 + 随机抖动，避免多个客户端同时重试导致"惊群效应"。
