Agent间通信机制

1. 问题

请详细说明多智能体系统中Agent之间的通信机制，包括直接通信、间接通信、共享内存等模式，以及各自的优缺点和适用场景。

1.1.1. 答案

Agent间通信的分类

Agent间通信是MAS的核心基础设施，决定了信息如何在Agent之间流动。通信方式分为两大类：直接通信和间接通信。

1. 直接通信（Direct Communication）

Agent之间直接交换消息，点对点或广播。

方式 说明 优点 缺点
消息传递 Agent A向Agent B发送结构化消息 直接、明确、可追溯 耦合度高，需要知道接收方
群聊（GroupChat） 多个Agent在共享对话中发言 灵活、自然、支持涌现 Token消耗高、可能混乱
RPC/HTTP调用 Agent A通过API调用Agent B 标准化、跨语言、可扩展 延迟、网络依赖

2. 间接通信（Indirect Communication）

Agent通过共享介质交换信息，无需直接交互。

方式 说明 优点 缺点
共享内存/黑板 所有Agent读写同一块共享区域 松耦合、信息持久化 并发冲突、数据一致性问题
消息队列 通过Kafka/RabbitMQ等中间件 异步、可靠、可扩展 系统复杂度高
向量数据库 Agent将信息Embedding存入向量库 语义检索、长期记忆 检索精度依赖Embedding质量

3. 黑板模式（Blackboard Pattern）详解

黑板模式是MAS中最重要的间接通信模式之一，所有Agent读写同一个共享内存区。

# 黑板模式实现示例
from typing import Dict, Any, List
import threading

class Blackboard:
    """共享黑板——所有Agent的公共工作区"""

    def __init__(self):
        self._data: Dict[str, Any] = {}
        self._lock = threading.Lock()
        self._subscribers: Dict[str, List[callable]] = {}

    def write(self, key: str, value: Any, agent_id: str):
        """Agent向黑板写入信息"""
        with self._lock:
            if key not in self._data:
                self._data[key] = []
            self._data[key].append({
                "value": value,
                "agent": agent_id,
                "timestamp": time.time()
            })
        # 通知订阅者
        self._notify(key, value)

    def read(self, key: str) -> List[Any]:
        """Agent从黑板读取信息"""
        with self._lock:
            return self._data.get(key, [])

    def subscribe(self, key: str, callback: callable):
        """订阅特定key的更新"""
        if key not in self._subscribers:
            self._subscribers[key] = []
        self._subscribers[key].append(callback)

# 使用示例
blackboard = Blackboard()

# Agent A写入研究结果
blackboard.write("research_result", "AI Agent市场增长50%", agent_id="researcher")

# Agent B读取并继续工作
results = blackboard.read("research_result")

2026年的技术演进——向量黑板：

传统黑板通常是结构化数据库或内存对象，现在的"黑板"进化为长短期记忆混合的向量库：

  1. Agent A将其推理过程和中间结果Embedding后存入向量库
  2. Agent B在执行相关任务时，通过语义检索自动获取A的上下文
  3. 即使Agent A已经销毁，其贡献的知识依然留存，供后续Agent复用

代码示例：基于向量数据库的黑板

from langchain.vectorstores import Chroma
from langchain.embeddings import OpenAIEmbeddings

class VectorBlackboard:
    """基于向量数据库的语义黑板"""

    def __init__(self):
        self.embeddings = OpenAIEmbeddings()
        self.vectorstore = Chroma(embedding_function=self.embeddings)

    def contribute(self, content: str, agent_id: str, metadata: dict):
        """Agent贡献知识到黑板"""
        self.vectorstore.add_texts(
            texts=[content],
            metadatas=[{"agent": agent_id, **metadata}]
        )

    def query(self, query: str, k: int = 3) -> List[dict]:
        """语义检索黑板内容"""
        return self.vectorstore.similarity_search(query, k=k)

# Agent A贡献知识
board = VectorBlackboard()
board.contribute("AI Agent市场规模预计2026年达到100亿美元", "market_researcher")

# Agent B通过语义检索获取相关知识（不需要知道A的存在）
insights = board.query("AI Agent市场趋势")

1.1.2. 延伸追问

  • 追问1：LLM Agent之间的通信与传统分布式系统通信有何不同？
    • 答：LLM Agent通信内容主要是自然语言或结构化Prompt，而非二进制数据；通信模式更偏向"对话"和"协作推理"；通信协议需要支持语义理解（如A2A），而非单纯的RPC。
  • 追问2：如何设计Agent间通信的安全机制？
    • 答：采用零信任架构，每次通信验证身份；最小权限原则，Agent只能访问必要的通信通道；通信内容加密；审计日志记录所有通信；Guardrails AI进行Input/Output扫描。

1.1.3. 常见误区

  • 误区：Agent间通信越频繁越好。
  • 纠正：过度通信会导致Token成本激增和上下文膨胀。应该设计合理的通信粒度，重要信息才共享，非关键中间结果可以省略。
