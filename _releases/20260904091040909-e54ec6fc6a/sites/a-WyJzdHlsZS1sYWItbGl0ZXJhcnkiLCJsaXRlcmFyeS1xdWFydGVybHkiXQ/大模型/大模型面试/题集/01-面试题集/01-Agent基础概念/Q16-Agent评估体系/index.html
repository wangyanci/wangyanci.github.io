问题

Agent 系统的评估与传统 LLM 评估有什么不同？请描述 Agent 专属的评估维度、指标体系和评估方法。

1. 答案

Agent 评估 vs LLM 评估的核心差异：

维度 传统 LLM 评估 Agent 系统评估
评估对象 静态文本输出 动态执行过程
评估标准 困惑度、BLEU、ROUGE 任务完成率、步骤效率
测试方式 固定测试集 动态环境交互
关注点 输出质量 过程质量 + 结果质量
成本考量 较少关注 Token 消耗是关键指标

评估方法：

class AgentEvaluator:
    """Agent 评估器"""
    
    def __init__(self):
        self.test_cases = TestCaseLoader().load()
        self.judge_llm = GPT4()  # LLM-as-a-Judge
    
    async def evaluate(self, agent: Agent) -> EvaluationReport:
        """完整评估流程"""
        results = []
        
        for test_case in self.test_cases:
            result = await self.run_test_case(agent, test_case)
            results.append(result)
        
        return self.aggregate_results(results)
    
    async def run_test_case(self, agent: Agent, 
                           test_case: TestCase) -> TestResult:
        """执行单个测试用例"""
        start_time = time.time()
        
        # 执行 Agent
        trajectory = await agent.run_with_trace(test_case.input)
        
        elapsed = time.time() - start_time
        
        # 评估结果
        completion = self.check_completion(trajectory, test_case.expected)
        accuracy = self.judge_llm.evaluate(
            predicted=trajectory.final_answer,
            expected=test_case.expected
        )
        
        return TestResult(
            test_id=test_case.id,
            completed=completion,
            accuracy=accuracy,
            steps=len(trajectory.steps),
            tokens=trajectory.total_tokens,
            latency=elapsed,
            tool_calls=len(trajectory.tool_calls),
            errors=len(trajectory.errors)
        )
    
    def check_completion(self, trajectory: Trajectory, 
                        expected: ExpectedOutput) -> bool:
        """检查任务是否完成"""
        # 精确匹配
        if trajectory.final_answer == expected.exact:
            return True
        
        # 语义匹配（LLM-as-a-Judge）
        return self.judge_llm.semantic_match(
            trajectory.final_answer, expected.semantic
        )

LLM-as-a-Judge 评估：

class LLMAsJudge:
    """使用 LLM 作为评估者"""
    
    JUDGE_PROMPT = """
    你是一个公正的评估者。请评估以下 Agent 的回答质量。
    
    任务：{task}
    标准答案：{reference}
    Agent 回答：{prediction}
    
    请从以下维度评分（1-5分）：
    1. 准确性（信息是否正确）
    2. 完整性（是否覆盖所有要点）
    3. 相关性（是否回答了问题）
    4. 有用性（对用户是否有帮助）
    
    输出格式：
    {{
        "accuracy": 分数,
        "completeness": 分数,
        "relevance": 分数,
        "helpfulness": 分数,
        "overall": 综合分数,
        "reasoning": "评分理由"
    }}
    """
    
    def evaluate(self, task: str, prediction: str, 
                 reference: str = None) -> dict:
        prompt = self.JUDGE_PROMPT.format(
            task=task, prediction=prediction, reference=reference or "N/A"
        )
        response = self.llm.generate(prompt)
        return json.loads(response)

2. 延伸追问

  1. 追问：LLM-as-a-Judge 有什么局限性？

    • 答：①位置偏见（偏好某个位置的回答）②长度偏见（偏好更长的回答）③对特定风格有偏见。缓解：多 Judge 投票、设计去偏见 Prompt

  2. 追问：如何处理评估中的"部分正确"情况？

    • 答：使用细粒度评估，将任务拆解为子目标，分别评估每个子目标的完成情况，而非整体二分类

3. 常见误区

  • 误区：只看最终结果，不看过程
  • 纠正：Agent 的过程指标（步数、重试次数、幻觉率）同样重要，反映了系统的健壮性和效率
