## 问题
什么是 RAG（检索增强生成）？请详细描述其从文档处理到最终答案生成的完整流程，并说明为什么需要 RAG。

## 答案

**RAG（Retrieval-Augmented Generation，检索增强生成）** 是一种结合信息检索与大型语言模型生成的技术架构。它通过在生成答案前先从外部知识库中检索相关信息，并将检索结果作为上下文提供给 LLM，从而让模型生成更准确、更符合事实的答案。

**为什么需要 RAG：**

1. **解决知识时效性问题**：LLM 的知识有截止日期，无法获取最新信息
2. **减少幻觉（Hallucination）**：通过提供有据可查的上下文，降低模型编造信息的概率
3. **引入私有知识**：让 LLM 能访问企业内部的专有文档和数据
4. **可溯源性**：回答基于明确的文档来源，便于验证和审计

**RAG 的完整流程：**

**具体步骤详解：**

| 阶段 | 步骤 | 说明 |
|------|------|------|
| 离线 | 文档加载 | 从 PDF、Word、网页、数据库等加载原始文档 |
| 离线 | 文档切片 | 将长文档切分成适合检索的 Chunk（通常 200-1000 tokens） |
| 离线 | 向量化 | 使用 Embedding 模型将文本 Chunk 转换为高维向量（如 768/1024/1536 维） |
| 离线 | 存储索引 | 将向量存入向量数据库，建立 ANN 索引（如 HNSW） |
| 在线 | 查询向量化 | 将用户问题用同样的 Embedding 模型转换为向量 |
| 在线 | 相似度检索 | 在向量数据库中查找与查询向量最相似的 Top-K 个 Chunk |
| 在线 | 上下文组装 | 将检索到的 Chunk 作为上下文，与用户问题组装成 Prompt |
| 在线 | 生成答案 | 将组装好的 Prompt 输入 LLM，生成最终回答 |

## 代码示例

```python
# 使用 LangChain 实现基础 RAG 流程
from langchain_community.document_loaders import TextLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_chroma import Chroma
from langchain.chains import create_retrieval_chain
from langchain.chains.combine_documents import create_stuff_documents_chain
from langchain_core.prompts import ChatPromptTemplate

# 1. 文档加载
loader = TextLoader("documents.txt")
docs = loader.load()

# 2. 文档切片
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,      # 每个 chunk 的大小
    chunk_overlap=200     # 重叠大小，保持上下文连续性
)
splits = text_splitter.split_documents(docs)

# 3. 向量化 + 存储
embeddings = OpenAIEmbeddings()
vectorstore = Chroma.from_documents(
    documents=splits,
    embedding=embeddings
)

# 4. 创建检索器
retriever = vectorstore.as_retriever(search_kwargs={"k": 4})

# 5. 创建 RAG 链
llm = ChatOpenAI(model="gpt-3.5-turbo")
prompt = ChatPromptTemplate.from_template("""
根据以下上下文回答问题。如果上下文没有相关信息，请说"我不知道"。

上下文:
{context}

问题: {input}
""")

# 组合文档链 + 检索链
document_chain = create_stuff_documents_chain(llm, prompt)
rag_chain = create_retrieval_chain(retriever, document_chain)

# 6. 查询
result = rag_chain.invoke({"input": "什么是RAG？"})
print(result["answer"])

延伸追问

Q: RAG 和 Fine-tuning 有什么区别？

A: 主要区别：

  • RAG：外挂知识库，不改变模型参数；适合知识频繁更新的场景；成本低，灵活性高
  • Fine-tuning：修改模型参数，将知识内化到模型中；适合固定领域知识；成本高，需要重新训练

Q: RAG 中的检索结果为空时应该怎么处理？

A: 应设计兜底策略：

  1. 降低相似度阈值再次检索
  2. 使用宽泛化的查询重写
  3. 直接回答"未找到相关信息"，而不是让 LLM 硬编
  4. 记录空召回日志，用于后续优化知识库

常见误区

  1. 认为 RAG 能完全消除幻觉 — RAG 只能显著降低幻觉，不能完全消除，仍需结合其他策略
  2. 忽视文档切片质量 — 不合理的切片会导致信息丢失或检索不准
  3. 认为 chunk 越大越好 — 过大的 chunk 会降低检索精度，过小则会丢失上下文
  4. 忽略离线到在线的一致性 — 必须使用相同的 Embedding 模型处理文档和查询
