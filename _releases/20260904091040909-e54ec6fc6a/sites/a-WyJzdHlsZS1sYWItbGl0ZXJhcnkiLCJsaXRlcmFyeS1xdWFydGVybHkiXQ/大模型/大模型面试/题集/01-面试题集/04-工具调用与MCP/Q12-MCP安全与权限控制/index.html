问题

MCP 的安全模型是怎样的？如何实现工具调用的权限控制和审计？

答案

MCP 的安全模型遵循最小权限原则，从工具注册、调用审批、执行隔离到审计追踪形成完整的安全闭环。

权限控制四层模型

第一层：工具级权限（Tool-level ACL）

class ToolACL:
    """工具访问控制列表"""
    
    def __init__(self):
        self.permissions = {
            # 用户角色 -> 允许调用的工具（支持通配符）
            "admin": ["*"],  # 所有工具
            "analyst": ["query_*", "search_*", "export_report"],
            "operator": ["query_*", "update_status", "send_notification"],
            "guest": ["query_public_*"],  # 只能查询公开数据
        }
    
    def can_execute(self, user_role: str, tool_name: str) -> bool:
        allowed_patterns = self.permissions.get(user_role, [])
        for pattern in allowed_patterns:
            if pattern == "*" or self._match(pattern, tool_name):
                return True
        return False
    
    def _match(self, pattern: str, tool_name: str) -> bool:
        import fnmatch
        return fnmatch.fnmatch(tool_name, pattern)

# 使用
acl = ToolACL()
assert acl.can_execute("admin", "delete_database") == True
assert acl.can_execute("analyst", "delete_database") == False
assert acl.can_execute("analyst", "query_sales") == True

第二层：操作风险分级（Risk-based Approval）

from enum import Enum

class RiskLevel(Enum):
    LOW = "low"       # 只读查询，自动执行
    MEDIUM = "medium"  # 一般操作，记录日志
    HIGH = "high"      # 敏感操作，需自动审批
    CRITICAL = "critical"  # 危险操作，需人工审批

class RiskBasedApprover:
    """基于风险等级的审批系统"""
    
    RISK_MAP = {
        "query_*": RiskLevel.LOW,
        "search_*": RiskLevel.LOW,
        "export_*": RiskLevel.MEDIUM,
        "update_*": RiskLevel.HIGH,
        "delete_*": RiskLevel.CRITICAL,
        "transfer_*": RiskLevel.CRITICAL,
        "send_email": RiskLevel.HIGH,
        "exec_shell": RiskLevel.CRITICAL,
    }
    
    def assess(self, tool_name: str, arguments: dict) -> RiskLevel:
        """评估操作风险等级"""
        for pattern, risk in self.RISK_MAP.items():
            if self._match(pattern, tool_name):
                # 额外判断参数敏感程度
                if self._has_sensitive_args(arguments):
                    return RiskLevel(min(risk.value + 1, RiskLevel.CRITICAL.value))
                return risk
        return RiskLevel.MEDIUM  # 默认中风险
    
    def _has_sensitive_args(self, args: dict) -> bool:
        """检查参数是否涉及敏感信息"""
        sensitive_keys = ['password', 'token', 'secret', 'ssn', 'credit_card']
        return any(k in str(args).lower() for k in sensitive_keys)

# 使用
approver = RiskBasedApprover()
risk = approver.assess("delete_user", {"user_id": "12345"})
if risk in (RiskLevel.HIGH, RiskLevel.CRITICAL):
    # 需要审批流程
    ...

第三层：执行隔离（Execution Isolation）

import subprocess
import tempfile
import os

class SandboxExecutor:
    """沙箱隔离执行器"""
    
    def __init__(self):
        self.allowed_paths = ["/tmp/mcp_workspace", "/data/public"]
        self.max_file_size = 10 * 1024 * 1024  # 10MB
        self.max_execution_time = 30  # 30秒
    
    async def execute_in_sandbox(self, command: list) -> dict:
        """在沙箱中执行命令"""
        with tempfile.TemporaryDirectory() as tmpdir:
            try:
                result = subprocess.run(
                    command,
                    cwd=tmpdir,
                    capture_output=True,
                    text=True,
                    timeout=self.max_execution_time,
                    # 资源限制
                    env={"PATH": "/usr/bin:/bin"},  # 限制环境变量
                )
                return {
                    "returncode": result.returncode,
                    "stdout": result.stdout[:10000],  # 限制输出长度
                    "stderr": result.stderr[:5000]
                }
            except subprocess.TimeoutExpired:
                return {"error": "执行超时", "returncode": -1}
    
    def validate_path(self, path: str) -> bool:
        """校验文件路径是否在允许范围内"""
        abs_path = os.path.abspath(path)
        for allowed in self.allowed_paths:
            if abs_path.startswith(os.path.abspath(allowed)):
                return True
        return False

第四层：审计追踪（Audit Trail）

import hashlib
import json
from datetime import datetime

class AuditLogger:
    """审计日志系统"""
    
    def __init__(self, storage_backend):
        self.storage = storage_backend
    
    def log_tool_call(self, record: dict):
        """记录工具调用"""
        audit_entry = {
            "event_type": "tool_call",
            "timestamp": datetime.utcnow().isoformat(),
            "trace_id": record.get("trace_id"),
            "user": {
                "id": record["user_id"],
                "role": record["user_role"]
            },
            "tool": {
                "name": record["tool_name"],
                "arguments_hash": self._hash(record["arguments"]),
                "arguments_plain": record["arguments"]  # 脱敏后存储
            },
            "result": {
                "status": record["status"],
                "latency_ms": record["latency_ms"]
            },
            "context": {
                "session_id": record["session_id"],
                "client_ip": record.get("client_ip"),
                "mcp_server": record.get("server_name")
            }
        }
        
        # 敏感参数脱敏
        audit_entry["tool"]["arguments_plain"] = self._sanitize(
            record["arguments"]
        )
        
        self.storage.save(audit_entry)
    
    def _hash(self, data: dict) -> str:
        return hashlib.sha256(
            json.dumps(data, sort_keys=True).encode()
        ).hexdigest()[:16]
    
    def _sanitize(self, arguments: dict) -> dict:
        """脱敏处理"""
        sensitive_fields = ['password', 'token', 'secret', 'api_key']
        sanitized = arguments.copy()
        for key in sanitized:
            if any(sf in key.lower() for sf in sensitive_fields):
                sanitized[key] = "***REDACTED***"
        return sanitized

MCP 安全最佳实践

实践 说明
最小权限 每个 Agent 只配置执行任务所需的最小工具集
文件系统隔离 Agent 只能在专属工作目录操作，禁止访问 ~/.ssh 等敏感目录
网络访问控制 配置专属 VLAN，限制访问内部核心数据库、配置中心的 IP 段
工具清单白名单 在配置中明确列出可用工具清单，清单外的调用直接拦截
凭证管理 从 Agent 内部移除凭证控制权，改为通过网络边界注入
人类介入 高风险操作必须经过人工确认，不能自动执行

延伸追问

Q: 如何防止 Agent 绕过审批直接执行工具？
A: 所有 ToolCall 必须经过 SecureToolExecutor 的权限和审批检查，没有直通路径。通过依赖注入确保只有该执行器被调用，并用 ArchUnit 等工具在 CI 中检查。

Q: 什么情况下应该跳过人工审批？
A: 风险等级为 LOW 和 MEDIUM 的操作通常不需要审批；紧急情况（如系统故障自动恢复）可在策略中配置跳过审批，但必须事后审计。

常见误区

  1. 误区：安全只依赖模型的自我约束。
    纠正：安全决策必须从"模型内部"移到"模型外部"，通过框架层强制拦截。

  2. 误区：审计日志影响性能，可以关闭。
    纠正：审计是生产环境必需，可采用异步写入、采样记录等方式降低性能影响。

  3. 误区：权限控制只做到工具级别就够了。
    纠正：需要细到参数级别（如某用户只能查特定表、特定时间范围的数据）。
