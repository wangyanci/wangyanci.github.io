## 问题
什么是 Agentic RAG？它与传统 RAG 的核心区别是什么？请描述其工作原理和典型应用场景。

## 答案

**Agentic RAG** 是在 RAG 基础上引入 **Agent（智能体）** 的主动决策能力，让系统能自主判断何时需要检索、检索什么、是否需要多步检索。

**传统 RAG vs Agentic RAG：**

| 维度 | 传统 RAG | Agentic RAG |
|------|---------|-------------|
| **检索时机** | 固定流程：每次查询都检索 | 动态决策：Agent 判断是否需要检索 |
| **检索策略** | 单次检索 | 可多步检索、递归检索 |
| **查询处理** | 直接使用原始查询 | Agent 可重写、分解查询 |
| **工具使用** | 仅检索向量库 | 可调用多种工具（API、数据库等） |
| **反馈机制** | 无 | 可根据生成结果反馈调整检索 |

**Agentic RAG 的工作原理：**

用户提问
│
▼
┌─────────────────────────────────────────────┐
│ Agent (由 LLM 驱动) │
│ 1. 理解用户意图 │
│ 2. 判断是否需要检索 │
│ 3. 决定检索策略（单次/多步/工具调用） │
└──────────────────────────────────────────────┘
│
├──▶ 无需检索 ──▶ 直接用 LLM 知识回答
│
└──▶ 需要检索 ──▶ 执行检索计划
│
├──▶ 检索向量数据库
├──▶ 调用外部 API
├──▶ 查询结构化数据库
│
▼
评估检索结果是否充分
│
├──▶ 不充分 ──▶ 再次检索（递归）
│
└──▶ 充分 ──▶ 生成最终答案


**典型实现模式：**

```python
from langchain.agents import Tool, AgentExecutor, create_react_agent
from langchain_openai import ChatOpenAI
from langchain import hub

# 定义工具
tools = [
    Tool(
        name="KnowledgeBase",
        func=rag_retriever.invoke,
        description="从知识库中检索相关信息，适用于产品文档、公司制度等"
    ),
    Tool(
        name="OrderService",
        func=query_order_api,
        description="查询订单信息，需要订单号"
    ),
    Tool(
        name="WeatherService",
        func=query_weather_api,
        description="查询天气信息，需要城市名"
    )
]

# 创建 ReAct Agent
llm = ChatOpenAI(model="gpt-4", temperature=0)
prompt = hub.pull("hwchase17/react")
agent = create_react_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# 执行：Agent 会自动判断需要调用哪些工具
result = agent_executor.invoke({
    "input": "我昨天买的iPhone 15 Pro到哪里了？北京今天能收到货吗？"
})
# Agent 会自动调用 OrderService 和 WeatherService

典型应用场景：

场景 说明
智能客服 自动判断查订单、查物流、查知识库等
复杂问答 多步推理，如"比较 A 和 B 的优缺点"
多源数据融合 同时查询文档、数据库、API
动态检索 根据中间结果决定下一步检索方向

延伸追问

Q: Agentic RAG 和 Self-RAG 有什么区别？

A:

  • Self-RAG：通过反思令牌（Retrieve, ISREL, ISSUP, ISUSE）让模型自我判断是否需要检索和验证，偏模型层面的改进
  • Agentic RAG：通过 Agent 框架（ReAct、Tool Use）实现检索决策和工具调用，偏架构层面的改进
  • 两者可以结合使用

Q: Agentic RAG 的延迟问题怎么解决？

A: 1) 使用更快的 LLM 做决策；2) 并行执行多个工具调用；3) 设置最大迭代次数；4) 对常见路径做缓存和预计算。

常见误区

  1. 所有 RAG 都应该升级为 Agentic RAG — 简单场景传统 RAG 更直接高效
  2. Agent 可以无限递归 — 必须设置最大迭代次数防止死循环
  3. 忽视 Tool 描述的质量 — Agent 依赖 Tool 描述来决定调用哪个工具
