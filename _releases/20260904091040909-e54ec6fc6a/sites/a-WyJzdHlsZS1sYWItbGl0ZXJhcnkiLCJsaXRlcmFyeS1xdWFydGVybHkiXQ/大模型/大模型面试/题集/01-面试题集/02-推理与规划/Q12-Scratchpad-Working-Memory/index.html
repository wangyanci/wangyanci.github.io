问题

解释 Agent 中 Scratchpad（草稿板）和 Working Memory（工作记忆）的概念、作用，以及如何在工程上实现高效的 Working Memory 管理。

答案

Scratchpad / Working Memory 概念：

Scratchpad（草稿板）是 Agent 在执行任务过程中用于记录中间计算、推理步骤和临时状态的内存区域。它类似于人类做数学题时在草稿纸上写写画画的过程。

Working Memory（工作记忆）是当前任务中活跃的状态存储——包括变量值、中间结果、当前步骤索引、待办事项等。它是 Agent "当前在做什么、做到哪了"的载体。

在 ReAct 中的体现：

Thought: 我需要先查询用户ID，然后查订单
Action: query_user(name="张三")
Observation: user_id=12345
→ Working Memory: {current_step: 1, user_id: 12345, next: "query_orders"}

Thought: 已获取用户ID=12345，现在查询订单
Action: query_orders(user_id=12345)
Observation: 订单列表 [...]
→ Working Memory: {current_step: 2, user_id: 12345, orders: [...]}

工程实现：

from typing import Any, Dict, Optional
from dataclasses import dataclass, field

@dataclass
class WorkingMemory:
    """工作记忆：当前任务的临时状态"""
    task_id: str
    current_step: int = 0
    variables: Dict[str, Any] = field(default_factory=dict)
    scratchpad: List[str] = field(default_factory=list)
    todo_list: List[str] = field(default_factory=list)
    completed_steps: List[str] = field(default_factory=list)
    
    def set(self, key: str, value: Any):
        """设置变量"""
        self.variables[key] = value
        self.scratchpad.append(f"Set {key} = {value}")
    
    def get(self, key: str, default=None) -> Any:
        """获取变量"""
        return self.variables.get(key, default)
    
    def append_note(self, note: str):
        """在草稿板上添加笔记"""
        self.scratchpad.append(note)
    
    def next_step(self, description: str = ""):
        """推进到下一步"""
        self.current_step += 1
        if description:
            self.completed_steps.append(description)
    
    def add_todo(self, item: str):
        """添加待办事项"""
        self.todo_list.append(item)
    
    def complete_todo(self, item: str):
        """完成待办事项"""
        if item in self.todo_list:
            self.todo_list.remove(item)
    
    def to_context_string(self) -> str:
        """转换为可放入 LLM 上下文的字符串"""
        parts = []
        
        if self.variables:
            parts.append("[当前变量]")
            for k, v in self.variables.items():
                parts.append(f"  {k}: {v}")
        
        if self.todo_list:
            parts.append(f"[待办事项] {', '.join(self.todo_list)}")
        
        if self.completed_steps:
            parts.append(f"[已完成] {', '.join(self.completed_steps[-5:])}")
        
        if self.scratchpad:
            parts.append(f"[草稿笔记] {'; '.join(self.scratchpad[-10:])}")
        
        return "\n".join(parts)
    
    def serialize(self) -> Dict:
        """序列化为可持久化的字典"""
        return {
            "task_id": self.task_id,
            "current_step": self.current_step,
            "variables": self.variables,
            "scratchpad": self.scratchpad,
            "todo_list": self.todo_list,
            "completed_steps": self.completed_steps
        }
    
    @classmethod
    def deserialize(cls, data: Dict) -> "WorkingMemory":
        """从字典反序列化"""
        wm = cls(task_id=data["task_id"])
        wm.current_step = data.get("current_step", 0)
        wm.variables = data.get("variables", {})
        wm.scratchpad = data.get("scratchpad", [])
        wm.todo_list = data.get("todo_list", [])
        wm.completed_steps = data.get("completed_steps", [])
        return wm

# 使用示例
def agent_task(task: str, tools: Dict):
    wm = WorkingMemory(task_id="task_001")
    wm.add_todo("查询用户信息")
    wm.add_todo("查询订单")
    wm.add_todo("生成报告")
    
    max_steps = 10
    for step in range(max_steps):
        # 构建 prompt，包含 working memory
        context = wm.to_context_string()
        prompt = f"""任务: {task}
当前状态:
{context}

请决定下一步行动："""
        
        # 调用 LLM
        response = llm.generate(prompt)
        
        # 解析行动
        action = parse_action(response)
        
        if action.type == "final":
            return action.content
        
        # 执行工具
        result = tools[action.tool](**action.params)
        
        # 更新工作记忆
        wm.set(f"result_{action.tool}", result)
        wm.complete_todo(action.description)
        wm.next_step(action.description)
        wm.append_note(f"执行 {action.tool}: {str(result)[:100]}")
    
    return "Max steps reached"

设计要点：

  1. 持久化：Working Memory 需要支持序列化，以便任务中断后恢复
  2. 结构化：变量、待办、笔记分层管理，便于 LLM 理解
  3. 容量控制：草稿笔记不能无限增长，需要定期摘要
  4. 作用域隔离：不同任务的工作记忆应该隔离，避免互相污染

延伸追问

  • 追问 1：Scratchpad 和对话历史有什么区别？答：Scratchpad 是 Agent 内部使用的"草稿"，通常不对用户可见；对话历史是用户和 Agent 的交互记录。
  • 追问 2：Working Memory 怎么支持断点续传？答：通过序列化/反序列化，将 WM 存入 Redis 等持久存储，任务恢复时重新加载。
  • 追问 3：多 Agent 协作时 Working Memory 怎么共享？答：通过共享内存空间或消息队列，定义好读写权限和同步机制。

常见误区

  • 误区 1：Scratchpad 就是对话历史。实际上 Scratchpad 是 Agent 内部推理的辅助空间。
  • 误区 2：Working Memory 不需要持久化。长任务中 WM 持久化是支持断点续传的关键。
  • 误区 3：所有变量都放进 WM。只放当前任务相关的变量，避免信息过载。
