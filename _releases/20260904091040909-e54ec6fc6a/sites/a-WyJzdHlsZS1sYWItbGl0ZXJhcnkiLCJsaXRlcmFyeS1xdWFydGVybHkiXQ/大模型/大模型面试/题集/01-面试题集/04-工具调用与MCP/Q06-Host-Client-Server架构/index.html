问题

详细解释 MCP 的 Host-Client-Server 架构，各组件的职责是什么？数据流如何流转？

答案

MCP 采用三层架构：Host（宿主应用）、Client（连接组件）、Server（能力提供者）。理解这个架构是设计和调试 MCP 系统的核心。

架构总览

│                (AI 应用，如 Claude Desktop)                   │
│                                                              │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                  LLM (Claude/GPT 等)                   │  │
│  │  模型通过 Function Calling 决定调用哪个工具               │  │

各组件职责

1. MCP Host

Host 是 MCP 架构的入口，通常是集成了 AI 能力的应用程序：

  • 职责：

    • 提供用户交互界面
    • 调用 LLM 进行推理
    • 管理多个 MCP Client 的生命周期
    • 聚合来自各 Server 的工具、资源和提示
    • 权限控制和安全审计
    • 维护会话状态和上下文

  • 典型实现：Claude Desktop、Cursor IDE、ChatGPT、自建 AI 应用

2. MCP Client

Client 是 Host 内部连接某个 Server 的组件：

  • 职责：

    • 维护与 Server 的连接（stdio / HTTP / SSE）
    • 将 Host 的请求转换为 MCP 协议格式（JSON-RPC 2.0）
    • 处理请求/响应的转换和路由
    • 管理连接的生命周期（建立、保持、断开、重连）
    • 处理错误和超时

  • 一个 Host 通常有多个 Client，每个 Client 连接一个 Server

3. MCP Server

Server 是能力的实际提供者，对接具体的工具和数据源：

  • 职责：

    • 暴露 Tools（可执行的动作）
    • 暴露 Resources（只读上下文数据）
    • 暴露 Prompts（可复用的提示模板）
    • 处理 Client 发来的工具调用请求
    • 执行实际的业务逻辑（查数据库、调 API、操作文件等）
    • 返回标准化的结果

  • Server 是独立的进程或服务，可以本地运行（stdio）或远程部署（HTTP）

完整数据流

1. 初始化阶段：
   Host ──启动──→ Server 进程（stdio）或连接远程 Server（HTTP）
   Client ──initialize──→ Server（交换协议版本和能力）
   Client ──list_tools──→ Server（获取可用工具列表）

2. 工具发现阶段：
   Host 收集所有 Client 的工具列表
   Host 将工具描述转换为 Function Calling Schema
   Host 将 Schema 提供给 LLM

3. 调用阶段：
   用户提问 ──→ Host ──→ LLM
   LLM 判断需要调用工具 ──→ 输出 tool_calls
   Host 根据 tool_name 路由到对应 Client
   Client ──tools/call──→ Server（JSON-RPC 2.0）
   Server 执行实际逻辑 ──→ 返回结果
   Client ──→ Host ──→ LLM（将结果注入上下文）
   LLM 生成最终回答

JSON-RPC 2.0 消息格式示例

// Client → Server: 列出工具
{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/list",
    "params": {}
}

// Server → Client: 工具列表响应
{
    "jsonrpc": "2.0",
    "id": 1,
    "result": {
        "tools": [
            {
                "name": "read_file",
                "description": "读取文件内容",
                "inputSchema": {
                    "type": "object",
                    "properties": {
                        "path": {"type": "string"}
                    },
                    "required": ["path"]
                }
            }
        ]
    }
}

// Client → Server: 调用工具
{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/call",
    "params": {
        "name": "read_file",
        "arguments": {"path": "/tmp/test.txt"}
    }
}

Python 实现示例

# MCP Server 完整实现
from mcp.server.fastmcp import FastMCP
import sqlite3

mcp = FastMCP("database-server")

@mcp.tool()
async def query_database(sql: str) -> str:
    """
    执行只读 SQL 查询。仅支持 SELECT 语句。
    禁止 INSERT/UPDATE/DELETE/DROP 等写操作。
    """
    # 安全检查
    dangerous_keywords = ['insert', 'update', 'delete', 'drop', 'alter', 'create']
    if any(kw in sql.lower() for kw in dangerous_keywords):
        return json.dumps({"error": "仅支持 SELECT 查询"})
    
    conn = sqlite3.connect('data.db')
    try:
        cursor = conn.execute(sql)
        rows = cursor.fetchall()
        columns = [desc[0] for desc in cursor.description] if cursor.description else []
        return json.dumps({"columns": columns, "rows": rows[:100]})
    except Exception as e:
        return json.dumps({"error": str(e)})
    finally:
        conn.close()

@mcp.resource("schema://tables")
def get_schema() -> str:
    """数据库 schema 作为资源暴露"""
    conn = sqlite3.connect('data.db')
    cursor = conn.execute("SELECT name, sql FROM sqlite_master WHERE type='table'")
    tables = cursor.fetchall()
    conn.close()
    return json.dumps(tables)

@mcp.prompt()
def data_analysis_prompt(table: str) -> str:
    """数据分析专用提示模板"""
    return f"""你是一个数据分析专家。请分析表 {table} 的数据，提供：
1. 数据概览（行数、列数、主要字段）
2. 关键统计指标
3. 潜在的数据质量问题
4. 业务洞察建议
"""

if __name__ == "__main__":
    mcp.run(transport="stdio")

延伸追问

Q: 一个 Host 可以连接多少个 Server？
A: 理论上无限制，实际取决于性能和工具数量。建议按场景组织 Server（如一个 Server 对应一个数据源）。

Q: Client 和 Server 的连接是怎么维护的？
A: stdio 方式下，Server 是 Client 启动的子进程，生命周期绑定。HTTP 方式下，Client 需要处理连接池、心跳检测和自动重连。

Q: Server 如何告知 Client 工具列表更新了？
A: MCP 支持 Server 发送通知（notifications），当工具列表变更时主动推送更新。

常见误区

  1. 误区：Host = Client = Server，三者是一个东西。
    纠正：三者是独立的概念，一个 Host 包含多个 Client，每个 Client 连接一个独立的 Server。

  2. 误区：MCP Server 必须远程部署。
    纠正：stdio 方式适合本地工具（如文件系统），HTTP 方式适合远程服务。

  3. 误区：工具调用是同步阻塞的。
    纠正：MCP 支持异步调用，耗时操作应该异步处理，避免阻塞 AI 应用。
