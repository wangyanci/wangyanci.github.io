RLHF 和 DPO 的原理和区别是什么？各有什么优劣势？

问题

RLHF 和 DPO 都是 LLM 对齐技术，它们的原理是什么？各有什么优缺点？

答案

一、RLHF（Reinforcement Learning from Human Feedback）

RLHF 是一种基于强化学习的对齐方法，分为三个阶段：

阶段 1: SFT（监督微调）
    用高质量指令数据微调预训练模型
    
阶段 2: 奖励模型训练
    收集人类偏好数据（A 比 B 好）
    训练奖励模型 r(x,y) 预测人类偏好
    使用 Bradley-Terry 模型建模偏好概率:
    P(y_w > y_l | x) = σ(r(x, y_w) - r(x, y_l))
    
阶段 3: RL 微调（PPO）
    使用 PPO 算法优化策略模型 π_θ
    目标: max E[r(x,y)] - β·KL(π_θ || π_ref)
    KL 散度约束防止模型偏离参考模型太远

二、DPO（Direct Preference Optimization）

DPO 跳过了奖励模型训练和 RL 阶段，直接从偏好数据优化语言模型：

核心思想：利用 RLHF 目标的闭式解，将奖励参数化为对数比率

r(x,y) = β·log(π_θ(y|x) / π_ref(y|x))

代入 Bradley-Terry 模型，得到 DPO 损失函数:
L_DPO = -E[log σ(β·log(π_θ(y_w|x)/π_ref(y_w|x)) 
                - β·log(π_θ(y_l|x)/π_ref(y_l|x)))]

直观理解：直接增大偏好答案的概率，减小非偏好答案的概率

三、RLHF vs DPO 对比

维度 RLHF DPO
训练流程 三阶段（SFT → RM → PPO） 单阶段（直接优化）
奖励信号 通过奖励模型间接获得 直接从偏好数据推导
计算复杂度 高（需要训练奖励模型 + RL） 低（类似监督学习）
训练稳定性 较低（PPO 可能不稳定，reward hacking） 较高（直接梯度更新）
灵活性 高（可处理复杂奖励结构） 较低（依赖对比偏好数据）
实现难度 高（需要 RL 算法和超参数调优） 低（易于实现）
应用成熟度 高（ChatGPT, Claude 广泛使用） 中（新兴方法，应用增多）

四、RLHF 的核心问题

  1. Reward Hacking：模型找到奖励模型的漏洞，获得高奖励但输出质量差
  2. 训练不稳定：PPO 需要精心调整超参数（KL 系数、学习率等）
  3. 计算成本高：需要同时维护 4 个模型（Policy, Ref, Reward, Value）

五、DPO 的优势和局限

from trl import DPOTrainer

trainer = DPOTrainer(
    model=model,
    ref_model=ref_model,        # 参考模型（SFT 后的模型）
    beta=0.1,                   # KL 散度系数
    train_dataset=dataset,      # 偏好数据集 (prompt, chosen, rejected)
    tokenizer=tokenizer,
)
trainer.train()

优势：简单高效、训练稳定、易于实现
局限：对数据质量敏感、难以处理复杂奖励、分布偏移问题

延伸追问

  • "实际项目中用 RLHF 还是 DPO？" — 资源充足选 RLHF，快速迭代选 DPO。很多团队用 DPO 作为 RLHF 的简化替代
  • "DPO 的数据要求是什么？" — 需要高质量的偏好对 (prompt, chosen, rejected)，数据质量比数量更重要

常见误区

  • ❌ "DPO 完全替代了 RLHF" — DPO 是对 RLHF 的简化，在复杂场景下 RLHF 上限更高
  • ❌ "偏好数据越多越好" — 偏好数据质量比数量重要，噪声数据会导致模型退化
