问题

Agent 系统的上下文管理面临哪些挑战？请从窗口分配、记忆分层、压缩策略、上下文编排四个层面系统性地阐述解决方案，以及窗口溢出时的降级策略。

1. 答案

上下文管理的挑战：

Agent 的上下文不只是"对话历史"，一次典型的 Agent 调用，上下文包含六七种不同类型的内容：

[System Prompt]          固定开销，200-1000 token
[工具定义]               每个工具 100-500 token
[对话历史]               逐轮增长，每轮 200-1000 token
[RAG 检索文档]           每次检索 500-3000 token
[工具返回结果]           每次调用 100-5000 token
[中间推理步骤]           每步 100-500 token
[用户当前输入]            50-500 token

四层管理策略：

第一层：窗口分配（Quota Management）

给上下文的每一部分设定配额，而不是随意增长：

class ContextBudget:
    """上下文预算管理"""
    
    def __init__(self, total_tokens=128000):
        self.budget = {
            "system_prompt": int(total_tokens * 0.015),   # ~2K
            "tool_definitions": int(total_tokens * 0.04), # ~5K
            "dialogue_history": int(total_tokens * 0.25), # ~32K
            "rag_documents": int(total_tokens * 0.31),    # ~40K
            "tool_results": int(total_tokens * 0.25),     # ~32K
            "input_reasoning": int(total_tokens * 0.136)  # ~17K
        }
    
    def allocate(self, category: str, content: str) -> str:
        """按配额分配空间，超出部分截断"""
        max_tokens = self.budget[category]
        actual_tokens = self._count_tokens(content)
        
        if actual_tokens <= max_tokens:
            return content
        
        # 需要截断或压缩
        return self._truncate_or_compress(content, max_tokens)
    
    def _truncate_or_compress(self, content: str, max_tokens: int) -> str:
        # 优先尝试智能压缩，不行再截断
        compressed = self._smart_compress(content, max_tokens)
        if self._count_tokens(compressed) <= max_tokens:
            return compressed
        return self._hard_truncate(content, max_tokens)

第二层：记忆分层（Memory Hierarchy）

工作记忆（热） → 短期记忆（温） → 中期摘要（凉） → 长期向量存储（冷）
   ↑                                                  ↓
   └────────────── 按需检索加载 ──────────────────────┘
  • 工作记忆：当前步骤必需的变量和状态（始终保留）
  • 短期记忆：最近 N 轮完整对话（滑动窗口）
  • 中期摘要：会话级摘要（压缩后保留）
  • 长期记忆：向量数据库，按需检索加载

第三层：压缩策略（Compression）

class ContextCompressor:
    """上下文压缩器"""
    
    def compress_dialogue(self, messages: List[str], budget: int) -> str:
        """对话历史压缩"""
        if self._count_tokens(messages) <= budget:
            return "\n".join(messages)
        
        # 保留最近 N 轮完整对话
        recent = messages[-5:]  # 保留最近5轮
        
        # 更早的对话生成摘要
        older = messages[:-5]
        summary = self.llm.summarize("\n".join(older), max_tokens=budget//2)
        
        return f"[历史摘要] {summary}\n\n[最近对话] {'\n'.join(recent)}"
    
    def compress_tool_result(self, result: str, budget: int) -> str:
        """工具返回结果压缩"""
        if self._count_tokens(result) <= budget:
            return result
        
        # 保留关键字段，截断详细内容
        if isinstance(result, dict):
            return json.dumps({k: v for k, v in list(result.items())[:5]})
        
        # 长文本用摘要
        return self.llm.summarize(result, max_tokens=budget)
    
    def compress_rag_docs(self, docs: List[str], budget: int) -> str:
        """RAG 文档压缩"""
        # 先 Rerank，只保留 Top-3 最相关文档
        reranked = self.reranker.rerank(docs)[:3]
        
        # 每篇文档摘要
        summaries = []
        for doc in reranked:
            if self._count_tokens(doc) > budget // 3:
                summaries.append(self.llm.summarize(doc, max_tokens=budget//3))
            else:
                summaries.append(doc)
        
        return "\n\n".join(summaries)

第四层：上下文编排（Context Orchestration）

控制多步推理中上下文的膨胀：

class ContextOrchestrator:
    """上下文编排器"""
    
    def __init__(self):
        self.transient_tools = {"get_current_time", "calculate"}  # 阅后即焚
        self.persistent_tools = {"search_knowledge_base", "query_user_profile"}
    
    def should_preserve(self, tool_name: str, result: str) -> bool:
        """判断工具结果是否应该保留在上下文中"""
        if tool_name in self.transient_tools:
            return False  # 瞬态信息，阅后即焚
        if tool_name in self.persistent_tools:
            return True   # 持久信息，保留
        # 根据结果长度和重要性判断
        return len(result) < 500  # 短结果保留，长结果摘要
    
    def preserve_reasoning_step(self, thought: str, action: str, obs: str) -> str:
        """保留推理步骤的摘要而非完整内容"""
        return f"Step: {self._summarize(thought)} → {action} → {self._summarize(obs)}"

窗口溢出时的降级策略：

class OverflowHandler:
    """窗口溢出处理器"""
    
    def handle_overflow(self, context: Context, usage_ratio: float):
        """
        usage_ratio: 当前使用量 / 总容量
        策略按优先级顺序执行
        """
        if usage_ratio < 0.8:
            return context  # 正常
        
        # Level 1: 预警，开始准备
        if 0.8 <= usage_ratio < 0.9:
            context = self._compress_rag_docs(context)  # 先压缩 RAG 文档
        
        # Level 2: 主动压缩
        elif 0.9 <= usage_ratio < 0.95:
            context = self._compress_rag_docs(context)
            context = self._summarize_history(context)  # 摘要历史
            context = self._prune_tool_results(context)  # 裁剪工具结果
        
        # Level 3: 激进降级
        elif 0.95 <= usage_ratio < 1.0:
            context = self._compress_rag_docs(context)
            context = self._summarize_history(context)
            context = self._prune_tool_results(context)
            context = self._reduce_system_prompt(context)  # 简化系统提示
            context = self._drop_older_memories(context)   # 丢弃旧记忆
        
        # Level 4: 紧急处理
        else:
            context = self._emergency_truncation(context)  # 紧急截断
            return {"status": "overflow", "message": "Context window exceeded"}
        
        return context
    
    def _emergency_truncation(self, context: Context) -> Context:
        """紧急截断：保留最关键的信息"""
        # 优先级：系统提示 > 用户输入 > 最近1轮对话 > 其他
        return Context(
            system=context.system,
            user_input=context.user_input,
            history=context.history[-1:] if context.history else [],
            rag_docs=[]
        )

2. 延伸追问

  • 追问 1：不同场景的配额应该怎么分配？答：知识库问答场景 RAG 配额大；工具调用密集场景工具返回配额大；长对话场景对话历史配额大。
  • 追问 2："阅后即焚"怎么判断？答：根据工具类型标记——查询当前时间、临时计算等结果是瞬态的；查询用户资料、知识库结果是持久的。
  • 追问 3：溢出的监控指标有哪些？答：上下文使用率、溢出频率、信息丢失率、压缩次数等。

3. 常见误区

  • 误区 1：只靠滑动窗口管理上下文。实际上需要四层策略配合。
  • 误区 2：所有场景用同一套配额。不同场景的上下文组成差异很大。
  • 误区 3：溢出时才处理。实际上应该在达到 80% 时就开始预警和压缩。
