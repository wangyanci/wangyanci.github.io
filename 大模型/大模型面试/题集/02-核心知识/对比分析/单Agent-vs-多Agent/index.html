二、详细对比

对比维度 单 Agent 多 Agent
架构复杂度 低 高
开发成本 低 高
维护成本 低 高
任务覆盖 通用型 专业分工
错误处理 无自我纠错 Agent 间可校验
并发能力 串行 可并行
调试难度 简单 复杂
延迟 较低 较高（通信开销）
Token 消耗 较少 较多
适用场景 简单-中等任务 复杂、多领域任务

三、适用场景分析

选择单 Agent 的场景

典型应用：

  • 客服问答机器人
  • 个人助手（查天气、设提醒）
  • 简单的 RAG 问答
  • 单步工具调用场景

选择多 Agent 的场景

典型应用：

  • 软件开发团队（产品经理+程序员+测试）
  • 研究分析（数据收集+分析+写作）
  • 复杂决策（多视角分析）
  • 内容创作（策划+写作+编辑）

五、常见面试考点

Q1: 什么场景适合单 Agent，什么适合多 Agent？

答: 简单任务、延迟敏感、预算有限用单 Agent；复杂任务、需要多领域协作、质量要求高用多 Agent。

Q2: 多 Agent 系统的主要挑战？

答:

  1. 通信开销大，延迟高
  2. 调试困难，问题定位复杂
  3. 协调机制设计复杂
  4. Token 消耗和成本高
  5. 一致性保证困难

Q3: 如何从单 Agent 演进到多 Agent？

答:

  1. 先识别任务中可分解的子任务
  2. 为每个子任务定义专门的 Agent
  3. 设计 Agent 间的通信协议
  4. 实现编排器协调工作流
  5. 添加监控和调试能力
